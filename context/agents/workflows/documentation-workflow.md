# Documentation Workflow

Use this workflow when adding or changing docs.

1. Decide whether the document belongs in `Docs/` or `context/`.
2. Use `context/` for plans, working notes, skills, prompts, and agent instructions.
3. Use `Docs/` for stable architecture, API, product, deployment, and design documentation.
4. Link related documents instead of copying long sections.
5. When a plan becomes stable, summarize the final decision in `context/decisions/` and publish durable documentation in `Docs/`.
