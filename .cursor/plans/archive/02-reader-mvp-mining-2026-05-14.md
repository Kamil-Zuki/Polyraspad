## Goal

Из текста в минимум жестов: **pop-up словарь** по клику и **«Создать карточку (Mine)»** в один клик; согласованность с term actions без поломки Phase 1 контрактов.

## Киллер-фича PVS.ai: AI вместо «ручного Anki»

**Контекст:** на форме создания карточки сейчас много ручных полей; **AI Assistant** на **внешних LLM по API-ключам** — главный дифференциатор: автоматизировать **~90%** работы, пользователю остаётся в основном **Save**. Локальный **Ollama** в продукте **не используем** — текущие интеграции с Ollama **снимаем** (compose, конфиги, `/api/ollama/*`).

## 1-Click Mining (целевой UX)

Триггер: пользователь в **reader** выделяет слово/фразу и жмёт **«+»** / Mine. **AI должен:**

1. Захватить **предложение целиком** как контекст карточки.
2. Дать **опциональную справочную начальную форму** (словарная лемма) **только как подсказку** для перевода/объяснения; **учёт и дубликаты** остаются по **реальной форме из текста** (term-first, см. `.cursor/rules/06-lingq-domain-guardrails.mdc`).
3. Перевести целевое слово/фразу **в контексте этого предложения** (не «сухой» словарный перевод, как часто у LingQ).
4. Сгенерировать перевод **всего предложения**.
5. Оставить пользователю **одно подтверждение** — **Save** (при необходимости лёгкая правка полей).

## TTS «из коробки»

- Тумблер **Auto TTS** — развивать до продакшн-качества: подключить внешнее **API озвучки** (например Google Cloud TTS, Azure Speech, OpenAI TTS) и автоматически привязывать аудио к карточке при создании.
- Аудио критично для языкового обучения.

## AI Grammar Notes

- По клику в AI Assistant: краткое объяснение грамматики **в сохранённом предложении** (например, «почему здесь Past Perfect»).
- Не заменяет term inspector; дополняет карточку/урок.

## Граница шага

Всё, что пользователь делает, чтобы **извлечь из контекста** слово/фразу в учёт (термин, значение, опционально карточка) — **без** интервального повторения.

## MVP обязательно

- По клику на слово: **pop-up словарь** (lookup / перевод).
- Из pop-up: **Mine** в **один клик** (term-first: термин + опциональная карточка); эволюция к сценарию **1-Click Mining** с AI (см. выше).
- Согласованность с **CreateOrUpdateTerm → SAVED**, **MarkTermKnown**, **IgnoreTerm**, **phrase**, если инспектор остаётся параллельно.

## Agents

- `product-agent`: приёмка шага 2 (один клик Mine, нет «мёртвых» веток); сценарии после отключения Ollama.
- `backend-agent`: terms API, создание карточки из контекста; **замена Ollama-клиента** на LLM provider + секреты.
- `frontend-agent`: pop-up слой, инспектор, связка с `term-client`.
- `reviewer-agent`: контракты DTO/API client.

## Contracts To Lock

- **LLM-провайдеры:** единый контракт вызова (модель, endpoint, ключ из секретов); без обязательного self-hosted LLM в инфраструктуре PVS.
- **Удаление Ollama:** отсутствие зависимостей от `ollama` в compose, отсутствие публичных `/api/ollama/*` после миграции (или временный shim только на период перехода — явно пометить deprecated).
- Terms CRUD/mutations, `bulkMarkKnown` (см. Aggregator contract).
- UI: инспектор без lemma labels; **pop-up** + **Mine** из одного слоя.
- `type` WORD | PHRASE, дубликаты по `NormalizedText`.
- **AI pipeline 1-Click Mining:** контракт запроса/ответа (предложение, перевод цели в контексте, перевод предложения, опциональная словарная лемма как метаданные, не как ключ статуса).
- **TTS:** контракт генерации/хранения аудио карточки (внешний TTS API + Auto TTS).
