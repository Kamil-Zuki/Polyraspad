# Завершение страницы Library по IA

## Что уже есть (соответствует IA)

- **Иерархия:** папки (Folders) и колоды (Decks) из `useDeckTree`, хлебные крошки (Project > Проект > Library > …), баннер «Project Stats» с кнопкой «View Analytics» (`[project-stats-banner.tsx](polyraspad-frontend/src/components/library/project-stats-banner.tsx)`).
- **Действия:** поиск по названию, «New Folder», «New Deck», диалог создания/редактирования колоды и папки (`[CreateDeckDialog](polyraspad-frontend/src/components/decks/create-deck-dialog.tsx)`), редактирование названия и удаление колоды/папки из меню карточки.
- **Сетки:** секции FOLDERS и ROOT DECKS / DECKS, карточки колод с обложкой, прогресс-баром, счётчиками и меню (Edit/Delete), ссылка на `/study/[deckId]`.

## Что осталось сделать

### 1. Фильтры «Мои / Скачанные / Публичные» (IA, с. 44)

В IA указано: _«Фильтры (Мои / Скачанные / Публичные)»_.

- **Текущее состояние:** фильтров в шапке Library нет; дерево колод приходит одним запросом `getDeckTree(projectId)` и отображается целиком.
- **Ограничение:** `[DeckTreeItemDto](polyraspad-frontend/src/lib/api/types.ts)` содержит только `id`, `title`, `cardCount`, `children` — нет `ownerId`, `isPublic`, `forkedFromId`, поэтому клиент не может отфильтровать «Мои / Скачанные / Публичные» по текущему API.
- **Варианты:**
  - **Бэкенд:** расширить ответ дерева (например, добавить в узлы `ownerId`, `isPublic`, `forkedFromId`) или ввести отдельный endpoint списка колод с query-параметром фильтра (`?filter=Mine|Downloaded|Public`). После этого на фронте добавить в actions bar переключатель (табы или сегмент) «Мои | Скачанные | Публичные» и фильтровать отображаемое дерево/список по выбранному значению.
  - **Только фронт (временный вариант):** если бэкенд пока не меняется — добавить UI фильтров с заглушкой (все три показывают одно и то же дерево) и комментарием в коде о необходимости расширения API.

### 2. Настройки колоды (IA: «Действия … Настройки колоды»)

- **Текущее состояние:** в меню карточки колоды есть только Edit (переименование + описание через `CreateDeckDialog`) и Delete. В `[UpdateDeckDto](polyraspad-frontend/src/lib/api/types.ts)` есть также `isPublic`, `coverImageUrl`, `contributionPolicy`.
- **Что сделать:** оформить полноценные «Настройки колоды»: отдельный экран/модалка (или расширить текущий edit), где можно менять описание, обложку (`coverImageUrl`), публичность (`isPublic`), политику вкладов (`contributionPolicy`). При открытии настроек запрашивать полную колоду через `useDeck(deckId)` (`[deck-queries.ts](polyraspad-frontend/src/lib/react-query/deck-queries.ts)`), т.к. в дереве этих полей нет. Текущий «Edit» можно оставить быстрым переименованием, а «Настройки» — отдельной кнопкой в меню карточки или объединить в один сценарий «Edit/Настройки» с полной формой.

### 3. Реальные данные для Project Stats Banner

- **Текущее состояние:** в `[LibraryPage](polyraspad-frontend/src/app/library/page.tsx)` баннер рендерится без пропсов; в `[ProjectStatsBanner](polyraspad-frontend/src/components/library/project-stats-banner.tsx)` используются дефолты `totalLemmas = 2543`, `matureLemmas = 1850`, `learningLemmas = 350`.
- **Что сделать:** на странице Library вызывать `useVocabularyStats(currentProject?.id ?? "")` (как на [странице Analytics](polyraspad-frontend/src/app/analytics/page.tsx)), передавать в баннер `totalLemmas`, `matureLemmas`, `learningLemmas` из `VocabularyStatsDto` (поля: `totalLemmas`, `matureCount`, `learningCount`). Обработать состояния загрузки и ошибки (скелетон или скрытие баннера при ошибке — по желанию).

### 4. Реальные данные для карточек колод (обложка, прогресс, due)

- **Текущее состояние:** в `[page.tsx](polyraspad-frontend/src/app/library/page.tsx)` (строки 339–352) для каждой колоды подставляются моковые `image`, `progress`, `dueCount`, `isPurchased`; в коде есть комментарии «TODO: Calculate from card SRS status» и «until API provides».
- **Обложка и признак «куплено»:** полная колода приходит в `DeckResponseDto`: `coverImageUrl`, `forkedFromId` (можно считать «скачанной/купленной»). Варианты: либо расширить бэкенд и отдавать в узле дерева `coverImageUrl` и `forkedFromId`, либо на странице Library для отображаемых колод (например, только листовых в текущем уровне) вызывать `useDeck(deckId)` — тогда получится N запросов; оптимальнее один расширенный tree или batch endpoint.
- **Прогресс и due:** в текущих DTO нет полей «карт к повторению по колоде» и «процент зрелости по колоде». Нужен либо новый endpoint (например, «статистика по колоде»: due count, progress), либо расширение дерева/списка колод этими полями. Пока можно оставить расчёт на фронте только если появится API (например, по карточкам колоды), либо оставить плейсхолдеры (0 / 0%) с комментарием.
- **Итог по пункту:** минимум — убрать моковые URL и флаги, подставлять `coverImageUrl` и признак «purchased» из API (через расширение tree или `useDeck`). Прогресс и due — после появления соответствующего API.

### 5. Мелкие доработки (по желанию)

- **Папки:** при редактировании папки сейчас открывается тот же `CreateDeckDialog` с `initialData: { title }`; полные настройки (если введёте «Настройки колоды») логично применять и к папкам, т.к. папка — это колода с дочерними.
- **Бreadcrumb:** при клике по последнему сегменту пути вызывается `handleBreadcrumbClick(null)` (возврат в корень). Если нужно, можно сделать клик по текущей папке без действия (no-op).
- **Подпись к поиску:** в IA в макете placeholder «Filter decks...» — уже используется в коде.

## Зависимости и порядок

- П. 3 (реальные данные баннера) и п. 4 (обложка/признак purchased) можно делать независимо от фильтров и настроек.
- П. 1 (фильтры) зависит от бэкенда (расширение дерева или новый endpoint).
- П. 2 (настройки колоды) зависит только от фронта (useDeck + форма по UpdateDeckDto).

## Рекомендуемый порядок реализации

1. **Реальные данные баннера** — подключить `useVocabularyStats` на Library и передать данные в `ProjectStatsBanner`.
2. **Настройки колоды** — модалка/страница с полной формой (description, isPublic, coverImageUrl, contributionPolicy), открытие по кнопке в меню карточки, данные через `useDeck`.
3. **Обложки и «Purchased»** — договориться с бэкендом: либо поля в дереве (`coverImageUrl`, `forkedFromId`), либо batch/отдельный список; убрать моки с карточек и подставить данные из API.
4. **Фильтры «Мои / Скачанные / Публичные»** — после появления полей/API на бэкенде добавить UI фильтров и логику фильтрации.
5. **Прогресс и due по колодам** — после появления API статистики по колоде подставить реальные значения и убрать заглушки (0/0%).

После выполнения пунктов 1–3 страница Library будет максимально близка к завершению по IA при текущем API; пункты 4–5 закроют оставшиеся требования и данные.
