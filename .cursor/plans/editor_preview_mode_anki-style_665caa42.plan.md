# План: Preview mode в редакторе — уровень Anki

## Текущее состояние

- **Preview:** [card-preview.tsx](polyraspad-frontend/src/components/editor/card-preview.tsx) — переключатель Front/Back, контент из [editor-card-context](polyraspad-frontend/src/contexts/editor-card-context.tsx) (sentence, targetWord, translation, imageUrl, audioUrl). Изображение только на обороте, фиксированная высота `h-32`, при ошибке загрузки скрывается через `onError` → `display: none`. Аудио — один `<audio controls>`.
- **Размещение:** десктоп — боковая панель 320px ([page.tsx](polyraspad-frontend/src/app/editor/page.tsx)), мобильный — под формой.
- **Почему не видно изображений:**
  1. **Редактирование карточки:** из браузера есть ссылка «Edit» на `/editor?cardId=...`, но страница редактора **не читает** `cardId` и **не загружает** карточку в контекст — при открытии редактора для существующей карточки поля и медиа пустые, в Preview ничего не отображается.
  2. **Ошибки загрузки:** невалидный URL, CORS или сеть — картинка молча скрывается, пользователь не видит ни изображения, ни сообщения об ошибке.
  3. **Узкая колонка:** в боковой панели 320px изображение с `h-32` выглядит мелко и не «финально».
- **Сравнение:** В [CardViewModal](polyraspad-frontend/src/components/browser/card-view-modal.tsx) картинка на **лицевой** стороне (`max-h-48 object-contain`), на обороте — перевод, целевое слово, аудио. [StudyCard](polyraspad-frontend/src/components/study/study-card.tsx) медиа **вообще не отображает** (только плейсхолдер кнопки аудио) — финальный вид карточки при изучении пока без изображения/аудио.

---

## Целевое поведение

1. **Изображения и аудио в Preview отображаются** при наличии URL в контексте (в т.ч. после загрузки карточки по `cardId` при редактировании).
2. **Режим «полный размер»** (как в Anki): возможность развернуть Preview в полноэкранный/крупный просмотр и увидеть карточку так, как она будет выглядеть в финале (единый стиль с изучением/браузером).
3. **Удобное размещение медиа:** логичный порядок (текст → изображение → аудио), изображение достаточного размера, аудио с понятным контролом; при полном размере — пропорции и отступы как у финальной карточки.

---

## 1. Данные: загрузка карточки при редактировании (cardId)

Чтобы в режиме редактирования в Preview показывались и медиа, редактор должен подставлять в контекст данные карточки.

- **Файл:** [page.tsx](polyraspad-frontend/src/app/editor/page.tsx) (или обёртка над формой внутри `EditorCardProvider`).
- **Действия:**
  - Читать `searchParams` (например `useSearchParams()` из `next/navigation`), при наличии `cardId` вызывать существующий `useCard(cardId)` ([card-client](polyraspad-frontend/src/lib/api/card-client.ts)).
  - При успешном ответе вызывать `setCardState({ sentence, targetWord, translation, imageUrl: media?.imageUrl ?? "", audioUrl: media?.audioUrl ?? "" })`.
  - Учесть, что сейчас API по плану [Card Browser](.cursor/plans/card_browser_anki-style_view_511a4649.plan.md) может не отдавать `imageUrl`/`audioUrl` в gRPC/REST; после добавления этих полей на бэкенде они начнут приходить. На фронте достаточно использовать `card.media?.imageUrl` и `card.media?.audioUrl` (типы в [types.ts](polyraspad-frontend/src/lib/api/types.ts) уже содержат эти поля).

Итог: при переходе по «Edit» из браузера контекст заполняется, и Preview показывает текст и медиа (как только бэкенд начнёт отдавать URL).

## 2. Отображение изображений в Preview

- **Файл:** [card-preview.tsx](polyraspad-frontend/src/components/editor/card-preview.tsx).
- **Исправить скрытие при ошибке:** вместо безусловного `display: none` при `onError`:
  - показывать плейсхолдер («Не удалось загрузить изображение» или иконка), чтобы пользователь понимал, что медиа есть, но URL недоступен;
  - опционально выводить короткое сообщение под превью (например, «Проверьте URL или загрузите файл заново»).
- **Размер и пропорции в обычном (боковая панель) режиме:**
  - увеличить высоту превью изображения (например с `h-32` до `min-h-[140px] max-h-48` или аналогично [CardViewModal](polyraspad-frontend/src/components/browser/card-view-modal.tsx): `object-contain`), чтобы картинка была читаемой и не обрезалась без необходимости.
- **CORS/внешние URL:** если изображения с внешних доменов не грузятся из-за CORS, в рамках фронта можно:
  - оставить обычный `<img src={imageUrl} />` (после исправления отображения ошибки);
  - при необходимости в будущем — прокси через бэкенд или использование `next/image` с `unoptimized` и доменом в `remotePatterns` только для превью; в плане не обязательно, если загрузка через ваш storage (MinIO) уже отдаёт URL с нужными CORS.

---

## 3. Полноэкранный / «полный размер» просмотр (как в Anki)

- **Компонент:** новый компонент или режим внутри `CardPreview`: по кнопке «Развернуть» / «Full size» открывать модальное окно (или полноэкранный overlay) с той же разметкой карточки (Front/Back), но:
  - большая область контента (например `max-w-3xl` и `min-h-[400px]` как в [StudyCard](polyraspad-frontend/src/components/study/study-card.tsx)), чтобы видеть финальный вид;
  - те же данные из `useEditorCard()` (sentence, targetWord, translation, imageUrl, audioUrl);
  - переключатель Front/Back сохранён;
  - закрытие по кнопке «Закрыть» и по клику вне карточки / Escape.
- **Размещение кнопки:** в шапке блока Preview (рядом с «Card Preview») или внутри стеклянной карточки — одна кнопка «Развернуть» / иконка «на весь экран», видимая когда включён Preview mode.
- **Единообразие с финальной карточкой:** в полноэкранном режиме использовать те же классы/структуру, что и в [CardViewModal](polyraspad-frontend/src/components/browser/card-view-modal.tsx) / будущем отображении карточки в Study (текст, затем изображение, затем аудио), чтобы «как будет выглядеть в финале» совпадало с реальным видом при просмотре и при обучении.

---

## 4. Размещение медиа и удобство просмотра

- **Порядок на обороте (Back):** перевод (цитата) → целевое слово (при необходимости) → изображение → аудио. В [card-preview.tsx](polyraspad-frontend/src/components/editor/card-preview.tsx) порядок уже: translation → image → audio; можно оставить, при необходимости явно вывести блок «Target» как в CardViewModal.
- **Лицевая сторона (Front):** по аналогии с [CardViewModal](polyraspad-frontend/src/components/browser/card-view-modal.tsx) при наличии `imageUrl` показывать изображение и на лицевой стороне (предложение + картинка) — так превью ближе к Anki и к браузеру карточек. Опционально: настройка «картинка только на обороте» можно не вводить на первом этапе, а единообразно показывать изображение на обеих сторонах если оно есть.
- **Аудио:** оставить `controls`, при желании обернуть в блок с подписью «Аудио» и отступами для читаемости.
- **Визуал:** отступы, скругления и границы уже заданы (`glass-panel`, `rounded-xl`); в полноэкранном режиме — те же стили, увеличенная область и возможно чуть больший размер шрифта для предложения/перевода, чтобы было удобно просматривать.

---

## 5. Зависимости от бэкенда

- Для **редактирования карточки** (п. 1) и отображения медиа в Preview при открытии из браузера нужны `imageUrl` и `audioUrl` в ответе API карточки (REST/GET по id). По плану Card Browser это предполагается добавить в gRPC `CardMedia` и в REST DTO. Пока полей нет — при редактировании по `cardId` в Preview будут заполняться только текст; после появления URL медиа начнут отображаться без дополнительных правок в логике Preview.

---

## Порядок внедрения

1. **Данные:** загрузка карточки по `cardId` в редакторе и заполнение контекста (sentence, targetWord, translation, imageUrl, audioUrl).
2. **Preview:** исправление отображения изображения (ошибка → плейсхолдер/сообщение, увеличение размера, при желании изображение и на лицевой стороне).
3. **Полный размер:** кнопка «Развернуть» и модальное/полноэкранное окно с карточкой в финальном виде.
4. **Полировка:** порядок блоков, подписи для аудио, единый стиль с CardViewModal/Study.

После этого Preview будет стабильно показывать изображения и аудио (при наличии URL в контексте), даст возможность развернуть просмотр в полный размер и будет визуально удобен и согласован с финальным видом карточки.
