# TDD Start — Начало фичи по Red-Green-Refactor

Используй эту команду для старта новой фичи или изменения поведения.

## Чеклист

### 1. Понимание (Do not skip)
- [ ] Прочитать активный план из `.cursor/plans/` или создать новый
- [ ] Изучить связанный код через `rg` поиск
- [ ] Определить границу изменений (scope)
- [ ] Сформулировать ожидаемое поведение одним предложением

### 2. Red — Пишем тест/спецификацию

#### Backend (xUnit)
- [ ] Создать/открыть тестовый класс
- [ ] Написать `[Fact]` или `[Theory]` с названием поведения
- [ ] Тест должен падать (Red)
- [ ] Пример:
```csharp
[Fact]
public void CreateTerm_SavesExactFormWithoutLemmatization()
{
    var result = _termService.Create("slept", projectId: 1);
    
    Assert.Equal("slept", result.Text);
    Assert.NotEqual(_termService.GetByText("sleep").Id, result.Id);
}
```

#### Frontend (Jest + RTL)
- [ ] Создать/открыть тестовый файл `.test.tsx`
- [ ] Написать `it('should...')` с описанием поведения
- [ ] Тест должен падать (Red)
- [ ] Пример:
```typescript
it('renders yellow highlight for saved LingQ terms', () => {
  render(<Reader terms={[{ text: 'hello', status: 'LINGQ' }]} />);
  expect(screen.getByText('hello')).toHaveClass('text-yellow-400');
});
```

### 3. Green — Минимальная реализация
- [ ] Написать минимальный код для прохождения теста
- [ ] НЕ рефакторить на этом этапе
- [ ] Запустить тест, убедиться что проходит (Green)
- [ ] Если тест не проходит — откатить и попробовать проще

### 4. Refactor — Улучшение
- [ ] Улучшить имена переменных и методов
- [ ] Убрать дублирование
- [ ] Проверить соответствие правилам `.cursor/rules/`
- [ ] Убедиться что все тесты всё ещё проходят

### 5. LingQ Guardrails (если затрагивает Reader/Vocabulary)
- [ ] `sleep` и `slept` — разные сущности
- [ ] Дубликаты проверяются по точной нормализованной форме
- [ ] Фразы — отдельные термины типа PHRASE
- [ ] Reader не показывает lemma labels

### 6. Завершение
- [ ] Коммит с осмысленным сообщением (что и почему)
- [ ] Обновить план если scope изменился
- [ ] Задокументировать неожиданные находки в плане

## Шаблон сообщения коммита

```
feat: краткое описание поведения

- что изменено и почему
- какие тесты добавлены
- риски или ограничения (если есть)
```
