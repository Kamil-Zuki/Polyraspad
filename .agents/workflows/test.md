# Workflow: Test Runner (Test)

Этот workflow активируется командой `/test`. Его цель — запустить нужный набор тестов, убедиться, что система работает, и локализовать падения.

## 🛠️ Шаги для AI-агента:

1. **Определение скоупа:**
   - Спроси пользователя (или определи сам по измененным файлам): *"Для какого сервиса мы запускаем тесты?"*

2. **Запуск тестов:**
   - В зависимости от целевого проекта, выполни соответствующую команду (согласно `AGENTS.md` §5):
     - **Backend (.NET):** `dotnet test <Service.Tests>/<Service.Tests>.csproj -c Release`
     - **Frontend (Next.js):** `npm test -- --watchAll=false` (находясь в `polyraspad-frontend/`)
     - **Python (Inclusive):** `pytest test_fsrs_review_card.py` (находясь в `inclusive/`)

3. **Анализ результатов:**
   - Прочитай вывод тестов.
   - Если тесты прошли успешно (🟩) — сообщи пользователю и предложи продолжить работу.
   - Если тесты упали (🟥) — выдели конкретные падающие assert'ы, объясни причину падения и предложи варианты фикса.

4. **Интеграционные барьеры:**
   - Напомни пользователю: *"Любые изменения в статусах слов (FSRS), дубликатах или читалочке обязаны проходить регрессионные тесты LingQ-логики"* (см. `AGENTS.md` §9).
