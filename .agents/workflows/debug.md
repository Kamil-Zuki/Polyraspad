# Workflow: Structured Debugging (Debug)

Этот workflow активируется командой `/debug`. Его цель — обеспечить методичный процесс поиска и исправления ошибок, избегая слепых и хаотичных правок.

## 🛠️ Шаги для AI-агента:

1. **Сбор проблемы:**
   - Если пользователь просто написал `/debug`, спроси: *"Опиши проблему или покажи сообщение об ошибке, с которой мы разбираемся"*.

2. **Сбор фактов (Observability):**
   - Используй `docker compose logs` для целевого сервиса, чтобы прочитать стек-трейс или ошибки.
   - Прочитай код затронутых компонентов с помощью `view_file` или `grep_search`.

3. **Гипотеза:**
   - Выскажи пользователю четкую гипотезу: *"Я предполагаю, что проблема в X, потому что Y"*.
   - Не вноси изменения, пока не подтвердишь гипотезу фактами из логов или кода.

4. **Патч (Action):**
   - Внеси минимальное изменение, необходимое для проверки гипотезы.
   - Не делай рефакторинг в процессе дебага.

5. **Верификация (Check):**
   - Пересобери нужный сервис в Docker (например, `docker compose up --build -d <service-name>`).
   - Проверь логи снова. Если проблема решена — отлично. Если нет — откати изменения и вернись к шагу 2.

6. **Мемоизация (Memory):**
   - Если баг оказался неочевидным паттерном или хитрым краем архитектуры, предложи пользователю зафиксировать его через `/learn` (чтобы добавить в `skills` или `knowledge`).
