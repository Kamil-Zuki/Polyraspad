# Главный принцип

**`03 — Модель данных` — источник истины. Её нельзя менять без явного запроса пользователя.**

Типичная работа: пользователь просит дописать **`01`** → ты **читаешь** `03`, пишешь/правишь **`01`**. Если `01` не сходится с `03` → **ISSUE в `99`**, а не правка `03` «под SR».

| Ситуация | Разрешено |
| :--- | :--- |
| Запрос «допиши `01` … на основе `03`» | Править **только `01`**; `03` только читать |
| В `01` нужна сущность/поле, которых нет в `03` | **ISSUE** — не добавлять поле в `03` самому |
| Расхождение имён, типов, cardinality | **ISSUE** — не «синхронизировать» `03` молча |
| Пользователь явно: «измени `03`», «обнови entity …», «закрой ISSUE-… в `03`» | Можно править **`03`** |
| Пользователь явно: «исправь `01` под `03`» | Можно править **`01`** |

# ОБЯЗАТЕЛЬНО при правке `01` (без запроса на `03`)

Выполни **до завершения ответа** (в том же turn):

## Шаг 1 — Прочитай парную `03`

Сверь затронутые SR / группы с entity и полями в `…/03 - Модель данных/` (или `03 - Модель Данных/`).

## Шаг 2 — Сверка

| Проверка | Тип ISSUE |
| :--- | :--- |
| SR ссылается на сущность/поле, которых нет в `03` | **Пробел** |
| В `03` есть in-scope сущность/поле без SR в `01` | **Пробел** |
| Разные имена, типы, обязательность, cardinality | **Противоречие** |
| Группа в `01/00` ≠ группировка entity в `03` | **Нейминг** |

Область расхождения всегда **`01` ↔ `03`** — это контекст данного rule, **отдельное поле в ISSUE не нужно**.

## Шаг 3 — При конфликте: ISSUE на диске

**MUST** создать или обновить:

1. `<Сервис>/99 - Staging — Разрывы согласованности (DO NOT DELETE)/ISSUE-NNN-{slug}.md`
2. Строку в `…/00 - Реестр проблем.md`

Если `99` нет — создай (эталон: `Шаблон документации микросервиса/99 - Staging …/`).

**Запрещено:**

- Менять **`03`** без явного запроса пользователя (в т.ч. «добавить поле», «переименовать entity» ради согласования с `01`).
- Замалчивать конфликт и только дописывать `01`.
- Писать «нужно создать ISSUE» без **фактического** файла на диске.

## Шаблон ISSUE (`01` ↔ `03`)

Структура файла, стиль и навигация (якорь **SR-ID** / **Entity.field**, язык для человека) — **[`docs-staging-issues.mdc`](docs-staging-issues.mdc)**.

Для `01` ↔ `03` в поле **Тип** указывай только классификацию: **Пробел** | **Противоречие** | **Нейминг** — не дублируй «01↔03» (область задана этим rule).

В таблице **«Где проблема»** обязательны якоря: `01` → `SR-…`; `03` → Entity + поле.

Для расхождений с `02`/`04` (REST↔gRPC, 03↔DTO и т.д.) — типы и body в `.cursor/skills/docs-04-verify/issue-template.md` (тот же rule `docs-staging-issues`).

## Шаг 4 — В конце ответа (если был конфликт)

Перечисли созданные ISSUE: `ISSUE-NNN`, полный путь, одна строка сути.
