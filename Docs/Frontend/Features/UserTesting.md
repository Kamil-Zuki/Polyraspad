# Тестирование пользователя (Placement Test & Checkpoints)

**Статус:** Draft
**Связанный бекенд:** Vocabulary Service (SR-VOC-01, SR-VOC-06), Agent Service (SR-AGENT-TOOL-06)

## 1. UX-сценарий (User Journey)
Данная фича описывает процесс диагностики знаний пользователя для подбора оптимального уровня сложности и отслеживания прогресса.

* **Шаг 1:** Пользователь впервые заходит на страницу `/lessons`.
* **Шаг 2:** Если в бекенде нет пройденных уроков, фронтенд показывает баннер-приглашение пройти входное тестирование. Если уровень уже установлен, баннер скрывается, но доступна кнопка **"Retake Placement Test"** под описанием Curriculum Map.
* **Шаг 3:** При клике на "Start Test" или "Retake Placement Test" открывается изолированная страница чата с ИИ-агентом (`/lessons/placement`). В случае перепрохождения создается новая сессия с агентом.
* **Шаг 4:** Пользователь отвечает на вопросы агента (диалог).
* **Шаг 5:** Агент сообщает результат и вызывает инструмент `set_cefr_placement`. Фронтенд перехватывает успешный статус вызова инструмента, показывает пользователю тост с уведомлением, закрывает тест (возвращая на `/lessons`) и инвалидирует кэш Curriculum Map.

## 2. Маршрутизация и Страницы (Routing)
* `app/lessons/page.tsx` (Client Component) — проверяет статус уроков пользователя и решает, рендерить ли большой баннер тестирования или компактную кнопку "Retake".
* `app/lessons/placement/page.tsx` (Client Component) — изолированная страница для проведения ИИ-теста (Placement Test Mode).

## 3. Дерево компонентов (Component Architecture)
* `<LessonsRoadmap>` (Server) — отрисовывает карту уроков.
  * `<PlacementTestBanner>` (Client) — триггер старта (показывается только для новых учеников).
* `<PlacementTestContainer>` (Client) — обертка теста, управляющая жизненным циклом.
  * `<AgentChat>` (Client) — переиспользуемый UI чата с агентом.
  * `<SkillRadarChart>` (Client) — диаграмма, показывающая финальный результат или прогресс по навыкам.

## 4. Интеграция с API (Data Fetching & BFF)
* **Загрузка статуса (Queries):** `useQuery` для `GET /api/vocabulary/curriculum/progress` (AggregatorService).
* **Ведение теста (BFF):** Фронтенд использует `useAgentWorkspace` для отправки сообщений в `AgentService` через наш BFF (`POST /api/ai/chat`).
* **Особый контекст:** При инициализации чата фронт передает `SystemPromptOverride` = `"Ты диагност. Твоя цель задать вопросы и определить CEFR..."` (либо агент получает этот контекст автоматически через Intent Routing).
* **Завершение (Mutations):** Когда агент присылает сообщение об окончании теста, фронт вызывает `useMutation` для `POST /api/vocabulary/placement` с полученным уровнем, после чего делает инвалидацию кэша: `queryClient.invalidateQueries({ queryKey: ['curriculum'] })`.

## 5. Управление состоянием (State Management)
* Глобальное состояние (Zustand/Redux) не требуется. 
* Диалог с агентом хранится локально внутри кастомного хука (например, `useAgentWorkspace`).
* Прогресс вопросов высчитывается из метадаты сообщений агента (если агент присылает номер вопроса).

## 6. Стратегия тестирования фронтенда (UI Testing)
* **Компонентные тесты (Vitest + RTL):** Тестирование рендера `<PlacementTestBanner>`, проверяющее, что он отображается при `lessonsCount === 0`.
* **Мокирование (MSW):** Мок ответа от `/api/ai/chat`, чтобы проверить, что при получении специального сообщения "Тест завершен", фронтенд успешно отправляет API запрос на обновление уровня и делает редирект.
