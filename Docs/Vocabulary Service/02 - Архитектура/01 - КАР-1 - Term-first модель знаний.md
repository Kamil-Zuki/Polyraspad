# Введение

Статусы знания, дедупликация карточек и действия ридера опираются на **точные формы** (`ProjectTerm.Text` / `NormalizedText`), а не на леммы.

## Контекст и проблема

Классический NLP-подход «свести всё к лемме» ломает LingQ-модель обучения:

* `sleep` и `slept` получают один статус — пользователь теряет прогресс по формам.
* `go` / `went` ошибочно считаются дубликатами одной карточки.
* Создание карточки по выделению в ридере должно сохранять **ровно** выделенную фразу.

## Принятое решение

1. **`ProjectTerm`** хранит `Text`, `NormalizedText` (`trim + lowercase`), `Type` (`WORD`/`PHRASE`), `Language`.
2. **`UserTermStatus`** — статус на term (`NEW` / `SAVED` / `KNOWN` / `IGNORED`; legacy mapping допускается в UI).
3. Дубликат = совпадение нормализованной точной формы/фразы; компоненты фразы не делают её дубликатом.
4. Inclusive может возвращать леммы для подсказок NLP, но **не** как ключ знания.

## Обоснование и последствия

* Ридер остаётся primary learning surface без принудительной навигации.
* Phrase highlight имеет приоритет над word highlight.
* Регрессии LingQ (см. AGENTS.md) обязательны при изменениях term/status/reader.
