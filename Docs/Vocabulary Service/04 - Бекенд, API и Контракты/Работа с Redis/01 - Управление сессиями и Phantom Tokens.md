# Работа с Redis: Кэширование Колод и Очередей Повторения

Данный документ описывает механизм кэширования в `VocabularyService` с использованием паттерна Cache-Aside.

---

## 1. Кэширование Дерева Колод (`GetDeckTree`)

### Логика работы
1. При вызове `GetDeckTree(userId, projectId, libraryFilter)` сервис выполняет поиск по ключу `vocab:deck_tree:{user_id}:{project_id}:{filter}` в Redis.
2.При **Cache Hit** сервис немедленно десериализует JSON и возвращает `GetDeckTreeResponse`.
3. При **Cache Miss** происходит выборка колод и денормализованной статистики из PostgreSQL (`internal.decks`), результат записывается в Redis командой `SETEX` со сроком жизни **300 секунд (5 минут)**.
4.При вызове `CreateDeck`, `UpdateDeck` или `DeleteDeck` кэш дерева колод данного пользователя инвалидируется командой `DEL`.

---

## 2. Оперативное состояние Учебной Сессии (`StudySession`)

### Логика работы
- Для предотвращения частых записи в PostgreSQL при ответах на карточки ("Again", "Hard", "Good", "Easy"), оперативное состояние текущей сессии повторений удерживается в Redis.
- При вызове `CompleteStudySession` конечная статистика по времени и количеству повторений записывается в `StudySessions` PostgreSQL.
