# SR-VOC-02: Система Интервального Повторения (FSRS)

## Описание
Расписание повторений карточек (FSRS) через Python-микросервис `inclusive`, сессии study и логи ответов.

---

## Возможности данного раздела

| Код | Название и Описание |
| :--- | :--- |
| **SR-VOC-STUDY-01** | **Очередь сессии:** StartSession / формирование New+Learning+Review с учётом дневных целей. |
| **SR-VOC-STUDY-02** | **GetNextCard / SubmitReview:** выдача карточки и оценка Again/Hard/Good/Easy → FSRS update. |
| **SR-VOC-STUDY-03** | **Leeches:** выборка карточек с высоким `Lapses`. |
| **SR-VOC-STUDY-04** | **UndoReview:** откат последнего ответа. |
| **SR-VOC-STUDY-05** | **BatchSubmitReviews / Sync path:** пакетная отправка reviews (в т.ч. offline sync). |
| **SR-VOC-STUDY-06** | **Answer validation:** результат проверки ответа в `ReviewLog.AnswerValidationResult` (jsonb). |

---

# Детальная спецификация требований

## SR-VOC-STUDY-01: Очередь сессии {#SR-VOC-STUDY-01}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Смешанная очередь | New / Learning-Relearning / Due Review. |
| Лимиты | Ограничение дневными целями `UserSetting`. |

### 2. Высокоуровневое описание
`StartSession` создаёт `StudySession` и готовит очередь в рамках проекта/колоды.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Старт daily study
1. Клиент вызывает StartSession.
2. Сервис возвращает session id и готовность к GetNextCard.

---

## SR-VOC-STUDY-02: GetNextCard / SubmitReview {#SR-VOC-STUDY-02}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| FSRS via inclusive | Пересчёт Due/Stability/Difficulty в Python. |
| Audit trail | Каждый ответ → `ReviewLog`. |

### 2. Высокоуровневое описание
После rating Vocabulary обновляет `UserCardProgress` и пишет before/after поля в лог.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Good
1. Пользователь ставит 3.
2. inclusive возвращает новый state; Due сдвигается вперёд.

---

## SR-VOC-STUDY-03: Leeches {#SR-VOC-STUDY-03}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Порог Lapses | Карточки с частыми забываниями доступны как список leeches. |

### 2. Высокоуровневое описание
Список используется UI и agent tool `get_recent_leeches`.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Запрос leeches
1. Клиент запрашивает leeches проекта.
2. Сервис фильтрует по Lapses threshold.

---

## SR-VOC-STUDY-04: UndoReview {#SR-VOC-STUDY-04}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Откат | Восстановление предыдущего FSRS state из последнего ReviewLog. |

### 2. Высокоуровневое описание
`UndoReview` откатывает последний успешный ответ пользователя в сессии/проекте.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Undo
1. Пользователь нажимает Undo.
2. Progress возвращается к before-полям лога.

---

## SR-VOC-STUDY-05: BatchSubmitReviews {#SR-VOC-STUDY-05}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Offline batch | Несколько reviews одним запросом (sync path). |

### 2. Высокоуровневое описание
Используется мобильными/оффлайн клиентами совместно с SyncData.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Batch after offline
1. Клиент отправляет массив reviews.
2. Сервис применяет FSRS по каждому и пишет логи.

---

## SR-VOC-STUDY-06: Answer validation {#SR-VOC-STUDY-06}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Structured result | `AnswerValidationResult` — jsonb, не свободная строка. |

### 2. Высокоуровневое описание
Для активных типов карточек результат проверки ответа сохраняется в ReviewLog.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Typed answer
1. Пользователь вводит текст.
2. Валидатор возвращает структуру; она пишется в лог вместе с rating.
