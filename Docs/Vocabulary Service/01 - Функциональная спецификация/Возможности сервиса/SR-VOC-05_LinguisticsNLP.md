# SR-VOC-05: Лингвистическая модель и NLP (Linguistics & NLP)

## Описание
Функциональные требования к учебным единицам ридера (точные словоформы и фразы), статусам известности, анализу текста и связанным API терминов. Продуктовая модель — **term-first** (не lemma-first).

---

## Возможности данного раздела

| Код | Название и Описание |
| :--- | :--- |
| **SR-VOC-LING-01** | **Выделение и нормализация терминов:** `ProjectTerm` с нормализацией trim + lower + схлопывание пробелов. |
| **SR-VOC-LING-02** | **Жизненный цикл статуса:** `NEW` / `SAVED` / `KNOWN` / `IGNORED` (+ legacy `LINGQ`/`LEARNING` → API `SAVED`). |
| **SR-VOC-LING-03** | **Пометка известными при page-turn (клиент):** клиент вызывает `BulkMarkKnown`; отдельного флага в `UserSetting` нет. |
| **SR-VOC-LING-04** | **Term API:** CreateOrUpdate, MarkKnown, Ignore, GetDetails, SearchDuplicates, List. |
| **SR-VOC-LING-05** | **BulkMarkKnown:** пакетная пометка терминов `KNOWN`. |
| **SR-VOC-LING-06** | **AnalyzeText:** токенизация/фразы + статусы пользователя (`TextService`). |
| **SR-VOC-LING-07** | **PurgeDemoImport:** очистка демо-импорта терминов/связанных данных. |

# Детальная спецификация требований

## SR-VOC-LING-01: Выделение и нормализация терминов {#SR-VOC-LING-01}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Exact Form Preservation | `sleep` и `slept` — разные термины/статусы. |
| Duplicate key | Нормализация без удаления пунктуации (`TermNormalizer`). |
| Term-first | Статусы и дубликаты не опираются на `ProjectLemma`. |

### 2. Высокоуровневое описание
При сохранении термина создаётся/находится `ProjectTerm` (`WORD`/`PHRASE`). `ProjectLemma` — legacy-сущность и не является основой статусов.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Сохранение фразы
1. Пользователь выделяет фразу в ридере.
2. Сервис создаёт `ProjectTerm` с `Type=PHRASE` и `UserTermStatus` (`SAVED` при наличии перевода).

---

## SR-VOC-LING-02: Жизненный цикл статуса термина {#SR-VOC-LING-02}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| NEW | Встречено впервые. |
| SAVED | Сохранено с переводом/карточкой (желтый). |
| KNOWN / IGNORED | Известное / игнорируемое. |

### 2. Высокоуровневое описание
Статус хранится в `UserTermStatus` вместе с skill levels и контекстом первого появления.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Mark Known
1. Пользователь нажимает «Знаю».
2. Статус становится `KNOWN`; подсветка в ридере снимается.

---

## SR-VOC-LING-03: Пометка известными при page-turn {#SR-VOC-LING-03}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Клиентская инициация | Перелистывание страницы — ответственность клиента/ридера. |
| Серверный контракт | Сервис предоставляет `BulkMarkKnown`; поля `AutoMarkAsKnownOnPageTurn` в `UserSetting` нет. |

### 2. Высокоуровневое описание
Если в UI включена опция page-turn (если она есть на клиенте), фронтенд собирает NEW-термины страницы и вызывает `BulkMarkKnown`.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Page turn
1. Клиент отправляет список term ids страницы.
2. Сервис помечает их `KNOWN` и возвращает обновлённые статусы.

---

## SR-VOC-LING-04: Term API {#SR-VOC-LING-04}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Единый API | CreateOrUpdate / MarkKnown / Ignore / GetDetails / SearchDuplicates / List. |

### 2. Высокоуровневое описание
`TermService` / `TermGrpcService` — основной контракт работы со статусами и деталями терминов, включая related cards.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: GetDetails
1. Клиент запрашивает термин.
2. Сервис возвращает статус, meaning, skill levels, связанные карточки.

---

## SR-VOC-LING-05: BulkMarkKnown {#SR-VOC-LING-05}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Пакетность | Массовая пометка без N отдельных MarkKnown. |

### 2. Высокоуровневое описание
Используется ридером и импортом для пакетного перевода терминов в `KNOWN`.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Пакет
1. Клиент передаёт массив ProjectTermId.
2. Сервис обновляет статусы атомарно в рамках проекта пользователя.

---

## SR-VOC-LING-06: AnalyzeText {#SR-VOC-LING-06}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Токены + статусы | Текст разбирается; на токены/фразы накладываются UserTermStatus. |
| Phrase priority | Подсветка фраз приоритетнее одиночных слов (продуктовое правило ридера). |

### 2. Высокоуровневое описание
`TextService.AnalyzeText` возвращает токены и фразы со статусами для рендера ридера.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Анализ абзаца
1. Клиент отправляет текст и ProjectId.
2. Сервис возвращает токены со статусами NEW/SAVED/KNOWN/IGNORED.

---

## SR-VOC-LING-07: PurgeDemoImport {#SR-VOC-LING-07}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Очистка демо | Удаление данных, созданных демо-импортом. |

### 2. Высокоуровневое описание
RPC `PurgeDemoImport` очищает demo-набор терминов/связанных объектов проекта.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Purge
1. Пользователь сбрасывает демо-контент.
2. Сервис удаляет demo-записи и связанные tombstones при необходимости.
