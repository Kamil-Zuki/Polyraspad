# SR-VOC-04: Ядро Словаря (Vocabulary Core)

## Описание
Данный раздел описывает функциональные требования к управлению пользовательскими проектами, иерархией колод, процессом создания заметок и генерации карточек, а также работой алгоритма интервального повторения FSRS и операциями над карточками.

---

## Возможности данного раздела

| Код | Название и Описание |
| :--- | :--- |
| **SR-VOC-CORE-01** | **Изоляция проектов (Project Isolation):** Изоляция данных в рамках языкового проекта (`Title`, `SourceLang`, `TargetLang`, `IsArchived`). |
| **SR-VOC-CORE-02** | **Вложенные колоды (Nested Decks):** Древовидная иерархия колод с политиками публикации/контрибуций. |
| **SR-VOC-CORE-03** | **Генерация карточек по шаблонам (Card Generation):** Note + NoteType/CardTemplate → Card. |
| **SR-VOC-CORE-04** | **Интервальное повторение FSRS (FSRS Scheduling):** Расчёт Due/Stability/Difficulty через `inclusive`. |
| **SR-VOC-CORE-05** | **Теги как поле заметки:** Теги хранятся в `Note.FieldValues` для полей с `FieldType = "tags"` (отдельных entity Tag/NoteTag нет). |
| **SR-VOC-CORE-06** | **CRUD и поиск карточек:** Создание, чтение, обновление, удаление, поиск, bulk-операции (`CardService`). |
| **SR-VOC-CORE-07** | **Capture и проверка дубликатов:** `CaptureCard`, `CheckCardDuplicates` по нормализованному термину/фразе. |
| **SR-VOC-CORE-08** | **Обслуживание карточек:** Suspend/Unsuspend, reset progress, leeches, missing media. |
| **SR-VOC-CORE-09** | **NoteType для редактора:** `GetNoteTypeForEditor` — схема полей для UI редактора. |
| **SR-VOC-CORE-10** | **Прокси медиа карточек:** Upload image/document и получение URL через MediaService. |

# Детальная спецификация требований

## SR-VOC-CORE-01: Изоляция проектов {#SR-VOC-CORE-01}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Целевая языковая изоляция | Проект = замкнутое пространство пары `SourceLang` + `TargetLang`. |
| Архивация | Проект помечается `IsArchived`; отдельного флага `IsActive` в модели нет. |

### 2. Высокоуровневое описание
Пользователь создаёт проекты с полями `Title`, `SourceLang`, `TargetLang`, JSON `FsrsSettings` и `Stats`. Все запросы к словарю и ридеру фильтруются по `ProjectId`.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Создание проекта (Happy Path)
1. Клиент вызывает создание проекта с языковой парой.
2. Сервис сохраняет `Project` с дефолтными `FsrsSettings` и пустым `Stats`.
3. Последующие колоды/карточки/термины привязываются к `Project.Id`.

---

## SR-VOC-CORE-02: Вложенные колоды {#SR-VOC-CORE-02}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Иерархия | `ParentDeckId` задаёт дерево колод. |
| Marketplace-поля | `OwnerId`, `IsPublic`, `ContributionPolicy`, `LicenseType`, `ForkedFromId`, `CardCount`. |

### 2. Высокоуровневое описание
Колоды образуют дерево внутри проекта. Запуск изучения родительской колоды включает карточки дочерних подколод.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Создание подколоды
1. Клиент создаёт колоду с `ParentDeckId` существующей колоды того же проекта.
2. Сервис сохраняет `Deck` и обновляет дерево.

---

## SR-VOC-CORE-03: Генерация карточек по шаблонам {#SR-VOC-CORE-03}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Note-Card separation | Пользователь заполняет Note; Card генерируются по CardTemplate. |
| Связь с ридером | Note/Card могут ссылаться на `ProjectTermId`. |

### 2. Высокоуровневое описание
Из одной заметки по включённым шаблонам (`Enabled`) создаются одна или несколько карточек с поисковым индексом.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Создание заметки с двумя шаблонами
1. Пользователь сохраняет Note с field values.
2. Сервис создаёт Card для каждого enabled CardTemplate.

---

## SR-VOC-CORE-04: Интервальное повторение FSRS {#SR-VOC-CORE-04}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Модель памяти | `UserCardProgress`: Stability, Difficulty, Due, State, Lapses… |
| Четыре оценки | Again/Hard/Good/Easy → пересчёт через `inclusive`. |

### 2. Высокоуровневое описание
При ответе параметры уходят в Python-микросервис `inclusive`; результат пишется в `UserCardProgress` и `ReviewLog`.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Оценка Good
1. Пользователь ставит rating=3.
2. Scheduler обновляет Due/Stability и пишет ReviewLog.

---

## SR-VOC-CORE-05: Теги как поле заметки {#SR-VOC-CORE-05}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Без entity Tag | Отдельных таблиц `Tag`/`NoteTag` нет. |
| FieldType tags | Теги — значение поля с `NoteField.FieldType = "tags"` в `Note.FieldValues`. |

### 2. Высокоуровневое описание
Фильтрация по тегам (если реализована на клиенте/поиске) опирается на содержимое field values, а не на join с Tag.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Сохранение тегов в заметке
1. Редактор передаёт значение поля tags в FieldValues.
2. Сервис сохраняет Note без создания строк в таблице Tag.

---

## SR-VOC-CORE-06: CRUD и поиск карточек {#SR-VOC-CORE-06}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Полный lifecycle | Create/Update/Delete/Search/Get + bulk delete/move. |

### 2. Высокоуровневое описание
`CardService` / `CardGrpcService` обслуживают операции над карточками в рамках проекта пользователя.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Bulk move
1. Клиент передаёт список CardId и целевую колоду.
2. Сервис обновляет `DeckId` и пересчитывает `CardCount`.

---

## SR-VOC-CORE-07: Capture и проверка дубликатов {#SR-VOC-CORE-07}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Exact form | Capture сохраняет точную форму/фразу. |
| Duplicate key | Нормализация: trim + lower + схлопывание пробелов. |

### 2. Высокоуровневое описание
RPC `CaptureCard` и `CheckCardDuplicates` предотвращают создание дубликатов точной фразы; компонентные слова фразы дубликатами не считаются.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Capture существующей фразы
1. Клиент вызывает CheckCardDuplicates.
2. Сервис находит совпадение по NormalizedText и возвращает существующие карточки.

---

## SR-VOC-CORE-08: Обслуживание карточек {#SR-VOC-CORE-08}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Suspend | `UserCardProgress.IsSuspended` исключает карточку из очереди. |
| Leeches / media | Выборка проблемных карточек для UI обслуживания. |

### 2. Высокоуровневое описание
Сервис предоставляет RPC suspend/unsuspend, reset progress, списки leeches и карточек без медиа.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Suspend
1. Пользователь откладывает карточку.
2. `IsSuspended = true`; очередь study её не отдаёт.

## SR-VOC-CORE-09: NoteType для редактора {#SR-VOC-CORE-09}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |

### 2. Высокоуровневое описание
`GetNoteTypeForEditor` отдаёт схему для построения формы создания/редактирования карточки.

### 3. Примеры взаимодействия (логические сценарии)

1. Клиент запрашивает NoteType проекта.
2. UI строит поля по `NoteField.SortOrder`.

---

## SR-VOC-CORE-10: Прокси медиа карточек {#SR-VOC-CORE-10}
### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| Thin storage | Файлы в MediaService; Vocabulary хранит ссылки в полях заметки/карточки. |

### 2. Высокоуровневое описание
RPC upload image/document и get URL проксируют вызовы MediaService для контента карточек.

### 3. Примеры взаимодействия (логические сценарии)

#### Сценарий А: Upload изображения
1. Клиент загружает файл через Vocabulary gRPC.
2. Vocabulary вызывает MediaService и возвращает URL.
