## Введение

Настоящий документ определяет функциональные возможности (сервисные требования) микросервиса **«Billing Service»** — SaaS-биллинга платформы Polyraspad.

**Billing Service** владеет каталогом тарифов, подписками пользователей, entitlements и историей платежей. Публичный REST для браузера — через **AggregatorService** (JWT); другие микросервисы читают лимиты по **gRPC** (`CheckAccess`, `GetEntitlements`).

Документ предназначен для разработчиков, QA, системных аналитиков и архитекторов.

---

# Группы возможностей

Ниже представлен перечень из 9 групп функциональных возможностей (сервисных требований) для микросервиса Billing Service. Требования сгруппированы по логическим блокам для удобства навигации.

| Группа | Название и Описание |
| :----- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Управление клиентами (Customers)** | **Billing customer:** Создание/обеспечение записи customer по `user_id` для checkout и recurring payments. |
| **Каталог SaaS-планов (Plans)** | **Plan catalog:** Provider-agnostic список тарифов с ценой, trial и entitlements jsonb. |
| **Подписки SaaS (Subscriptions)** | **Subscription lifecycle:** Checkout, текущая подписка, отмена — `BillingSubscription` в PostgreSQL. |
| **Access и entitlements** | **Platform limits:** CheckAccess и GetEntitlements для VocabularyService и UI badge. |
| **Инвойсы (Invoices)** | **Payment history:** Список инвойсов пользователя с пагинацией. |
| **Платёжные провайдеры (Payment Providers)** | **Provider adapters:** IPaymentProvider, Mock и ЮKassa; factory по конфигу. |
| **Webhook-оркестрация (Webhooks)** | **Inbound events:** ProcessWebhook, idempotency, normalized domain events. |
| **Автопродление (Renewal)** | **LocallyManaged renewal:** Background worker для ЮKassa recurring. |
| **Платформенные контракты (Operations)** | **gRPC server и health:** Kestrel 5127, `/healthz`, без публичного REST. |

## Описание возможностей

Ниже представлен детальный перечень сервисных требований (SR) для каждой группы. Подробное описание каждого требования находится в соответствующих вложенных документах.

### 1. Управление клиентами (Customers)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-BILL-CUST-01** | **Ensure customer:** Создание или получение `Customer` по `user_id` и email перед checkout; unique `UserId`. |

### 2. Каталог SaaS-планов (Plans)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-BILL-PLAN-01** | **List plans:** Каталог активных SaaS-планов с price, trial и entitlements для UI billing page. |

### 3. Подписки SaaS (Subscriptions)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-BILL-SUB-01** | **Get subscription:** Текущая подписка пользователя — status, period, cancel flags. |
| **SR-BILL-SUB-02** | **Create checkout:** Создание checkout session у провайдера; subscription `Incomplete` + confirmation URL. |
| **SR-BILL-SUB-03** | **Cancel subscription:** Отмена at period end или immediate; обновление `CancelAtPeriodEnd` / `Canceled`. |

### 4. Access и entitlements

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-BILL-ACCESS-01** | **Check access:** has_access, plan_code, status, period_end с grace для PastDue и fallback на free. |
| **SR-BILL-ENT-01** | **Get entitlements:** Map лимитов текущего плана для enforcement в VocabularyService. |

### 5. Инвойсы (Invoices)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-BILL-INV-01** | **List invoices:** Пагинированная история платежей пользователя. |

### 6. Платёжные провайдеры (Payment Providers)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-BILL-PROV-01** | **Provider abstraction:** IPaymentProvider + factory; домен не знает ЮKassa/Stripe. |
| **SR-BILL-PROV-02** | **ЮKassa adapter:** Checkout, recurring, webhook mapping; LocallyManaged mode. |
| **SR-BILL-PROV-03** | **Mock provider:** Dev/tests без credentials; programmatic success path. |

### 7. Webhook-оркестрация (Webhooks)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-BILL-WH-01** | **Process webhook:** Signature verify, idempotency store, WebhookOrchestrator apply events. |

### 8. Автопродление (Renewal)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-BILL-REN-01** | **Renewal worker:** Polling LocallyManaged subscriptions; recurring charge + PastDue grace cutoff. |

### 9. Платформенные контракты (Operations)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-BILL-OPS-01** | **gRPC и healthz:** Единственный внешний API сервиса; REST только через Aggregator BFF. |

Подробные SR-блоки — во вложенных файлах групп. gRPC контракты — в `04 - Бекенд, API и Контракты/` (batch).
