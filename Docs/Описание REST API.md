## **Введение**

Настоящий документ содержит техническое описание REST API микросервиса **Personal Vocabulary Service (PVS)**.

API предназначено для взаимодействия с клиентскими приложениями (Web SPA, Mobile iOS/Android, Browser Extension) и обеспечивает доступ к функциям управления контентом, обучения, синхронизации и маркетплейса.

Документ разработан на основе функциональной спецификации версии **7.0 (Golden Master)** и документа описания DTO (**PVS-DTO-2025-1**).

### **Общие принципы**

1.  **Аутентификация:** Все запросы (кроме публичных эндпоинтов здоровья) требуют наличия заголовка Authorization: Bearer {jwt_token}. Токены выдаются Identity Service.

2.  **Формат данных:** Все запросы и ответы используют Content-Type: application/json.

3.  **Даты и время:** Все временные метки передаются в формате ISO 8601 (UTC).

4.  **Коды ответов:**

    - 200 OK --- Успешный синхронный запрос.

    - 202 Accepted --- Задача принята в фоновую обработку (например, импорт).

    - 400 Bad Request --- Ошибка валидации (возвращает ProblemDetails).

    - 401/403 --- Ошибки доступа.

    - 404 Not Found --- Ресурс не найден.

## **2. Колоды (Decks)**

### **SR-STR-03: Получение дерева колод: /projects/{projectId}/decks/tree**

**Общая информация**

  ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  Параметр                   Значение
  -------------------------- ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **Тип метода**             GET

  **Описание**               Получение полной иерархической структуры (дерева) колод внутри указанного проекта. Используется для построения навигационного меню (\"сайдбара\"). Метод оптимизирован для минимизации объема данных (возвращает только ID, названия и структуру, без полного контента). Реализует **SR-STR-03**.

  **DTO запроса**            N/A

  **DTO успешного ответа**   DeckTreeItemDto\[\] (Массив корневых узлов)
  ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

**Параметры URL**

  ----------------------------------------------------------------------------------------
  Название параметра   Тип данных      Описание
  -------------------- --------------- ---------------------------------------------------
  projectId            string (uuid)   ID проекта, для которого запрашивается структура.

  ----------------------------------------------------------------------------------------

**Логика обработки запроса**

1.  **Аутентификация:** Извлечение UserId.

### **SR-LRN-03: Отправка оценки (FSRS): /study/session/{id}/review**

**Общая информация**

  -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  Параметр                   Значение
  -------------------------- ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **Тип метода**             POST

  **Описание**               Обрабатывает ответ пользователя (Again/Hard/Good/Easy). Запускает алгоритм FSRS для расчета нового интервала, обновляет статистику и проверяет на «Личевость» (SR-LRN-05).

  **DTO запроса**            ReviewCardRequestDto

  **DTO успешного ответа**   ReviewResponseDto
  -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

**Параметры URL**

  ----------------------------------------------------------
  Название параметра   Тип данных      Описание
  -------------------- --------------- ---------------------
  id                   string (uuid)   ID активной сессии.

  ----------------------------------------------------------

**Логика обработки запроса**

1.  **Расчет FSRS:**

    - Загружается текущее состояние (S, D) из user_card_progress.

    - При включённом микросервисе **inclusive** (Inclusive:UseForFsrs) VocabularyService передаёт в запросе ReviewCard по gRPC настройки проекта: request_retention, maximum_interval и массив весов (w). Микросервис inclusive создаёт планировщик py-fsrs с этими параметрами и выполняет расчёт (соответствие Anki/FSRS). При недоступности inclusive используется встроенный калькулятор (fallback).

    - Применяется формула FSRS с учетом оценки (rating) и весов проекта.

2.  **Сохранение (Транзакция):**

    - Обновляется запись в user_card_progress.

    - Добавляется запись в review_logs (для Undo и Истории).

    - Обновляется статистика сессии в Redis.

3.  **Валидация ответа (опционально):**

    - Если передан **userAnswer**, сервис проверяет ответ (точное совпадение, fuzzy match, синонимы) и сохраняет результат в **review_logs.answer_validation_result**. Результат возвращается в **ReviewResponseDto.answerValidation**. При неверном ответе оценка может автоматически понижаться до Again.

4.  **Обработка \"Again\":**

    - Если оценка Again (1), карточка возвращается в очередь текущей сессии (Re-queue), чтобы пользователь повторил её через несколько минут.

5.  **Leech Check (SR-LRN-05):**

    - Если количество Lapses превысило порог, карточка помечается Suspended, и в ответе возвращается флаг isLeech: true.

6.  **Ответ:** Возвращается рассчитанный интервал (например, \"3d\") и при наличии **userAnswer** — объект **answerValidation**.

### **SR-SNC-01: Синхронизация данных (Delta Sync): /sync**

**Общая информация**

  -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

  **Тип метода**             POST

  **Описание**               Основной метод для синхронизации мобильных клиентов. Принимает токен времени последнего обновления (lastSyncToken) и возвращает только те данные (колоды, карточки, прогресс), которые изменились после этого времени. Также возвращает список ID удаленных объектов (\"надгробия\") для очистки локальной БД.

  **DTO запроса**            SyncRequestDto

  **DTO успешного ответа**   SyncResponseDto
  -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

**Параметры URL**

  -------------------------------------------------------------
  Название параметра   Тип данных   Описание

**Логика обработки запроса**

1.  **Аутентификация:** Извлечение UserId.

2.  **Валидация токена:**

    - Если lastSyncToken равен 0 или слишком старый (\> 30 дней), сервис может вернуть флаг requiresFullSync: true (принудительная полная перезагрузка).

6.  **Ответ:** Возвращается пакет данных.

**Общая информация**

  -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  Параметр                   Значение
  -------------------------- ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **Тип метода**             POST

  **Описание**               Принимает массив результатов обучения, накопленных клиентом в режиме офлайн. Сервис обрабатывает каждый ответ последовательно, пересчитывая интервалы FSRS \"задним числом\" на основе реального времени ответа (reviewedAt), чтобы сохранить математическую точность алгоритма.

5.  **Фиксация:** Транзакция комитится.

6.  **Ответ:** 200 OK. При следующей синхронизации (/sync) клиент получит обновленные интервалы.

  **DTO запроса**            AdminReviewRequestDto

  **DTO успешного ответа**   ProductDto (обновленный)
  -----------------------------------------------------------------------------------------------------------------------------------

**Логика обработки запроса**

1.  **RBAC:** Проверка роли MODERATOR.

2.  **Обработка вердикта:**

    - **APPROVE:** Статус меняется на PUBLISHED. Товар появляется в поиске.

    - **REJECT:** Статус меняется на DRAFT (для исправлений) или BANNED.

3.  **Уведомление:** Автору отправляется письмо/пуш с комментарием модератора.

4.  **Логирование:** Действие модератора записывается в admin_logs.

**Пример запроса (Отказ)**

code JSON

downloadcontent_copy

expand_less

{

\"verdict\": \"REJECT\",

\"reason\": \"VIOLATION_COPYRIGHT\",

\"comment\": \"Обложка содержит логотип Apple. Пожалуйста, замените изображение.\"

}

### **SR-MOD-03: Откат версии (Rollback): /admin/moderation/products/{id}/rollback**

**Общая информация**

  --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  Параметр                   Значение
  -------------------------- -----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **Тип метода**             POST

  **Описание**               Экстренная мера. Если автор обновил нормальный товар на вредоносный (Bait-and-Switch), модератор может принудительно откатить товар к предыдущей безопасной версии (DeckVersion).

  **DTO запроса**            AdminRollbackRequestDto

  **DTO успешного ответа**   SuccessResponseDto
  --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

**Логика обработки запроса**

1.  **RBAC:** Проверка роли ADMIN (обычно требует прав выше, чем модератор).

2.  **Откат:**

    - Сервис меняет ссылку linked_deck_id в товаре на ID старого снимка.

    - Текущая версия помечается как REJECTED.

3.  **Блокировка:** На товар накладывается edit_lock, чтобы автор не мог снова обновить его без проверки.

4.  **Принудительная синхронизация:** Генерируется системное событие, заставляющее клиентские приложения покупателей перекачать колоду.

**Пример запроса**

code JSON

downloadcontent_copy

expand_less

{

\"targetDeckVersionId\": \"version-uuid-v1\",

\"reason\": \"Hate speech detected in v2 update\"

}

### **SR-MOD-02: Массовое закрытие жалоб: /admin/moderation/reports/resolve**

**Общая информация**

  ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  Параметр                   Значение
  -------------------------- ---------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **Тип метода**             POST

  **Описание**               Позволяет закрыть все активные жалобы на товар после проведения проверки. Используется для разблокировки товара, скрытого системой автоматически (Circuit Breaker).

  **DTO запроса**            ResolveReportsRequestDto

  **DTO успешного ответа**   SuccessResponseDto
  ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

**Логика обработки запроса**

1.  **RBAC:** Проверка роли MODERATOR.

2.  **Анализ:** Модератор указывает, подтвердились ли жалобы.

    - **GUILTY (Виновен):** Товар банится, жалобы помечаются как \"Обоснованные\" (повышается рейтинг доверия жалобщиков).

    - **INNOCENT (Невиновен):** Товар возвращается в PUBLISHED, жалобы помечаются как \"Ложные\" (рейтинг доверия жалобщиков снижается).

3.  **Сброс счетчиков:** Счетчик активных жалоб на товаре сбрасывается.

**Пример запроса**

code JSON

downloadcontent_copy

expand_less

{

\"productId\": \"prod-uuid-123\",

\"verdict\": \"INNOCENT\",

\"comment\": \"Проверено. Нарушений авторских прав нет, контент легален.\"

}
