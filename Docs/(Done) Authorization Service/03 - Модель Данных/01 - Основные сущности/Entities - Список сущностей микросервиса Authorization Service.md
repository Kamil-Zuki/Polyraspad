# Введение

**Authorization Service (Сервис Авторизации Платформы)** — это высоконагруженный микросервис, выполняющий роль **локального привратника (Gatekeeper)** и **менеджера сессий** для конкретной инсталляции платформы STEOS (будь то публичное облако `steos.io`, приватный контур или on-premise установка).

В отличие от глобального `STEOS ID` (который отвечает за аутентификацию, хранение паролей и выдачу "паспортов"), данный микросервис отвечает за **контекст и авторизацию**. Он доверяет криптографическим токенам STEOS ID и использует их для того, чтобы пустить пользователя в конкретное Пространство (Workspace) и выдать ему локальные права.

**Ключевые архитектурные принципы сервиса:**
1.  **Паттерн Phantom Token (Opaque Token):** Сервис не выдает на фронтенд "толстые", читаемые JWT-токены с правами. Вместо этого он устанавливает защищенную, зашифрованную `HttpOnly` Cookie (Session ID). Вся бизнес-логика (парсинг ролей, ID пространства) происходит строго на бэкенде, защищая данные от перехвата и XSS-атак.
2.  **JIT Onboarding (Just-In-Time):** Сервис оркестрирует автоматическое создание локальных профилей. Если пользователь из STEOS ID заходит на платформу впервые, Auth Service автоматически обращается к `Workspace Service` для создания ему личного пространства (согласно глобальным политикам).
3.  **Асинхронная Инвалидация (Back-Channel Logout):** Сервис слушает события от глобального STEOS ID. Если там происходит блокировка аккаунта (Global Ban), локальные сессии в этом микросервисе уничтожаются мгновенно.
4.  **Управление контекстом (Workspace Context):** Пользователь может состоять в 10 пространствах. Auth Service управляет тем, в каком именно "окне" пользователь находится прямо сейчас, и отдает внутренним микросервисам (Tasks, CRM) только релевантные права для этого пространства.
5.  **Механика Одноразовых Билетов (One-Time Tickets):** Для работы WebSockets и безопасного скачивания файлов реализован механизм генерации короткоживущих (15 секунд) токенов, сгорающих при первом использовании. *(Реализуется в In-Memory хранилище Redis, без участия реляционной БД).*
6.  **Локальная авторизация и политики доступа (Access Control):** программный доступ через персональные API-ключи (**PAT**, таблица `api_keys`); политики периметра Workspace (Geo/IP) конфигурируются в **Workspace Service**, а Authorization Service применяет их при оценке доступа по контрактам API/gRPC.

# Список ключевых сущностей микросервиса

## Группа 1: Управление Сессиями и Контекстом (Session Management)
*Фундаментальное ядро микросервиса. Отвечает за идентификацию входящих HTTP-запросов и их жесткую привязку к глобальным субъектам, локальным профилям и рабочим пространствам.*

| Сущность                                             | Описание и назначение                                                                                                                                                                                                                                                                                                         |
| :--------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Авторизованная сессия**<br>(`authorized_sessions`) | **Контракт входа.** Главная сущность, представляющая активное подключение верифицированного субъекта (Человека или ИИ-Агента). Фиксирует факт обмена OIDC-токена STEOS ID на локальную сессию платформы. Поддерживает механизм **Имперсонации** (когда суперадмин входит под аккаунтом клиента для оказания техподдержки).    |
| **Контекст сессии**<br>(`session_contexts`)          | **Маршрутизатор Пространств.** Таблица, связанная 1:1 с `authorized_sessions`. Отвечает на вопрос: "В каком Пространстве (Workspace) этот юзер находится прямо сейчас?". Обновляется при переключении между пространствами в UI без необходимости повторного ввода пароля.                                                    |
| **Гостевая сессия**<br>(`guest_sessions`)            | **Теневой аккаунт (Аноним).** Сессия для неавторизованных посетителей (Public Mode). Привязывается к аппаратному отпечатку браузера (`fingerprint`). Позволяет платформе выдавать демо-квоты (например, "3 бесплатные генерации ИИ") и сохранять наработанный гостем стейт для последующей конвертации в полноценный аккаунт. |
## Группа 2: Инфраструктура OIDC и Интеграция (OIDC Infrastructure)
*Техническая прослойка, обеспечивающая криптографически безопасный и стандартизированный диалог между локальной платформой и глобальным STEOS ID.*

| Сущность                                         | Описание и назначение                                                                                                                                                                                                                                                                              |
| :----------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Состояние OIDC-потока**<br>(`oidc_auth_flows`) | **Защита редиректов.** Временная таблица. Хранит параметры `state`, `nonce` и `code_verifier` (стандарт PKCE) в тот момент, когда платформа перенаправила пользователя на страницу логина STEOS ID. Защищает платформу от атак типа CSRF и перехвата авторизационных кодов.                        |
| **Кэш ключей IdP**<br>(`idp_jwks_cache`)         | **Криптографический кэш.** Хранит актуальные публичные ключи (JSON Web Key Set), скачанные с глобального STEOS ID. Позволяет локальному сервису авторизации математически валидировать входящие JWT-токены мгновенно, без выполнения сетевых HTTP-запросов к глобальному облаку при каждом логине. |
## Группа 3: Защита Периметра и Гостевые Квоты (Security & Quotas)
*Слой локальной безопасности, защищающий конкретную инсталляцию платформы от перегрузок и злоупотребления бесплатными ресурсами.*

| Сущность                                                    | Описание и назначение                                                                                                                                                                                                                                   |
| :---------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Использование гостевой фичи**<br>(`guest_feature_usages`) | **Счетчик лимитов.** Связывает `guest_session_id` с конкретной Фичей (возможностью) из `Platform Service`. Отслеживает и ограничивает потребление исчерпаемых ресурсов (например, попыток генерации текста) для анонимов.                               |
| **Причина локальной блокировки**<br>(`local_ban_reasons`)   | **Справочник.** Категоризирует основания для блокировки трафика на уровне локального шлюза платформы (например, `GUEST_QUOTA_ABUSE`, `API_RATE_LIMIT`, `MALICIOUS_PAYLOAD`). Обеспечивает стандартизацию инцидентов и локализацию сообщений об ошибках. |
| **Локальная блокировка**<br>(`local_suspicious_activities`) | **Динамический файрвол.** Реестр временно заблокированных IP-адресов или Fingerprint-ов на уровне текущей платформы (например, защита от парсинга публичных страниц или DDoS-атак). Срабатывает до того, как запрос дойдет до глобального STEOS ID.     |
## Группа 4: Локальный Аудит Доступа (Local Access Audit)
*Собственный журнал безопасности платформы. В отличие от глобального аудита STEOS ID (который логирует смену паролей), здесь фиксируются действия на уровне приложения.*

| Сущность                                                     | Описание и назначение                                                                                                                                                                                                                                                               |
| :----------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Событие локального аудита**<br>(`local_audit_event_types`) | **Справочник.** Единый реестр стандартизированных действий, происходящих на уровне локального шлюза авторизации (например: `SESSION_STARTED`, `CONTEXT_SWITCHED`, `GUEST_SESSION_CREATED`). Позволяет жестко типизировать логи и локализовать их для пользовательского UI.          |
| **Журнал локального доступа**<br>(`access_audit_logs`)       | **Неизменяемый реестр (WORM).** Фиксирует критические для платформы события: успешный вход (завершение OIDC-флоу), смену активного Пространства (Context Switch), старт/стоп сессии Имперсонации, а также срабатывание сигналов удаленного завершения сессий (Back-Channel Logout). |

## Группа 5: Локальная авторизация и политики доступа (Access Control)

*Программные учётные данные (PAT) и согласованная оценка периметра Workspace: что персистится в Auth (`api_keys`), а что — во внешнем Workspace Service. Подробнее в группирующем документе: [Entity - Локальная Авторизация и Политики Доступа - Access Control](Entity%20-%20Локальная%20Авторизация%20и%20Политики%20Доступа%20-%20Access%20Control.md).*

| Сущность / объект | Описание и назначение |
| :--- | :--- |
| **Персональный API-ключ (PAT)**<br>(`api_keys`) | **Машинный доступ с ограниченными правами (реляционная сущность Auth).** Метаданные ключа, **хэш** секрета, scopes, сроки и отзыв; открытый токен — только при создании. |
| **Политики периметра Workspace**<br>(логическая модель; хранение в Workspace Service) | **Geo/IP и связанные ограничения для Workspace.** Источник правды не в БД Auth; Auth запрашивает политику и применяет её при валидации доступа. Детали схемы — в модели Workspace. |
