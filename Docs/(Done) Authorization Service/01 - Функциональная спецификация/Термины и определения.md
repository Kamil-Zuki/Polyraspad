# Введение

Настоящий документ представляет собой единый глоссарий терминов, концепций и паттернов, используемых при проектировании, разработке и эксплуатации микросервиса **Authorization Service (Сервис Авторизации)** и связанных с ним компонентов платформы STEOS.

# Назначение и цель документа

Цель данного документа — создать общий, однозначный язык для всех участников проекта: разработчиков, архитекторов, QA-инженеров, DevOps-специалистов и менеджеров. 

Единая терминология является краеугольным камнем эффективной коммуникации, она устраняет двусмысленность и четко разделяет зоны ответственности между глобальным Identity Provider (STEOS ID) и локальным менеджером сессий (Authorization Service). Понимание этих концепций критически важно для реализации архитектуры **Zero Trust** внутри экосистемы.

# Ключевые понятия и сущности

| Термин | Описание |
| :--- | :--- |
| **AUTH (Authorization Service / Локальный Gatekeeper)** | Микросервис, реализующий локальные сессии, политики и PEP. **Единая точка входа HTTP/WebSocket для клиентов** — это **API Gateway (агрегатор)** на периметре; он терминирует REST/WSS и вызывает AUTH по gRPC. AUTH *не проверяет* пароли сам по себе в роли IdP — он *доверяет* токенам от STEOS ID и управляет локальным состоянием. |
| **STEOS ID (Global IdP)** | Внешний, независимый от платформы сервис аутентификации. Выступает единым источником истины о пользователях. Хранит пароли, 2FA, паспорта (KYC) и выдает OIDC-токены. |
| **Session Context (Контекст сессии)** | Маршрутизатор Пространств. Сущность на стороне бэкенда, запоминающая, в каком именно Workspace (Рабочем пространстве) пользователь работает в данный момент. Позволяет не передавать ID пространства в каждом HTTP-запросе от фронтенда. |
| **One-Time Tickets (Одноразовые билеты)** | Короткоживущие (15 секунд) случайные токены, генерируемые в Redis. Используются для передачи прав доступа в сценариях, где нельзя использовать Cookie (например, открытие `ws://` соединений или формирование ссылок на прямое скачивание файлов `<img>`, `<a>`). |
| **Device Fingerprint (Отпечаток устройства)** | Уникальный хэш характеристик устройства (браузер, разрешение, ОС, шрифты), собираемый фронтендом. Используется для привязки Cookie к конкретному устройству. Попытка использовать украденную Cookie с другим Fingerprint приводит к мгновенному сбросу сессии. |
| **Гостевая сессия (Guest Session)** | Временный "теневой" аккаунт для неавторизованных посетителей (Public Mode). Привязывается аппаратному отпечатку браузера. Позволяет платформе выдавать демо-квоты и сохранять наработанный гостем стейт до регистрации. |

# Процессы и рабочие потоки

| Термин                                      | Описание                                                                                                                                                                                                                                          |
| :------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **OIDC Authorization Code Flow**            | Стандартизированный протокол (OAuth 2.1 BCP), по которому фронтенд платформы безопасно получает от глобального STEOS ID токены доступа, используя механизмы защиты `state`, `nonce` и `PKCE` (без передачи токенов в URL браузера).               |
| **JIT Onboarding (Just-In-Time)**           | Автоматизированный процесс "ленивой" регистрации на платформе. Если пользователь с валидным токеном STEOS ID заходит на платформу впервые, AUTH перехватывает его и автоматически вызывает `Workspace Service` для создания личного пространства. |
| **OIDC Back-Channel Logout**                | Асинхронный механизм отзыва сессий. Если пользователя блокируют глобально в STEOS ID, сигнал об этом мгновенно рассылается через брокер сообщений. AUTH убивает локальные сессии в Redis за миллисекунды, выкидывая злоумышленника из платформы.  |
| **Impersonation (Имперсонация / God Mode)** | Легитимный механизм входа сотрудника техподдержки (impersonator) в аккаунт клиента. В бизнес-логику прокидывается ID клиента (чтобы саппорт видел его данные), но в WORM-аудит записывается ID саппорта (для юридической защиты компании).        |
| **Silent Refresh (Тихое продление)**        | Фоновый процесс продления "жизни" сессии. AUTH автоматически, без участия пользователя и перезагрузки страницы, использует зашифрованный `refresh_token` для получения нового `access_token` у STEOS ID.                                          |

# Архитектура и паттерны

| Термин | Описание |
| :--- | :--- |
| **Phantom Token Pattern (Opaque Token)** | Паттерн безопасности. Суть: вместо выдачи браузеру читаемого JWT-токена со всеми правами, браузер получает лишь криптографически случайную строку (UUID) в `HttpOnly` Cookie. Реальные права хранятся на бэкенде. Исключает возможность кражи стейта через XSS. |
| **Zero Trust Architecture (Нулевое доверие)** | Подход к внутренней безопасности. Внутренние бизнес-сервисы платформы (Tasks, CRM, Billing) *никогда* не проверяют сессии и Cookie. Они полностью доверяют заголовкам (`X-Global-Actor-Id`, `X-Workspace-Id`), которые может проставить *только* Authorization Service (Edge-слой). |
| **Server-Side Context Routing** | Паттерн, при котором маршрутизация запросов (в какое именно пространство направить задачу) выполняется не фронтендом, а API Gateway'ем (AUTH) на основе стейта, лежащего в Redis. |
| **WORM (Write Once, Read Many)** | Принцип неизменяемости данных. Локальные логи аудита платформы (`access_audit_logs`) могут быть только записаны, но никогда не могут быть обновлены (`UPDATE`) или удалены (`DELETE`) из базы данных. |

# Технические компоненты и инструменты

| Термин | Описание |
| :--- | :--- |
| **PostgreSQL** | Основная реляционная система управления базами данных. В контексте Auth Service используется для долговременного (персистентного) хранения истории сессий, контекстов и неизменяемых логов локального аудита (WORM). |
| **Redis** | In-memory хранилище структур данных. Используется как сверхбыстрый оперативный кэш для хранения `Phantom Tokens` (активных сессий), One-Time билетов и счетчиков Rate Limiting для минимизации задержки на уровне API Gateway (< 2мс). |
| **RabbitMQ** | Брокер сообщений. В платформе используется исключительно он (Kafka не используется). В контексте Auth Service служит для получения критически важных асинхронных сигналов от STEOS ID (например, команд на `Back-Channel Logout`). |

# Надежность, производительность и эксплуатация

| Термин | Описание |
| :--- | :--- |
| **Correlation ID (ID трассировки / Trace ID)** | Сквозной уникальный идентификатор, который Auth Service (как API Gateway) генерирует при входе HTTP-запроса от пользователя и пробрасывает через заголовки во все внутренние бизнес-микросервисы. Ключевой инструмент для распределенной отладки в Kibana/Jaeger. |
| **Rate Limiting (Ограничение частоты)** | Механизм защиты сервиса от перегрузки (DoS-атак) и брутфорса, жестко ограничивающий количество попыток логина или генерации одноразовых билетов с одного IP-адреса за единицу времени. |
| **TTL (Time to Live)** | Время жизни данных в кэше. Критически важный параметр для Redis. Например, TTL для One-Time билетов составляет 15 секунд, после чего они автоматически стираются базой данных, предотвращая ее переполнение. |
