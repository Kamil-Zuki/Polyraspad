## Введение

Настоящий документ определяет и описывает полный набор функциональных возможностей (сервисных требований) для микросервиса **«Сервис Авторизации» (Authorization Service)**. 

Цель документа — предоставить максимально полную и однозначную спецификацию того, что сервис должен уметь делать, с точки зрения управления сессиями, интеграции с глобальным Identity Provider'ом (STEOS ID) и защиты платформы.

**Authorization Service** — это локальный Gatekeeper (привратник) и менеджер сессий для конкретной инсталляции платформы STEOS. В отличие от глобального STEOS ID, который выдает "паспорта", данный микросервис отвечает за **контекст и авторизацию**. Он доверяет токенам STEOS ID и использует их для того, чтобы пустить пользователя в конкретное Пространство (Workspace) и выдать ему локальные права, используя паттерн **Phantom Token** (выдача браузеру только `HttpOnly` Cookie вместо читаемого JWT).

Документ предназначен для разработчиков, QA-инженеров, системных аналитиков и архитекторов и является основой для проектирования, реализации и тестирования микросервиса.

# Группы возможностей

Ниже представлен перечень из 7 групп функциональных возможностей (сервисных требований) для микросервиса Authorization Service. Требования сгруппированы по логическим блокам для удобства навигации.

| Группа | Название и Описание |
| :--- | :--- |
| **Управление Сессиями и Контекстом (Session Management)** | Фундаментальное ядро. Замена уязвимых JWT-токенов на безопасные Phantom Tokens (Cookie), маршрутизация по Workspaces и управление состоянием. |
| **Инфраструктура OIDC и Интеграция (OIDC Infrastructure)** | Криптографический слой общения с глобальным STEOS ID, кэширование ключей (JWKS) и обработка асинхронных сигналов блокировки (Back-Channel Logout) через RabbitMQ. |
| **Защита Периметра и Гостевые Квоты (Security & Quotas)** | Слой локальной защиты инсталляции. Валидация Fingerprint'ов (Anti-Hijacking), управление гостевыми сессиями и временные файрволы (Local Bans). |
| **Локальный Аудит Доступа (Local Access Audit)** | Собственный WORM-журнал платформы. Фиксация входов, смены рабочих пространств, стартов сессий имперсонации и инъекция заголовков во внутренние сервисы. |
| **Локальная Авторизация и Политики Доступа (Access Control)** | Гранулярная проверка прав, step-up MFA, персональные API-ключи и корпоративные политики доступа на уровне Workspace. |
| **Межсервисная Аутентификация и Внутренние Токены (M2M & Internal Tokens)** | Контракты для выпуска и валидации короткоживущих внутренних JWT, когда downstream-системам недостаточно одного лишь Header Routing. |
| **Платформенные Контракты и Эксплуатация (Platform Contracts & Operations)** | Эксплуатационные и платформенные возможности сервиса: health-check, метрики, WebSocket backplane и идемпотентность мутирующих API-методов. |

## Описание возможностей

Ниже представлен детальный перечень сервисных требований (SR) для каждой группы. Подробное описание каждого требования находится в соответствующих вложенных документах.

### 1. Управление Сессиями и Контекстом (Session Management)

*Фундаментальное ядро для управления стейтом в браузере. Перевод глобальной идентичности в защищенные локальные сессии.*

| Код             | Название и Описание                                                                                                                                                                                                                           |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SR-AUTH-SM-01** | **Создание Phantom Token (HttpOnly Cookie):** Защита от XSS. Браузер получает случайный UUID, а все права и стейт хранятся на бэкенде (Redis + PostgreSQL).                                                                                     |
| **SR-AUTH-SM-02** | **Server-Side Context Routing:** Бесшовное переключение пользователя между рабочими пространствами (Workspaces) без перелогина и изменения Cookie.                                                                                            |
| **SR-AUTH-SM-03** | **Управление Гостевыми Сессиями:** Выделенная логика для `guest_sessions` с привязкой к аппаратному отпечатку браузера (Public Mode / Анонимный демо-доступ).                                                                               |
| **SR-AUTH-SM-04** | **Одноразовые билеты (One-Time Tickets):** Генерация эфемерных токенов (живут 15 секунд в Redis) для безопасного открытия WebSocket-соединений и прямого скачивания защищенных файлов (без передачи Cookie в параметрах URL).                 |
| **SR-AUTH-SM-05** | **Бесшовная Имперсонация (God Mode):** Вход техподдержки "под пользователем". Создание двойного контекста (`global_steos_id` + `impersonator_id`) для защиты компании от несанкционированных действий сотрудников в логах аудита.             |
| **SR-AUTH-SM-06** | **API Управления Локальными Сессиями:** Механизм просмотра списка активных сессий на конкретной инсталляции платформы и возможность их точечного отзыва (Revoke) пользователем.                                                               |
| **SR-AUTH-SM-07** | **Тихое продление (Silent Refresh):** Автоматический фоновый запрос свежего Access-токена у STEOS ID (используя зашифрованный локально `refresh_token`), предотвращающий внезапный разрыв сессии во время работы (сброс `expires_at`).      |
| **SR-AUTH-SM-08** | **Доверенные устройства (Trusted Devices):** Управление белым списком браузеров и устройств пользователя для снижения friction при повторных входах и риск-оценке подозрительных логинов.                                                     |
| **SR-AUTH-SM-09** | **Продление TTL активной сессии (Session Keep-Alive):** Sliding TTL для локальной Phantom-сессии при активной работе пользователя в интерфейсе без обязательного обращения к глобальному IdP на каждый запрос.                               |
| **SR-AUTH-SM-10** | **Горячее обновление контекста сессии:** Динамическая перезагрузка ролей, лицензий и бизнес-атрибутов во всех активных сессиях пользователя без принудительного перелогина.                                                                   |

REST-коды `SR-AUTH-OT-01..03` трактуются как контрактная декомпозиция `SR-AUTH-SM-04`, а `SR-AUTH-GQ-01..04` — как API-поверхность над `SR-AUTH-SM-03` и `SR-AUTH-SQ-02`, а не как отдельные канонические доменные блоки source of truth.

### 2. Инфраструктура OIDC и Интеграция (OIDC Infrastructure)

*Техническая прослойка, обеспечивающая криптографически безопасный диалог между локальной платформой и глобальным IdP.*

| Код               | Название и Описание                                                                                                                                                                                                                         |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AUTH-OI-01** | **OIDC Authorization Code Flow с PKCE:** Реализация защищенного потока аутентификации со строгой валидацией параметров `state` и `nonce` (для защиты от CSRF) при редиректах на STEOS ID и обратно.                                         |
| **SR-AUTH-OI-02** | **Кэширование и Валидация JWKS:** Фоновое скачивание публичных ключей STEOS ID для мгновенной in-memory проверки математических подписей (RSA) входящих JWT-токенов, без сетевых HTTP-запросов к STEOS ID при каждом логине пользователя.   |
| **SR-AUTH-OI-03** | **Just-In-Time (JIT) Onboarding:** Автоматическая оркестрация: если пользователь STEOS ID заходит на платформу впервые, Auth Service просит `Workspace Service` немедленно создать ему персональное пространство (Zero-Click Registration). |
| **SR-AUTH-OI-04** | **OIDC Back-Channel Logout (via RabbitMQ):** Слушатель брокера сообщений RabbitMQ. Если глобальный STEOS ID банит пользователя, локальный микросервис получает событие и за миллисекунды убивает все локальные сессии этого юзера в Redis.  |
| **SR-AUTH-OI-05** | **Аварийная ротация JWKS:** Принудительный сброс локального кэша ключей и немедленная синхронизация нового набора JWKS при подозрении на компрометацию ключевого материала STEOS ID.                                                        |
| **SR-AUTH-OI-06** | **Синхронизация Identity Claims:** Фоновое обновление локального профиля пользователя (`email`, `name`, глобальный статус) из STEOS ID при логине или по внешнему событию.                                                                  |
| **SR-AUTH-OI-08** | **Кросс-девайсная аутентификация:** Безопасный вход через QR/Intent-сценарии, когда аутентификация подтверждается на одном устройстве, а локальная сессия создается на другом.                                                              |
| **SR-AUTH-OI-09** | **Passwordless / Magic Link Login:** Беспарольный вход через одноразовые ссылки и exchange-коды с бесшовным завершением логина в целевом браузере.                                                                                          |

### 3. Защита Периметра и Гостевые Квоты (Security & Quotas)

*Слой локальной безопасности, защищающий инсталляцию от перегрузок и злоупотреблений.*

| Код             | Название и Описание                                                                                                                                                                                                                                    |
| :-------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SR-AUTH-SQ-01** | **Защита от угона сессии (Session Hijacking):** Строгая привязка `HttpOnly` Cookie к цифровому отпечатку устройства (Device Fingerprint). Смена IP/Браузера при живой Cookie приводит к немедленному аннулированию сессии (Revoke).                    |
| **SR-AUTH-SQ-02** | **Гостевые Лимиты (Guest Feature Quotas):** Синхронизация с `Platform Service` для строгого учета и ограничения потребления платных фич платформы анонимными пользователями (например, "3 генерации ИИ бесплатно").                                    |
| **SR-AUTH-SQ-03** | **Локальная блокировка (Local Firewall/Ban):** Динамический реестр временно заблокированных IP-адресов или Fingerprint-ов на уровне платформы (защита от парсинга публичных страниц). Срабатывает до того, как запрос дойдет до глобального STEOS ID.|
| **SR-AUTH-SQ-04** | **Rate Limiting & API Throttling:** Ограничение количества попыток инициализации OIDC-потока, старта гостевых сессий или генерации One-Time билетов с одного IP в единицу времени.                                                                     |
| **SR-AUTH-SQ-05** | **Снятие локальной блокировки (Unban):** Контролируемый разбан IP-адреса, подсети или Device Fingerprint администратором безопасности с обязательной причиной и аудитом действия.                                                                 |
| **SR-AUTH-SQ-06** | **Репортинг подозрительной активности:** Внутренний механизм приема сигналов от бизнес-сервисов о брутфорсе, мошенничестве или аномальном поведении с последующим throttling, баном или эскалацией.                                                |
| **SR-AUTH-SQ-07** | **Алерты безопасности и обработка инцидентов:** Формирование, выдача и lifecycle-обработка локальных предупреждений ИБ для администраторов платформы и SOC-процессов.                                                                            |

### 4. Локальный Аудит Доступа (Local Access Audit)

*Журнал безопасности, фиксирующий факты перемещения пользователей внутри платформы и прокидывающий контекст во внутренние сервисы.*

| Код             | Название и Описание                                                                                                                                                                                                                                    |
| :-------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SR-AUTH-LA-01** | **Журнал Локального Доступа (WORM):** Регистрация только платформенных событий: успешный вход, смена Workspace, старт имперсонации, срабатывание Back-Channel Logout. Пишется в таблицу `access_audit_logs` (Append-Only).                           |
| **SR-AUTH-LA-02** | **Категоризация Причин Блокировок:** Использование стандартизированного справочника `local_ban_reasons` (например, `GUEST_QUOTA_ABUSE`, `MALICIOUS_PAYLOAD`) для аналитики инцидентов и локализации сообщений об ошибках в UI.                       |
| **SR-AUTH-LA-03** | **Инъекция Трассировки в Downstream (Header Routing):** Концепция Zero Trust. Auth Service "снимает" Cookie, извлекает стейт из Redis и отправляет во внутренние бизнес-микросервисы (Tasks, CRM) только доверенные HTTP-заголовки (`X-Workspace-Id`, `X-Global-Actor-Id`). |
| **SR-AUTH-LA-04** | **Потоковая передача WORM-аудита в SIEM:** Асинхронная трансляция новых событий локального аудита во внешние системы мониторинга и расследования инцидентов.                                                                                     |
| **SR-AUTH-LA-05** | **Экспорт архива аудита:** Асинхронная подготовка и выдача архивов журнала доступа за период для комплаенса, регуляторных проверок и внутренних расследований.                                                                                 |
| **SR-AUTH-LA-06** | **Детализация события аудита:** Получение расширенного макроконтекста конкретного инцидента (`before/after`, actor, trace, reason) без изменения WORM-природы исходной записи.                                                                  |
| **SR-AUTH-LA-07** | **Агрегированная аналитика доступа:** Получение сводных показателей по активным сессиям, блокировкам, гостевым квотам и событиям безопасности для административных панелей и аналитики.                                                        |

### 5. Локальная Авторизация и Политики Доступа (Access Control)

*Гранулярный слой принятия решений о доступе, который дополняет голый факт наличия сессии правилами бизнеса, MFA и корпоративными ограничениями.*

| Код               | Название и Описание                                                                                                                                                                              |
| :---------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SR-AUTH-AC-01** | **Гранулярная проверка прав (Permission Check):** Централизованная ABAC/RBAC-проверка права пользователя или сервиса на конкретное действие над ресурсом для UI, BFF и внутренних микросервисов. |
| **SR-AUTH-AC-02** | **Step-Up MFA для высокорисковых действий:** Инициация и проверка дополнительного фактора (TOTP / Push / device approval) перед критичными операциями внутри уже активной сессии.                |
| **SR-AUTH-AC-04** | **Персональные API-ключи (PAT):** Выпуск, просмотр и отзыв персональных ключей доступа пользователя для CLI, интеграций и автоматизации.                                                         |
| **SR-AUTH-AC-05** | **Geo-Policies и IP Whitelisting Workspace:** Настройка политик допустимых регионов, сетей и источников входа для корпоративных пространств.                                                     |

### 6. Межсервисная Аутентификация и Внутренние Токены (M2M & Internal Tokens)

*Криптографические контракты для сценариев, где внутренним или legacy-системам требуется математически проверяемый JWT, а не только доверенные заголовки от шлюза.*

| Код             | Название и Описание                                                                                                                                                                                                                           |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SR-AUTH-M2M-01** | **Валидация межсервисных токенов:** Проверка внутренних M2M JWT для фоновых процессов, интеграционных шлюзов и сервисов, работающих вне прямого HTTP Header Routing.                                                                       |
| **SR-AUTH-M2M-02** | **Выпуск внутренних JWT-токенов:** Обмен локального сессионного контекста на короткоживущий подписанный токен для legacy- и внешних доверенных систем.                                                                                    |

### 7. Платформенные Контракты и Эксплуатация (Platform Contracts & Operations)

*Поддерживающие возможности, необходимые для безопасной эксплуатации сервиса, прозрачной диагностики и корректной работы распределенного real-time контура.*

| Код             | Название и Описание                                                                                                                                                                                                                           |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SR-AUTH-MH-01** | **Health Checks сервиса:** Эндпоинты liveness/readiness для проверки процесса, связности с Redis/PostgreSQL и готовности принимать трафик.                                                                                                 |
| **SR-AUTH-MH-02** | **Экспорт метрик и телеметрии:** Публикация метрик производительности, валидации токенов, rate-limit и безопасности для Prometheus/Alerting.                                                                                               |
| **SR-AUTH-WS-01** | **WebSocket Backplane между репликами:** Синхронизация real-time событий между несколькими подами Authorization Service; примеры имён: `session_revoked`, `context_updated`, `mfa_push_approved` (исчерпывающий перечень событий и полей — в документации WebSocket API, папка `Методы API/Socket`). |
| **SR-AUTH-REST-01** | **Idempotency Keys для мутирующих REST-методов:** Защита API от повторных списаний, двойного merge гостя или дублированного выпуска ключей при сетевых ретраях клиента.                                                                  |
