# Введение

Настоящий документ содержит описание методов API и протоколов взаимодействия с глобальным провайдером идентичности (STEOS ID), а также с внутренними микросервисами платформы, используемыми микросервисом **Authorization Service**.

Цель данных интеграций — обеспечить выполнение критических требований по безопасной аутентификации (OIDC Flow) и валидации ключей подписи (**SR-AUTH-OI-01**, **SR-AUTH-OI-02**), автоматическому онбордингу новых пользователей (**SR-AUTH-OI-03**), асинхронной терминации сессий при глобальных блокировках (**SR-AUTH-OI-04**), проверке прав доступа при маршрутизации контекста (**SR-AUTH-SM-02**) и конвертации гостевых ресурсов в постоянные (**SR-AUTH-SM-03**).

Документ предназначен для разработчиков, инженеров по безопасности и команды эксплуатации (DevOps). Документ разработан на основе анализа функциональных требований (SR-AUTH-xxx) и архитектурных решений (КАР-xxx) и описывает как внешние (IdP), так и внутренние межсервисные зависимости, необходимые для функционирования локального контура авторизации.

# 1. Список внутренних и внешних интеграций

Сводная таблица всех зависимостей Authorization Service, сгруппированная по бизнес-задачам и протоколам.

| Интеграция | Код требования | Назначение |
| :--- | :--- | :--- |
| **STEOS ID (HTTP/REST)** | SR-AUTH-OI-01 | Выполнение OIDC Authorization Code Flow (обмен кода на токены через `/token`). |
| **STEOS ID (HTTP/REST)** | SR-AUTH-OI-02 | Фоновое скачивание публичных ключей (JWKS) с эндпоинта `/.well-known/jwks.json` для in-memory валидации. |
| **STEOS ID (HTTP/REST)** | SR-AUTH-SM-07 | S2S-вызов для тихого продления (Silent Refresh) сессий с использованием `refresh_token`. |
| **STEOS ID (RabbitMQ)** | SR-AUTH-OI-04 | Прослушивание событий о блокировках, смене паролей и глобальном выходе для мгновенного Back-Channel Logout. |
| **Workspace Service (gRPC)** | SR-AUTH-SM-02 | Синхронная проверка прав доступа пользователя к запрашиваемому Пространству при смене контекста. |
| **Workspace Service (gRPC)** | SR-AUTH-OI-03 | Синхронный запрос на создание персонального Пространства (Just-In-Time Onboarding) при первом входе пользователя на платформу. |
| **Внутренние микросервисы (RabbitMQ)** | SR-AUTH-SM-03 | Отправка броадкаст-события `platform.auth.guest_merged` для передачи гостевых ресурсов (задач, файлов) в новый авторизованный аккаунт. |
