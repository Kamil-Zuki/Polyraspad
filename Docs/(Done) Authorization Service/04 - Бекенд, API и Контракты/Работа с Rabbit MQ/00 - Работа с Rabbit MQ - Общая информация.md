# Введение

Настоящий документ содержит описание механизмов асинхронного взаимодействия микросервиса **Authorization Service** через брокер сообщений RabbitMQ. 

В Enterprise-архитектуре (Event-Driven Architecture) RabbitMQ выполняет роль связующего звена (Message Bus), позволяя Authorization Service асинхронно реагировать на изменения в глобальном провайдере идентичности STEOS ID (**SR-AUTH-OI-04**, **SR-AUTH-OI-06**), рассылать глобальные броадкасты для инвалидации кэшей в других сервисах (**SR-AUTH-OI-04**, **SR-AUTH-SM-02**) и оркестрировать выполнение тяжелых фоновых задач по комплаенсу (**SR-AUTH-LA-05**).

Цель документа — определить регламент работы с очередями, обменниками (Exchanges/Topics) и структурами сообщений для архитекторов и инженеров. Документ разработан на основе функциональных требований к безопасности Платформы.

# 1. Группы событий и задач

Ниже представлена сводная информация по всем группам асинхронных операций, обрабатываемых через RabbitMQ. Каждая группа отвечает за свою область ответственности.

| Группа | Описание |
| :--- | :--- |
| **Синхронизация OIDC и Федерация (OIDC & Federation)** | Прием вебхуков и событий от глобального провайдера STEOS ID (IdP) для синхронизации состояний. |
| **Аудит и Комплаенс (Audit & Compliance Jobs)** | Очереди для тяжелых фоновых задач (выгрузка WORM-архивов логов) и потоковая передача (Stream) в SIEM. |
| **Глобальное управление сессиями (Global Session Events)** | Публикация броадкаст-событий для других микросервисов Платформы, чтобы они очистили свои внутренние кэши. |
| **Гостевые сессии и Квоты (Guest & Quota Events)** | Асинхронная миграция данных при конвертации гостя в полноценного пользователя и списание лимитов. |

# 2. Синхронизация OIDC и Федерация

Данная группа событий позволяет локальному Authorization Service всегда иметь актуальные данные о пользователях (Claims) и криптографических ключах, не прибегая к постоянному HTTP Polling'у.

| Метод (SR) | Тип операции | Очередь / Топик | Описание |
| :--- | :--- | :--- | :--- |
| SR-AUTH-OI-04 | Consume | `steosid:events:backchannel-logout` | (Topic) Потребление сигнала о смене пароля или блокировке в STEOS ID для отзыва локальных сессий. |
| SR-AUTH-OI-06 | Consume | `steosid:events:user-updated` | (Topic) Оповещение об изменении профиля пользователя в IdP (смена Email/Имени). |
| SR-AUTH-OI-05 | Consume | `steosid:events:jwks-rotated` | (Fanout) Критический сигнал об аварийной ротации ключей STEOS ID для сброса In-Memory кэшей. |

# 3. Аудит и Комплаенс

Эта группа управляет очередями фоновых воркеров (Background Workers), защищая REST API от таймаутов при формировании тяжелых выгрузок, а также обеспечивает интеграцию с системами ИБ.

| Метод (SR) | Тип операции | Очередь / Топик | Описание |
| :--- | :--- | :--- | :--- |
| SR-AUTH-LA-05 | Publish | `auth:tasks:audit-export` | Постановка задачи на сборку ZIP-архива WORM-логов за указанный период. |
| SR-AUTH-LA-05 | Consume | `auth:tasks:audit-export` | Обработка задачи фоновым воркером (генерация CSV, загрузка в S3, вызов WSS-события об успехе). |
| SR-AUTH-LA-04 | Publish | `auth:events:audit-stream` | (Topic) Непрерывная публикация каждого записанного WORM-события для чтения SIEM-системами. |

# 4. Глобальное управление сессиями

Поскольку Платформа работает по архитектуре микросервисов, многие бизнес-сервисы (Storage, Tasks) могут кратковременно кэшировать у себя информацию о правах. Authorization Service публикует события в этот Exchange, чтобы заставить их сбросить кэш.

| Метод (SR) | Тип операции | Очередь / Топик | Описание |
| :--- | :--- | :--- | :--- |
| SR-AUTH-OI-04 | Publish | `platform:events:global-logout` | (Fanout) Широковещательное оповещение всех сервисов: "Пользователь X полностью разлогинен". Сервисы должны разорвать WSS-соединения и очистить кэш. |
| SR-AUTH-SM-02 | Publish | `platform:events:context-switched`| (Topic) Сигнал о том, что пользователь принудительно переведен в другой Workspace. |
| SR-AUTH-SM-07 | Publish | `platform:events:roles-updated` | (Topic) Сигнал об изменении RBAC-ролей пользователя (например, оплачена подписка). |

# 5. Гостевые сессии и Квоты

События для реализации механизма бесшовного онбординга (Seamless Onboarding) и интеграции с Биллингом.

| Метод (SR) | Тип операции | Очередь / Топик | Описание |
| :--- | :--- | :--- | :--- |
| SR-AUTH-GQ-04 | Publish | `platform:events:guest-merged` | Важнейшее событие. Сигнал бизнес-сервисам: "Гость X теперь стал пользователем Y. Перенесите все его черновики и файлы". |
| SR-AUTH-GQ-02 | Publish | `platform:events:quota-consumed` | (Опционально) Асинхронная отправка данных о потреблении демо-ресурсов в аналитическое хранилище или Billing Service. |
