# Введение

Данная группа REST API методов предназначена для офицеров безопасности (SecOps), инженеров поддержки и администраторов рабочих пространств. Она реализует концепцию Enterprise-наблюдаемости (Observability), позволяя выгружать иммутабельные логи (WORM) для комплаенса, обрабатывать инциденты безопасности, управлять локальным фаерволом (Fail2Ban) и запускать защищенный режим имперсонации (God Mode).

# 1. Список эндпоинтов

Ниже приведен список методов REST API для просмотра журнала аудита, управления черными списками и анализа инцидентов.

| Код требования | Метод  | Эндпоинт                        | Назначение                                                           |
| :------------- | :----: | :------------------------------ | :------------------------------------------------------------------- |
| SR-AUTH-LA-01  |  GET   | `/audit/logs`                   | Пагинированный поиск по журналу WORM (по датам, Actor, IP).          |
| SR-AUTH-LA-06  |  GET   | `/audit/logs/{eventId}/details` | Извлечение детального макроконтекста (разница состояний).            |
| SR-AUTH-LA-05  |  POST  | `/audit/export-jobs`            | Запуск асинхронной задачи выгрузки архива логов (CSV/JSONL).         |
| SR-AUTH-LA-05  |  GET   | `/audit/export-jobs/{jobId}`    | Проверка статуса выгрузки архива (с выдачей Presigned URL).          |
| SR-AUTH-SQ-07  |  GET   | `/security/alerts`              | Получение списка подозрительных активностей (Bruteforce, Geo-Jump).  |
| SR-AUTH-SQ-07  |  POST  | `/security/alerts/{id}/resolve` | Пометка алерта обработанным (True Positive / False Positive).        |
| SR-AUTH-SQ-03  |  GET   | `/security/blocklist`           | Просмотр текущего черного списка Local Firewall (IP / Fingerprints). |
| SR-AUTH-SQ-03  |  POST  | `/security/blocklist`           | Ручное добавление IP/подсети или Fingerprint в бан (Fail2Ban).       |
| SR-AUTH-SQ-05  | DELETE | `/security/blocklist/{target}`  | Снятие блокировки (разбан) субъекта.                                 |
| SR-AUTH-SM-05  |  POST  | `/impersonation/start`          | Инициализация режима "God Mode" для саппорта по номеру тикета.       |
| SR-AUTH-SM-05  |  POST  | `/impersonation/stop`           | Корректное завершение сессии имперсонации.                           |

# SR-AUTH-LA-01: Поиск по WORM-журналу: Audit Logs

## Общая информация

Эндпоинт для административной панели Платформы. Позволяет секьюрити-офицерам или владельцам Workspace фильтровать записи в таблице `audit_logs` (база данных PostgreSQL или ElasticSearch). Так как логи иммутабельны (Write-Once Read-Many), этот метод поддерживает только чтение. 

| Тип метода               | GET                                        |
| :----------------------- | :----------------------------------------- |
| **DTO запроса**          | AuditLogQueryDto (в виде Query-параметров) |
| **DTO успешного ответа** | PaginatedResponseDto<AuditLogEventDto>     |

## Параметры URL

| Название | Тип | Описание |
| :--- | :--- | :--- |
| `actor_id` | `string` | Опционально. Фильтр логов конкретного пользователя. |
| `target_id`| `string` | Опционально. Фильтр по ресурсу (например, конкретный API-ключ или Workspace). |
| `event_type`| `string` | Опционально. Тип события, например `SESSION_REVOKED` или `LOGIN_FAILED`. |
| `ip_address`| `string` | Опционально. Поиск инцидентов по IP-адресу инициатора. |
| `limit` | `int` | Лимит выборки (по умолчанию 50, максимум 1000). |
| `offset` | `int` | Сдвиг для пагинации. |

## Логика обработки запроса

*   BFF проверяет права администратора/SecOps и маппит query-параметры в `AuditLogQueryDto`.
*   BFF вызывает gRPC [`QueryAccessLogs`](../gRPC/05%20-%20Аудит%20доступа%20и%20Аналитика%20(Audit%20&%20Analytics).md#grpc-QueryAccessLogs).
*   Результат пагинируется и отдаётся как `PaginatedResponseDto<AuditLogEventDto>`.

## Успешный ответ

```json
{
  "success": true,
  "data": {
    "items": [
      {
        "eventId": "evt_9982",
        "timestamp": "2026-03-25T14:10:00Z",
        "actorId": "usr_alpha",
        "eventType": "WORKSPACE_SWITCHED",
        "ipAddress": "192.168.1.1",
        "severity": "INFO"
      }
    ],
    "totalCount": 1
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **400 Bad Request** | Неверный формат дат или запрошенный `limit` превышает 1000 строк. |
| **403 Forbidden** | Пользователь не имеет прав на просмотр логов безопасности платформы. |

# SR-AUTH-LA-06: Макроконтекст инцидента: Log Details

## Общая информация

При просмотре логов администратору часто нужно увидеть "что конкретно изменилось" (состояние ДО и ПОСЛЕ). Поскольку списочный метод (`/audit/logs`) не возвращает тяжелые JSONB-пайлоады для экономии трафика, этот метод служит для точечной подгрузки деталей конкретного события.

| Тип метода | GET |
| :--- | :--- |
| **DTO запроса** | N/A |
| **DTO успешного ответа** | AuditMacroContextDto |

## Параметры URL

| Название | Тип | Описание |
| :--- | :--- | :--- |
| `eventId` | `string` | Уникальный ID события в таблице аудита. |

## Логика обработки запроса

*   BFF проверяет права и передаёт `eventId` в Auth.
*   BFF вызывает gRPC [`GetAuditLogDetails`](../gRPC/05%20-%20Аудит%20доступа%20и%20Аналитика%20(Audit%20&%20Analytics).md#grpc-GetAuditLogDetails).
*   Ответ маппится в `AuditMacroContextDto`.

## Успешный ответ

```json
{
  "success": true,
  "data": {
    "eventId": "evt_9982",
    "previousState": {
      "roles": ["member"]
    },
    "newState": {
      "roles": ["member", "admin"]
    },
    "triggerReason": "Promotion via Admin Panel"
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **404 Not Found** | Запись не найдена (или нет доступа из данного Workspace). |

# SR-AUTH-LA-05: Асинхронный экспорт: Export Jobs

## Общая информация

Для целей регуляторного комплаенса (GDPR, SOC2) компании обязаны хранить и предоставлять выгрузки логов безопасности за длительные периоды (например, "Весь 2025 год"). Запрос на такую выгрузку миллионов строк не может быть выполнен синхронно (Тайм-аут HTTP), поэтому используется паттерн Asynchronous Job.

| Тип метода | POST / GET |
| :--- | :--- |
| **DTO запроса (POST)** | AuditLogQueryDto (добавляются `format` CSV/JSONL и период дат) |
| **DTO ответа (POST)** | SuccessResponseDto (с ID запущенной Job) |
| **DTO ответа (GET)** | FileDownloadUrlDto (статус + Presigned URL на скачивание) |

## Параметры URL

| Название | Тип | Описание |
| :--- | :--- | :--- |
| `jobId` | `string` | В методе `GET`: Идентификатор запущенной фоновой задачи экспорта. |

## Логика обработки запроса

*   **`POST`:** BFF валидирует период и формат экспорта, вызывает gRPC [`ExportAuditArchive`](../gRPC/05%20-%20Аудит%20доступа%20и%20Аналитика%20(Audit%20&%20Analytics).md#grpc-ExportAuditArchive); возвращается `jobId`.
*   **`GET`:** BFF вызывает gRPC [`GetExportArchiveJobStatus`](../gRPC/05%20-%20Аудит%20доступа%20и%20Аналитика%20(Audit%20&%20Analytics).md#grpc-GetExportArchiveJobStatus) по `jobId`; при готовности — presigned URL и хэш файла.
*   Пока job в работе — **202** с `status=processing`.

## Успешный ответ (GET)

```json
{
  "success": true,
  "data": {
    "status": "COMPLETED",
    "url": "https://s3.steos.com/exports/audit_logs_2025.zip?Signature=...",
    "expiresIn": 3600,
    "fileHash": "sha256:d8b2..."
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **202 Accepted** | В методе GET: Задача всё еще выполняется (возвращается `status='processing'`). |
| **500 Internal Server Error** | Сбой загрузки файла в S3 Object Storage. |

# SR-AUTH-SQ-07: Инциденты и Алерты: Alerts & Resolve

## Общая информация

Authorization Service (и его локальный фаервол) генерирует алерты `SecurityAlertDto` при обнаружении подозрительной активности (например, 10 неправильных MFA-кодов подряд или резкая смена страны). Эти эндпоинты позволяют ИБ-офицеру просматривать и обрабатывать очередь инцидентов.

| Тип метода | GET / POST |
| :--- | :--- |
| **DTO запроса (GET)** | QueryAlertsRequest (фильтр по статусу `unresolved`) |
| **DTO ответа (GET)** | PaginatedResponseDto<SecurityAlertDto> |
| **DTO запроса (Resolve)**| ResolveAlertRequest (с резолюцией: `FALSE_POSITIVE` или `MITIGATED`) |

## Параметры URL

| Название | Тип | Описание |
| :--- | :--- | :--- |
| `id` | `string` | В методе `POST`: ID алерта для обработки (резолюции). |

## Логика обработки запроса

*   **`GET`:** BFF вызывает gRPC [`QuerySecurityAlerts`](../gRPC/05%20-%20Аудит%20доступа%20и%20Аналитика%20(Audit%20&%20Analytics).md#grpc-QuerySecurityAlerts) с фильтрами (например, только неразрешённые).
*   **`POST .../resolve`:** BFF вызывает gRPC [`ResolveSecurityAlert`](../gRPC/05%20-%20Аудит%20доступа%20и%20Аналитика%20(Audit%20&%20Analytics).md#grpc-ResolveSecurityAlert) с телом резолюции (`FALSE_POSITIVE`, `MITIGATED` и т.д.).

## Успешный ответ (Resolve)

```json
{
  "success": true,
  "message": "Инцидент SEC-889 успешно обработан (Ложное срабатывание)."
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **404 Not Found** | Алерт не найден или уже был разрешен другим администратором. |

# SR-AUTH-SQ-03: Управление Local Firewall: Blocklist

## Общая информация

Методы CRUD для работы с черным списком (Blocklist) Платформы. Позволяют SecOps мгновенно "отрезать" любой IP-адрес, подсеть (CIDR) или аппаратный Fingerprint устройства от Платформы (Fail2Ban) на заданное время (TTL) или навсегда.

| Тип метода | GET / POST / DELETE |
| :--- | :--- |
| **DTO запроса (POST)** | BlockListAddRequestDto (`target`, `type=IP/FP`, `ttlSeconds`, `reason`) |
| **DTO ответа (POST)** | SuccessResponseDto (с ID правила блокировки) |

## Параметры URL

| Название | Тип | Описание |
| :--- | :--- | :--- |
| `target` | `string` | В методе `DELETE`: Значение (IP, CIDR, Hash), которое нужно разбанить. |

## Логика обработки запроса

*   BFF проверяет права SecOps.
*   **`GET`:** gRPC [`QueryBlocklist`](../gRPC/04%20-%20Защита%20периметра%20и%20Гостевые%20квоты%20(Security%20&%20Quotas).md#grpc-QueryBlocklist) — текущие правила и записи.
*   **`POST`:** по типу цели — gRPC [`BanIpAddress`](../gRPC/04%20-%20Защита%20периметра%20и%20Гостевые%20квоты%20(Security%20&%20Quotas).md#grpc-BanIpAddress) или [`BanDeviceFingerprint`](../gRPC/04%20-%20Защита%20периметра%20и%20Гостевые%20квоты%20(Security%20&%20Quotas).md#grpc-BanDeviceFingerprint) (с TTL и причиной).
*   **`DELETE`:** gRPC [`UnbanSubject`](../gRPC/04%20-%20Защита%20периметра%20и%20Гостевые%20квоты%20(Security%20&%20Quotas).md#grpc-UnbanSubject) для `target` из path.

## Успешный ответ (POST)

```json
{
  "success": true,
  "message": "IP 192.168.1.100 успешно заблокирован на 3600 секунд. Сброшено 2 скомпрометированных сессий."
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **400 Bad Request** | Неверный формат IP-адреса, CIDR-маски или отсутствие обязательной причины блокировки. |
| **403 Forbidden** | Попытка заблокировать Whitelisted IP (внутреннюю подсеть Kubernetes или балансировщик Envoy). |

# SR-AUTH-SM-05: Имперсонация (God Mode): Start / Stop

## Общая информация

Специфический Enterprise-механизм для Tier-3 поддержки. Позволяет инженеру саппорта войти в Платформу от лица клиента (для воспроизведения бага), не запрашивая у клиента его пароль. Создает изолированный "Двойной контекст безопасности" (Sandboxed Session) с жестким логированием каждого клика саппорта.

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса (Start)** | ImpersonateRequestDto (`targetUserId`, `ticketId`) |
| **DTO ответа (Start)** | GodModeContextDto |
| **DTO запроса (Stop)** | ImpersonationStopRequestDto (текстовый отчет инженера) |

## Параметры URL

Параметры отсутствуют (авторизация по Cookie саппорта).

## Логика обработки запроса

*   **`POST /impersonation/start`:** BFF проверяет роль саппорта и тело (`targetUserId`, `ticketId`), вызывает gRPC [`StartImpersonation`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-StartImpersonation); возвращается `GodModeContextDto` с флагами песочницы.
*   **`POST /impersonation/stop`:** BFF вызывает gRPC [`StopImpersonation`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-StopImpersonation) с отчётом; сессия возвращается в обычный контекст.

## Успешный ответ (Start)

```json
{
  "success": true,
  "data": {
    "isImpersonated": true,
    "impersonatorId": "supp_102",
    "targetUserId": "usr_9982",
    "ticketId": "JIRA-4822",
    "sandboxRoles": ["read_only_admin"]
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **400 Bad Request** | Не передан обязательный обосновывающий номер тикета `ticketId`. |
| **403 Forbidden** | Саппорт не имеет прав на режим имперсонации или пытается войти к другому сотруднику саппорта. |
