# Введение

Настоящий документ задаёт **внешний HTTP-контракт** (пути и семантику методов), через который клиенты работают с возможностями **Authorization Service**. Сама доменная логика авторизации, сессий, квот, PAT и аудита реализуется в микросервисе **Authorization Service** и доступна вызывающим сторонам прежде всего по **gRPC**.

**Размещение REST:** публичные HTTP-маршруты и **контроллеры REST** не обязаны (и по целевой архитектуре **не** должны) жить в процессе микросервиса Authorization Service. Их реализует **API Gateway — агрегатор** (BFF / Edge API): он принимает запросы от SPA, админок и оркестраторов, выполняет маппинг **REST → gRPC** (или внутренний HTTP, где это оговорено) и проксирует вызовы в Authorization Service. Ниже перечисленные пути — это **контракт поверхности API платформы**, а не утверждение, что каждый маршрут реализован как отдельный контроллер внутри процесса Auth.

# 1. Группы методов REST API

Ниже представлена сводная таблица всех логических групп методов REST API в **контракте платформы** (как правило, реализуемых **API Gateway — агрегатором** с проксированием в Authorization Service по gRPC). Каждая группа отвечает за свой набор бизнес-функций в области аутентификации, сессий и безопасности Enterprise-уровня.

| Группа | Описание |
| :--- | :--- |
| **Аутентификация и OIDC (Auth & OIDC)** | Точки входа для начала OIDC Authorization Code Flow, обработки коллбэков, фонового обновления (Silent Refresh) и получения вебхуков глобального логаута от STEOS ID. |
| **Управление сессиями и Доверенными устройствами (Session & Device Management)** | Получение текущего бизнес-контекста, отзыв подозрительных сессий, переключение активного Workspace и управление списком "знакомых" (Trusted) устройств. |
| **Гостевые сессии и квоты (Guest Sessions & Quotas)** | Выделение демо-лимитов анонимным пользователям и последующая конвертация накопленных гостем данных при его успешной регистрации. |
| **Управление доступом и API-ключами (Access & API Keys)** | Выпуск долгоживущих токенов (PAT) для разработчиков, проверка эффективных прав пользователя для UI и настройка ограничений (например, IP Whitelisting) для Workspace. |
| **Одноразовые билеты (One-Time Tickets)** | Генерация краткосрочных "burn-after-read" токенов для безопасного скачивания файлов или установки WebSocket соединений. |
| **Аудит доступа, Риски и Безопасность (Audit, Risk & Security)** | Просмотр иммутабельного WORM-журнала, резолюция инцидентов ИБ, управление черными списками (Fail2Ban) и режим имперсонации (God Mode). |
| **Межсервисные процессы и Здоровье (Internal & Health)** | Технические эндпоинты для выпуска M2M JWT, синхронизации Claims, отдачи публичных ключей (JWKS) и проверки состояния (Health checks). |

# 2. Аутентификация и OIDC (Auth & OIDC)

Данная группа обеспечивает сопряжение локального микросервиса авторизации с глобальным провайдером STEOS ID и установку защищенной Phantom Cookie в браузере клиента.

| Код требования | Метод | Эндпоинт                 | Назначение                                                                                              |
| :------------- | :---: | :----------------------- | :------------------------------------------------------------------------------------------------------ |
| SR-AUTH-OI-01  |  GET  | `/auth/oidc/login`       | Инициализация OIDC-протокола (формирование URL и редирект в STEOS ID).                                  |
| SR-AUTH-OI-01  |  GET  | `/auth/oidc/callback`    | Обработка `code` и `state`, обмен на токены, установка HTTPOnly Phantom Cookie.                         |
| SR-AUTH-SM-06  | POST  | `/auth/logout`           | Уничтожение локальной сессии и (опционально) отправка команды на логаут в IdP.                          |
| SR-AUTH-OI-04  | POST  | `/auth/oidc/backchannel` | Webhook для STEOS ID: асинхронный отзыв сессии при смене пароля.                                        |
| SR-AUTH-SM-07  | POST  | `/auth/refresh`          | Тихое обновление OIDC-токенов в фоне (Silent Refresh) по истечению срока жизни Access Token.            |
| SR-AUTH-AC-02  | POST  | `/auth/mfa/challenge`    | Инициация локального Step-up MFA для подтверждения высокорискового действия (например, смены биллинга). |
| SR-AUTH-AC-02  | POST  | `/auth/mfa/verify`       | Проверка MFA-кода (TOTP) и выдача временного разрешения (Scope).                                        |

# 3. Управление сессиями и Доверенными устройствами (Session & Device Management)

Эндпоинты для SPA-клиентов и пользовательского раздела "Безопасность". Позволяют клиенту узнать, "кто он", в каком рабочем пространстве находится, и прервать подозрительные сессии.

| Код требования | Метод | Эндпоинт | Назначение |
| :--- | :---: | :--- | :--- |
| SR-AUTH-SM-06 | GET | `/sessions/me` | Получение полного контекста текущей сессии (`SessionContextDto`), ролей и активного Workspace. |
| SR-AUTH-SM-06 | GET | `/sessions` | Получение списка всех активных сессий пользователя (с гео-данными и User-Agent). |
| SR-AUTH-SM-06 | DELETE | `/sessions/{sessionId}` | Принудительный отзыв конкретной сессии (разлогинить старый телефон). |
| SR-AUTH-SM-06 | DELETE | `/sessions` | Логаут со всех остальных устройств (кроме текущего). |
| SR-AUTH-SM-02 | POST | `/sessions/workspace-switch`| Переключение активного корпоративного пространства (Workspace) пользователя. |
| SR-AUTH-SM-09 | POST | `/sessions/keep-alive` | Продление TTL (Time-To-Live) сессии при активных действиях пользователя в SPA. |
| SR-AUTH-SM-08 | GET | `/devices/trusted` | Получение списка устройств, помеченных пользователем как "Доверенные". |
| SR-AUTH-SM-08 | POST | `/devices/trusted/remember` | Добавление аппаратного отпечатка текущего устройства в белый список пользователя (упрощение Risk Score). |
| SR-AUTH-SM-08 | DELETE | `/devices/trusted/{id}` | Удаление устройства из доверенных (требует повторной верификации при логине). |

# 4. Гостевые сессии и квоты (Guest Sessions & Quotas)

Эндпоинты, реализующие концепцию Seamless Onboarding (бесшовный демо-доступ), позволяя пользователям взаимодействовать с платформой до регистрации.

| Код требования | Метод | Эндпоинт | Назначение |
| :--- | :---: | :--- | :--- |
| SR-AUTH-GQ-01 | POST | `/guests/init` | Создание гостевой сессии (Cookie) и выделение начальной квоты (например, "3 генерации"). |
| SR-AUTH-GQ-02 | GET | `/guests/status` | Получение текущего состояния квот (сколько лимитов осталось у гостя). |
| SR-AUTH-GQ-03 | POST | `/guests/convert` | Конвертация гостя в полноценного пользователя (вызывается после успешного OIDC Callback). |
| SR-AUTH-GQ-04 | POST | `/guests/merge` | Асинхронное слияние данных (например, созданных черновиков) из гостевого ID в постоянный User ID. |

# 5. Управление доступом и API-ключами (Access & API Keys)

Enterprise-блок (Developer API) для управления программным доступом к Платформе, динамическим UI-отображением и локальными политиками периметра Workspace.

| Код требования | Метод | Эндпоинт | Назначение |
| :--- | :---: | :--- | :--- |
| SR-AUTH-AC-04 | POST | `/access/pat` | Создание персонального API-ключа (Personal Access Token) для разработчиков (CLI, CI/CD). |
| SR-AUTH-AC-04 | GET | `/access/pat` | Получение списка всех выпущенных PAT пользователя (с маскированными ключами). |
| SR-AUTH-AC-04 | DELETE | `/access/pat/{keyId}` | Мгновенный отзыв (Revocation) персонального API-ключа. |
| SR-AUTH-AC-01 | POST | `/access/permissions/check` | Универсальная проверка "Имею ли я право X на ресурс Y?" для динамического скрытия кнопок в UI фронтенда. |
| SR-AUTH-AC-05 | GET | `/workspaces/{wsId}/geo-policies`| Получение настроек Geo-Fencing / IP Whitelisting (откуда разрешен вход сотрудникам). |
| SR-AUTH-AC-05 | PUT | `/workspaces/{wsId}/geo-policies`| Настройка белого списка IP-адресов или запрещенных регионов (VPN) для конкретного Workspace (доступно только Owner). |

# 6. Одноразовые билеты (One-Time Tickets)

Интерфейсы для генерации короткоживущих артефактов, используемых для преодоления технических ограничений протоколов (например, невозможность передать Header в `<img>` тег или WebSocket `onopen`).

| Код требования | Метод | Эндпоинт                | Назначение                                                                                      |
| :------------- | :---: | :---------------------- | :---------------------------------------------------------------------------------------------- |
| SR-AUTH-OT-01  | POST  | `/tickets`              | Генерация одноразового билета с указанием намерения (Intent) и ресурса (Resource ID).           |
| SR-AUTH-OT-02  | POST  | `/tickets/validate`     | (Для внешних шлюзов без gRPC) HTTP-метод проверки и "гашения" билета с возвратом контекста.     |
| SR-AUTH-OT-03  | POST  | `/tickets/download-url` | Утилитарный метод: быстрая генерация готового URL (с билетом) для скачивания защищенного файла. |
| SR-AUTH-OT-03  | POST  | `/tickets/ws-url`       | Утилитарный метод: генерация WSS-ссылки с билетом для инициализации WebSocket-туннеля.          |

# 7. Аудит доступа, Риски и Безопасность (Audit, Risk & Security)

Интерфейсы DevSecOps (ИБ-администраторов) для расследования инцидентов, управления локальным фаерволом (Fail2Ban) и регуляторного комплаенса.

| Код требования | Метод  | Эндпоинт                             | Назначение                                                                                            |
| :------------- | :----: | :----------------------------------- | :---------------------------------------------------------------------------------------------------- |
| SR-AUTH-LA-01  |  GET   | `/audit/logs`                        | Пагинированный поиск по иммутабельному журналу доступа (WORM) с фильтрацией (IP, Actor, Dates).       |
| SR-AUTH-LA-06  |  GET   | `/audit/logs/{eventId}/details`      | Извлечение детального макроконтекста (разница состояний Before/After) конкретного инцидента.          |
| SR-AUTH-LA-05  |  POST  | `/audit/export-jobs`                 | Запуск асинхронной задачи (Job) на выгрузку архива логов (CSV/JSONL) за период (GDPR/Compliance).     |
| SR-AUTH-LA-05  |  GET   | `/audit/export-jobs/{jobId}`         | Проверка статуса выгрузки архива логов и получение временной ссылки на скачивание (S3 Presigned URL). |
| SR-AUTH-SQ-07  |  GET   | `/security/alerts`                   | Получение списка активных предупреждений ИБ (например, "Обнаружен брутфорс" или "Suspicious IP").     |
| SR-AUTH-SQ-07  |  POST  | `/security/alerts/{alertId}/resolve` | Пометка алерта как обработанного (Resolve / False Positive).                                          |
| SR-AUTH-SQ-03  |  GET   | `/security/blocklist`                | Просмотр текущего черного списка Local Firewall (Fail2Ban: заблокированные IP и Fingerprints).        |
| SR-AUTH-SQ-03  |  POST  | `/security/blocklist`                | Ручное добавление IP-адреса, подсети (CIDR) или Fingerprint в черный список.                          |
| SR-AUTH-SQ-05  | DELETE | `/security/blocklist/{target}`       | Снятие блокировки (разбан) субъекта.                                                                  |
| SR-AUTH-SM-05  |  POST  | `/impersonation/start`               | Инициализация режима "God Mode" (вход в аккаунт клиента саппортом по номеру тикета).                  |
| SR-AUTH-SM-05  |  POST  | `/impersonation/stop`                | Корректное завершение сессии имперсонации (возврат в системный контекст).                             |

# 8. Межсервисные процессы и Здоровье (Internal & Health)

Служебная группа эндпоинтов, предназначенная для оркестраторов (Kubernetes), систем мониторинга (Prometheus) и внутреннего обмена техническими данными.

| Код требования | Метод | Эндпоинт | Назначение |
| :--- | :---: | :--- | :--- |
| SR-AUTH-M2M-02| POST | `/internal/token` | Обмен текущего Phantom Context на подписанный короткоживущий M2M JWT для внешних legacy-интеграций. |
| SR-AUTH-OI-02 | POST | `/internal/introspect` | (Внутренний) Проверка валидности любого выданного платформой JWT (в обход кэша). |
| SR-AUTH-OI-06 | POST | `/internal/sync-claims` | Webhook или ручной триггер для фонового скачивания обновленного профиля юзера из STEOS ID. |
| SR-AUTH-M2M-01 | GET | `/.well-known/jwks.json`| Публичный эндпоинт отдачи ключей (JWKS) **платформенных M2M** JWT, выданных Authorization Service (не путать с кэшем JWKS STEOS ID — **SR-AUTH-OI-02**, gRPC [`GetCachedJwks`](../gRPC/03%20-%20Интеграция%20OIDC%20и%20Внутренние%20токены%20(OIDC%20Infrastructure).md#grpc-GetCachedJwks)). |
| SR-AUTH-MH-01 | GET | `/health/live` | Проверка жизнеспособности (Liveness Probe). |
| SR-AUTH-MH-01 | GET | `/health/ready` | Проверка готовности (Readiness Probe, проверка коннектов к Redis/DB). |
| SR-AUTH-MH-02 | GET | `/metrics` | Экспорт Prometheus метрик (счетчики токенов, latency, rate limits). |
