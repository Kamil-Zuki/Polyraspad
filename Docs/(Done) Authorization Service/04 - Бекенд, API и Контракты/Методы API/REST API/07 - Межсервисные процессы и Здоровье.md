# Введение

Данная группа REST API методов предназначена для оркестраторов (Kubernetes), систем мониторинга (Prometheus, Grafana) и других микросервисов Платформы, которые по каким-либо причинам (Legacy, внешние DMZ) не могут использовать gRPC-протокол. 

Методы обеспечивают выдачу и интроспекцию M2M-токенов, синхронизацию профилей пользователей с глобальным провайдером STEOS ID, а также мониторинг состояния "здоровья" самого микросервиса Authorization Service.

# 1. Список эндпоинтов

Ниже приведен список служебных и межсервисных эндпоинтов REST API.

| Код требования | Метод | Эндпоинт | Назначение |
| :--- | :---: | :--- | :--- |
| SR-AUTH-M2M-02| POST | `/internal/token` | Обмен текущего Phantom Context на подписанный JWT (M2M) для legacy-интеграций. |
| SR-AUTH-OI-02 | POST | `/internal/introspect` | (Внутренний) Интроспекция: проверка статуса любого выданного токена (в обход кэша). |
| SR-AUTH-OI-06 | POST | `/internal/sync-claims` | Webhook для фонового обновления профиля юзера (имя, email) из STEOS ID. |
| SR-AUTH-M2M-01 | GET | `/.well-known/jwks.json`| Публичная отдача JWKS для проверки **платформенных M2M** JWT (не путать с кэшем JWKS STEOS ID — **SR-AUTH-OI-02**, gRPC [`GetCachedJwks`](../gRPC/03%20-%20Интеграция%20OIDC%20и%20Внутренние%20токены%20(OIDC%20Infrastructure).md#grpc-GetCachedJwks)). |
| SR-AUTH-MH-01 | GET | `/health/live` | Liveness Probe (проверка, что процесс не завис). |
| SR-AUTH-MH-01 | GET | `/health/ready` | Readiness Probe (проверка подключения к Redis и PostgreSQL). |
| SR-AUTH-MH-02 | GET | `/metrics` | Экспорт телеметрии (счетчики валидаций, latency, rate limits) для Prometheus. |

# SR-AUTH-M2M-02: Выпуск M2M JWT-токена: Internal Token

## Общая информация

Решает проблему интеграции со сторонними или устаревшими (legacy) системами, которые не понимают Header Routing (прокидывание заголовков от API Gateway) и требуют классический `Authorization: Bearer <JWT>`. Метод берет текущий контекст пользователя и запаковывает его в короткоживущий (1-5 минут) подписанный JWT, который можно передать "наружу".

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса** | TokenExchangeRequestDto (`audience`, `scopes`) |
| **DTO успешного ответа** | TokenExchangeResponseDto (`internal_jwt_token`, `expires_in`) |

## Параметры URL

Параметры отсутствуют (авторизация по Phantom Cookie).

## Логика обработки запроса

*   BFF извлекает контекст сессии из Cookie и тело с `audience` / `scopes`.
*   BFF вызывает gRPC [`ExchangeInternalToken`](../gRPC/03%20-%20Интеграция%20OIDC%20и%20Внутренние%20токены%20(OIDC%20Infrastructure).md#grpc-ExchangeInternalToken).
*   В ответе — `TokenExchangeResponseDto`.

## Успешный ответ

```json
{
  "success": true,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expiresIn": 300,
    "tokenType": "Bearer",
    "issuedFor": "external_billing_system"
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **403 Forbidden** | Вызывающий субъект не имеет прав на генерацию токена для запрошенной `Audience`. |

# SR-AUTH-OI-02: Интроспекция: Introspect

## Общая информация

Внутренний (Internal DMZ) эндпоинт, совместимый со стандартом RFC 7662 (OAuth 2.0 Token Introspection). Позволяет любому микросервису передать Authorization Service токен (OIDC, PAT или M2M JWT) и получить ответ о его валидности, сроке жизни и статусе отзыва (Revocation).

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса** | IntrospectRequestDto (Формат x-www-form-urlencoded или JSON: `token`, `token_type_hint`) |
| **DTO успешного ответа** | TokenIntrospectionResponseDto |

## Параметры URL

Параметры отсутствуют.

## Логика обработки запроса

*   BFF (или Auth напрямую) аутентифицирует вызывающий микросервис (M2M / Basic).
*   BFF передаёт тело с `token` и опционально `token_type_hint` в gRPC [`IntrospectToken`](../gRPC/03%20-%20Интеграция%20OIDC%20и%20Внутренние%20токены%20(OIDC%20Infrastructure).md#grpc-IntrospectToken).
*   Ответ приводится к полям RFC 7662 (`active`, `exp`, `sub`, …).

## Успешный ответ

*Внимание: согласно RFC, при недействительном токене HTTP-код всё равно 200 OK, но `active = false`.*

```json
{
  "active": true,
  "scope": "read write",
  "client_id": "app_backend",
  "username": "admin@steos.com",
  "exp": 1742918400,
  "sub": "usr_9982"
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **401 Unauthorized** | Микросервис не авторизован для вызова эндпоинта интроспекции (нужен Basic Auth или M2M). |

# SR-AUTH-OI-06: Синхронизация профиля: Sync Claims

## Общая информация

Webhook для получения обновлений от STEOS ID. Если пользователь меняет имя, аватарку или контактный email в глобальном хабе, STEOS ID асинхронно вызывает этот эндпоинт, чтобы Authorization Service актуализировал свои локальные кэши (и UI платформы сразу обновился).

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса** | Webhook payload (User ID, измененные Claims) |
| **DTO успешного ответа** | Пустой ответ 200 OK |

## Параметры URL

Параметры отсутствуют.

## Логика обработки запроса

*   BFF проверяет подпись/секрет webhook (HMAC или mTLS — по договорённости со STEOS ID).
*   BFF передаёт payload в gRPC [`SyncIdentityClaims`](../gRPC/03%20-%20Интеграция%20OIDC%20и%20Внутренние%20токены%20(OIDC%20Infrastructure).md#grpc-SyncIdentityClaims).
*   При успехе — **200 OK** без тела.

## Успешный ответ

HTTP 200 OK без тела.

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **403 Forbidden** | Неверная подпись HMAC (Webhook не от доверенного STEOS ID). |

# SR-AUTH-M2M-01: Отдача публичных ключей: JWKS Endpoint

## Общая информация

Стандартный эндпоинт (OIDC Discovery) для отдачи актуального JSON Web Key Set (публичных ключей), которым подписываются локальные M2M токены Платформы. Позволяет внутренним микросервисам (или Edge-роутеру) проверять подписи токенов локально, без сетевых вызовов (Zero-Hop Validation).

| Тип метода | GET |
| :--- | :--- |
| **DTO запроса** | N/A |
| **DTO успешного ответа** | Массив ключей `keys` (по стандарту RFC 7517) |

## Параметры URL

Параметры отсутствуют. Отвечает по фиксированному пути `/.well-known/jwks.json`.

## Логика обработки запроса

*   Обработчик читает актуальный набор публичных ключей из памяти/хранилища процесса Authorization Service (ротация при старте или по событию).
*   Отдельного unary gRPC под этот **GET** нет: ответ формируется как статический JSON по RFC 7517.
*   JWKS **платформенных M2M** JWT не путать с gRPC [`GetCachedJwks`](../gRPC/03%20-%20Интеграция%20OIDC%20и%20Внутренние%20токены%20(OIDC%20Infrastructure).md#grpc-GetCachedJwks) (JWKS **STEOS ID**).

## Успешный ответ

```json
{
  "keys": [
    {
      "kty": "RSA",
      "alg": "RS256",
      "use": "sig",
      "kid": "key_2026_03_alpha",
      "n": "0vx7agoebGcQSuuPi...",
      "e": "AQAB"
    }
  ]
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **500 Internal Server Error** | Ключевая пара не была сгенерирована при старте сервиса. |

# SR-AUTH-MH-01: Health Checks: Liveness & Readiness

## Общая информация

Технические эндпоинты для Kubernetes Probes. Обеспечивают автоматический перезапуск зависших Pod-ов и умную маршрутизацию трафика (Traffic Routing).

| Тип метода | GET |
| :--- | :--- |
| **DTO запроса** | N/A |
| **DTO успешного ответа** | JSON со статусом `UP` |

## Параметры URL

Параметры отсутствуют. Эндпоинты: `/health/live`, `/health/ready`.

## Логика обработки запроса

*   **`/health/live`:** быстрая проверка, что процесс отвечает (без обязательных зависимостей).
*   **`/health/ready`:** проверка подключений к Redis, PostgreSQL и др.; при сбое — **503**.
*   gRPC для проб **не используется** — это чистый HTTP для kubelet.

## Успешный ответ

```json
{
  "status": "UP",
  "components": {
    "redis": "UP",
    "postgres": "UP"
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **503 Service Unavailable** | В Readiness пробе: потеряно соединение с Redis или PostgreSQL. |

# SR-AUTH-MH-02: Экспорт метрик: Metrics

## Общая информация

Эндпоинт для сбора телеметрии (Scraping) сервером Prometheus. Предоставляет жизненно важные данные об активности системы безопасности в реальном времени.

| Тип метода | GET |
| :--- | :--- |
| **DTO запроса** | N/A |
| **DTO успешного ответа** | Текст в формате Prometheus (Plain Text) |

## Параметры URL

Параметры отсутствуют.

## Логика обработки запроса

*   Обработчик агрегирует счётчики и гистограммы из runtime (Prometheus client library).
*   Ответ — текст в формате exposition (`text/plain; version=0.0.4`); gRPC **не** используется (pull-модель Prometheus).

## Ключевые метрики

*   `auth_sessions_active_total` — Количество активных Phantom-сессий (Gauge).
*   `auth_token_validations_per_second` — Скорость проверок сессий в Ядре валидации (Rate).
*   `auth_blocklist_size` — Размер черного списка Local Firewall (Fail2Ban).
*   `auth_mfa_challenges_total` — Счетчик запросов на Step-Up MFA (попытки смены биллинга).
*   `auth_guest_conversions_total` — Воронка конверсии: успешные переходы Guests -> Users (Counter).
