# Введение

Данная группа REST API предназначена для работы с уже аутентифицированными пользователями (через Phantom Token). Эндпоинты обеспечивают доступ SPA-клиентов к своему авторизационному профилю, управлению несколькими параллельными сессиями (например, мобильное приложение и веб-браузер), а также управлению «Доверенными устройствами» (Trusted Devices), что позволяет снизить частоту проверок MFA.

# 1. Список эндпоинтов

Ниже приведен список методов REST API для клиентских SPA и мобильных приложений.

| Код требования | Метод | Эндпоинт | Назначение |
| :--- | :---: | :--- | :--- |
| SR-AUTH-SM-06 | GET | `/sessions/me` | Получение информации о текущем сеансе (Контекст). |
| SR-AUTH-SM-06 | GET | `/sessions` | Просмотр списка всех своих активных сессий. |
| SR-AUTH-SM-06 | DELETE | `/sessions/{sessionId}`| Принудительное завершение конкретной сессии (свой телефон/планшет). |
| SR-AUTH-SM-06 | DELETE | `/sessions` | Выйти со всех остальных устройств (Terminate Others). |
| SR-AUTH-SM-02 | POST | `/sessions/workspace-switch`| Переключение корпоративного пространства пользователя. |
| SR-AUTH-SM-09 | POST | `/sessions/keep-alive` | Фоновое продление TTL (Time-To-Live) в Redis. |
| SR-AUTH-SM-08 | GET | `/devices/trusted` | Просмотр списка доверенных устройств (запомненных). |
| SR-AUTH-SM-08 | POST | `/devices/trusted/remember` | Добавление текущего браузера в список доверенных. |
| SR-AUTH-SM-08 | DELETE | `/devices/trusted/{id}`| Отзыв доверия у устройства. |

# SR-AUTH-SM-06: Получение текущего контекста: Me

## Общая информация

Один из самых востребованных эндпоинтов для фронтенда. Сразу после загрузки SPA, клиент вызывает `/sessions/me` (отправляя Cookie), чтобы понять, авторизован ли пользователь, под каким Workspace он вошел, и какие роли (разрешения) ему доступны для отрисовки интерфейса.

| Тип метода | GET |
| :--- | :--- |
| **DTO запроса** | N/A |
| **DTO успешного ответа** | SessionContextDto |

## Параметры URL

Параметры отсутствуют.

## Логика обработки запроса

*   BFF извлекает Phantom Cookie из HTTP-запроса и определяет контекст вызова.
*   BFF вызывает gRPC [`GetSessionContext`](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md#grpc-GetSessionContext) (кэш сессии, при необходимости фолбэк в БД, маскирование полей для ответа клиенту).
*   Успешный ответ RPC маппится в JSON с `SessionContextDto` и возвращается с кодом **200 OK**.

## Успешный ответ

```json
{
  "success": true,
  "data": {
    "sessionId": "b3f...",
    "userId": "usr_9982",
    "activeWorkspaceId": "ws_alpha_1",
    "roles": ["admin", "billing_manager"],
    "isImpersonated": false
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **401 Unauthorized** | Сессия недействительна или Cookie не передана. |

# SR-AUTH-SM-06: Список сессий: List

## Общая информация

Метод для страницы "Безопасность -> Активные сеансы" в личном кабинете. Возвращает список устройств, с которых сейчас выполнен вход.

| Тип метода | GET |
| :--- | :--- |
| **DTO запроса** | N/A |
| **DTO успешного ответа** | SessionListResponseDto |

## Параметры URL

| Название | Тип | Описание |
| :--- | :--- | :--- |
| `limit` | `int` | Максимальное количество возвращаемых сессий (по умолчанию 10). |
| `offset` | `int` | Сдвиг для пагинации. |

## Логика обработки запроса

*   BFF проверяет аутентификацию по Cookie и передаёт параметры пагинации (`limit`, `offset`) в вызов Auth.
*   BFF вызывает gRPC [`ListActiveSessions`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-ListActiveSessions).
*   Ответ маппится в `SessionListResponseDto` и возвращается клиенту.

## Успешный ответ

```json
{
  "success": true,
  "data": {
    "sessions": [
      {
        "id": "ses_8821",
        "device": "Mac OS X / Chrome",
        "location": "Moscow, RU",
        "lastAccessed": "2026-03-25T14:10:00Z",
        "isCurrentSession": true
      },
      {
        "id": "ses_4419",
        "device": "iOS / Safari",
        "location": "Kazan, RU",
        "lastAccessed": "2026-03-24T09:00:00Z",
        "isCurrentSession": false
      }
    ],
    "totalCount": 2
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **401 Unauthorized** | Вызов неавторизован. |

# SR-AUTH-SM-06: Принудительное завершение конкретной сессии: Revoke

## Общая информация

Позволяет пользователю разлогинить свой телефон или компьютер, если он забыл это сделать или потерял устройство.

| Тип метода | DELETE |
| :--- | :--- |
| **DTO запроса** | RevokeSessionRequestDto |
| **DTO успешного ответа** | SuccessResponseDto |

## Параметры URL

| Название | Тип | Описание |
| :--- | :--- | :--- |
| `sessionId` | `string` | Идентификатор сессии (Path параметр), которую необходимо отозвать. |

## Логика обработки запроса

*   BFF определяет текущего пользователя по Cookie и передаёт в Auth целевой `sessionId` из path.
*   BFF вызывает gRPC [`RevokeSession`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-RevokeSession).
*   При успехе возвращается подтверждение в теле JSON (код **200**); при нарушении прав — **403**, при отсутствии сессии — **404**.

## Успешный ответ

```json
{
  "success": true,
  "message": "Сессия успешно завершена. Устройство отключено."
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **403 Forbidden** | Попытка удалить чужую сессию. |
| **404 Not Found** | Сессия не найдена или уже неактивна. |

# SR-AUTH-SM-06: Логаут остальных устройств: Terminate Others

## Общая информация

Кнопка "Выйти со всех остальных устройств" (Panic Button). Оставляет текущий браузер активным, но инвалидирует все прочие локальные сессии.

| Тип метода | DELETE |
| :--- | :--- |
| **DTO запроса** | N/A |
| **DTO успешного ответа** | SuccessResponseDto |

## Параметры URL

Параметры отсутствуют (целевой пользователь определяется по Cookie).

## Логика обработки запроса

*   BFF извлекает из Cookie текущую сессию, чтобы Auth отличил «это устройство» от остальных.
*   BFF вызывает gRPC [`TerminateOtherSessions`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-TerminateOtherSessions).
*   Возвращается сообщение с числом завершённых сессий.

## Успешный ответ

```json
{
  "success": true,
  "message": "Завершено 3 сессии(й). Текущее устройство остается активным."
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **500 Internal Server Error** | Ошибка при массовом обновлении записей в БД. |

# SR-AUTH-SM-02: Смена рабочего пространства: Switch Workspace

## Общая информация

Если пользователь состоит в нескольких командах (Workspaces), переключение контекста в SPA вызывает этот эндпоинт. Он обновляет кэш сессии, загружая роли для нового пространства, так что следующий вызов к бизнес-микросервису получит уже новые заголовки (Header Routing).

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса** | ContextSwitchRequestDto |
| **DTO успешного ответа** | SessionContextDto |

## Параметры URL

Параметры отсутствуют. Целевой Workspace передается в JSON-теле.

## Логика обработки запроса

*   BFF передаёт в Auth тело запроса с идентификатором целевого Workspace и контекст текущей сессии (из Cookie).
*   BFF вызывает gRPC [`ForceContextSwitch`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-ForceContextSwitch).
*   В ответе возвращается обновлённый `SessionContextDto` (как у `/sessions/me`).

## Успешный ответ

Возвращает измененный контекст аналогично эндпоинту `/sessions/me`, где `activeWorkspaceId` уже изменен.

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **400 Bad Request** | Не указан ID целевого рабочего пространства. |
| **403 Forbidden** | У пользователя нет прав доступа к запрашиваемому Workspace. |

# SR-AUTH-SM-09: Продление сессии: Keep-Alive

## Общая информация

SPA вызывает этот эндпоинт в фоне (например, раз в 15 минут) при наличии активности мышью или клавиатурой. Это позволяет отодвинуть Idle Timeout сессии в Redis (не путать с Silent Refresh, который работает с OIDC токенами).

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса** | KeepAliveRequestDto |
| **DTO успешного ответа** | SuccessResponseDto |

## Параметры URL

Параметры отсутствуют.

## Логика обработки запроса

*   BFF передаёт в Auth идентификатор текущей сессии по Cookie.
*   BFF вызывает gRPC [`KeepSessionAlive`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-KeepSessionAlive).
*   При успехе — **200 OK** с минимальным телом или без него.

## Успешный ответ

HTTP 200 OK без сложного тела.

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **401 Unauthorized** | Сессия уже была уничтожена по Idle Timeout. |

# SR-AUTH-SM-08: Доверенные устройства: List, Remember, Forget

## Общая информация

Управление списком Trusted Devices (на основе аппаратного Fingerprint + User-Agent). Если устройство помечено как "Доверенное" (например, после ввода MFA и нажатия галочки "Запомнить меня на 30 дней"), система не будет запрашивать MFA при следующих логинах с этого железа.

| Тип метода | GET / POST / DELETE |
| :--- | :--- |
| **DTO запроса (Remember)** | (в JSON передается название устройства и опционально TTL доверия) |
| **DTO успешного ответа (List)** | Массив объектов `TrustedDeviceDto` |

## Параметры URL

| Название | Тип | Описание |
| :--- | :--- | :--- |
| `id` | `string` | В методе `DELETE`: Идентификатор записи доверенного устройства в БД. |

## Логика обработки запроса

*   BFF по Cookie определяет пользователя и маршрутизирует HTTP-метод на соответствующий вызов Auth.
*   В зависимости от метода BFF вызывает gRPC:
    *   `GET` → [`ListTrustedDevices`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-ListTrustedDevices)
    *   `POST` → [`RememberTrustedDevice`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-RememberTrustedDevice)
    *   `DELETE` → [`RemoveTrustedDevice`](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md#grpc-RemoveTrustedDevice) (в path — `id` записи)
*   Ответ маппится в JSON (`TrustedDeviceDto` / подтверждение).

## Успешный ответ (List)

```json
{
  "success": true,
  "data": [
    {
      "id": "td_1092",
      "fingerprintHash": "sha256:abc...",
      "deviceName": "My Work Macbook",
      "trustedUntil": "2026-04-25T14:00:00Z"
    }
  ]
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **404 Not Found** | Попытка удалить несуществующее или чужое доверенное устройство. |
