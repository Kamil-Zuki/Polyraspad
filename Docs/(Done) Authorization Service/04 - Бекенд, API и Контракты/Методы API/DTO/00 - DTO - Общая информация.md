# Введение

Настоящий документ содержит описание Объектов Передачи Данных (DTO) для микросервиса Authorization Service — главного узла безопасности и управления сессиями платформы. 

Публичные **REST**-тела запросов/ответов и сериализация на периметре обычно относятся к **API Gateway (агрегатору)**, который маппит HTTP на **gRPC** Authorization Service; DTO ниже описывают **контракт данных** независимо от того, на каком узле выполняется сериализация JSON.

Цель данной документации — чётко определить структуры данных (DTO), которые используются для взаимодействия между Frontend (SPA), внутренними микросервисами (через API Gateway) и глобальным STEOS ID по протоколам REST API и через брокер сообщений RabbitMQ. DTO играют ключевую роль в обеспечении строгой типизации контрактов, сокрытии чувствительных данных (Phantom Token) и инкапсуляции внутренней логики безопасности микросервиса от потребителей его API.

Документ разработан на основе функциональных требований (SR-AUTH-xxx) и архитектурных решений (КАР-xxx) и предназначен для использования разработчиками, инженерами по безопасности и тестировщиками.


# 1. Группы DTO

Все Объекты Передачи Данных (DTO) в Authorization Service разделены на логические группы в зависимости от того, какую часть системы безопасности или бизнес-процесса они обслуживают.

| **Название группы** | **Краткое описание (за что отвечает)** |
| :--- | :--- |
| **Основные (общие) DTO** | Стандартизированные ответы, обертки для пагинации и унифицированные форматы ошибок (RFC 7807), используемые повсеместно. |
| **Управление сессиями (Session Management)** | Структуры данных для управления локальными сессиями пользователей, отображения списка активных устройств и маршрутизации контекста (Workspace). |
| **Аутентификация и OIDC (Auth & OIDC)** | DTO, обслуживающие OIDC Authorization Code Flow, PKCE, обмен кодов на токены и получение/кэширование JWKS. |
| **Управление гостевым доступом (Guest Sessions)** | Объекты для старта анонимных сессий, контроля демо-квот и события "склейки" гостевых ресурсов с авторизованным профилем. |
| **Одноразовые билеты (One-Time Tickets)** | Структуры для запроса и валидации эфемерных тикетов, используемых для WebSocket-соединений и прямых скачиваний файлов. |
| **Аудит и безопасность (Audit & Security)** | DTO для иммутабельного WORM-аудита, событий безопасности (Fail2Ban), экспорта архивов и черных списков, а также для управления режимом "Бесшовной имперсонации" (God Mode). |
| **Управление доступом и политики Workspace (Access Control)** | DTO для PAT (API-ключи разработчика) и политик Geo-Fencing / IP Whitelisting на уровне Workspace; согласованы с REST и gRPC Access Control. |
| **WebSocket и real-time уведомления (WebSocket Notifications)** | DTO полезной нагрузки Server → Client для канала WebSocket (события сессий, MFA, алерты, гостевые квоты и т.д.); см. [08 - WebSocket уведомления](08%20-%20WebSocket%20и%20real-time%20уведомления%20(WebSocket%20Notifications).md). |

# 2. Основные (общие) DTO

В данной группе собраны универсальные объекты передачи данных, которые применяются во множестве эндпоинтов API. Они обеспечивают стандартизацию ответов об успехе, единый формат возврата ошибок (включая ошибки безопасности) и унифицированную структуру для списков (например, список сессий).

| **Название DTO** | **Назначение** |
| :--- | :--- |
| **SuccessResponseDto** | Ответ (Общий): Стандартный успешный ответ для операций, не требующих возврата данных. |
| **ProblemDetailsDto** | Ответ (Общий): Унифицированная структура ответа об ошибке (согласно RFC 7807), расширенная кодами безопасности. |
| **PaginatedResponseDto** | Ответ (Общий): Обертка для списков с данными пагинации (total, limit, offset). |

# 3. Управление сессиями (Session Management)

Эта группа DTO используется для взаимодействия с механизмом локальных сессий (Phantom Token). Включает структуры для получения информации о текущей сессии, смены рабочего пространства (Context Routing) и отзыва (Revoke) сессий с конкретных устройств.

| **Название DTO**            | **Назначение**                                                                     |
| :-------------------------- | :--------------------------------------------------------------------------------- |
| **SessionDto**              | Ответ: Метаданные текущей сессии (ID, IP, User-Agent), исключая токены.            |
| **SessionContextDto**       | Ответ: Детальная информация о текущем активном Workspace и ролях пользователя.     |
| **ContextSwitchRequestDto** | Запрос: Входные параметры для переключения текущего активного пространства.        |
| **SessionListResponseDto**  | Ответ: Обертка над списком всех активных сессий пользователя с выделением текущей. |
| **RevokeSessionRequestDto** | Запрос: Параметры для принудительного отзыва сессии с указанием причины.           |
| **KeepAliveRequestDto**     | Запрос: Структура пинг-запроса от фронтенда для инициации Silent Refresh.          |
| **ListActiveSessionsRequest** | Запрос: Параметры gRPC/REST для получения списка активных сессий пользователя. |
| **TrustedDeviceDto**        | Ответ: Запись доверенного устройства (id, отпечаток, имя, дата добавления).        |
| **RememberTrustedDeviceRequest** | Запрос: Добавление текущего устройства в белый список.                     |
| **RemoveTrustedDeviceRequest** | Запрос: Удаление устройства из доверенных по id записи.                      |

# 4. Аутентификация и OIDC (Auth & OIDC)

Группа описывает структуры данных, необходимые для оркестрации взаимодействия с глобальным STEOS ID. Сюда входят DTO для настройки редиректов (PKCE), обмена кодов на токены (Token Exchange) и внутреннего кэширования ключей подписи.

| **Название DTO** | **Назначение** |
| :--- | :--- |
| **LoginRequestDto** | Запрос: Первичная аутентификация пользователя (логин/пароль) или начало OIDC Flow. |
| **LoginResponseDto** | Ответ: Содержит статус аутентификации (успех, редирект на 2FA или OIDC). |
| **OidcAuthRequestDto** | Запрос: Входные параметры (provider, redirect_uri) для инициализации Authorization Code Flow. |
| **OidcAuthResponseDto** | Ответ: Сгенерированный URL для редиректа пользователя на форму входа STEOS ID. |
| **OidcCallbackRequestDto** | Запрос: Callback от STEOS ID с параметром `code` и опциональным `state`. |
| **LogoutRequestDto** | Запрос: Стандартный выход пользователя (инвалидация Phantom Token и OIDC токенов). |
| **BackchannelLogoutRequestDto** | Запрос: Системный вебхук от STEOS ID на глобальную инвалидацию всех сессий пользователя (RFC 8417). |
| **MfaChallengeDto** | Ответ: Метаданные (например, замаскированный номер телефона или email) для отправки OTP/Push. |
| **MfaVerifyRequestDto** | Запрос: Пользователь вводит полученный одноразовый код (OTP) или подтверждает Push. |
| **TokenRefreshRequestDto** | Запрос: (Устарело/Внутреннее) Ручной запрос на обновление токенов. Чаще всего заменяется механизмом `KeepAliveRequestDto` и Silent Refresh. |
| **OidcFlowStateDto** | Внутренний объект: Структура, хранимая в Redis во время флоу логина (state, nonce, code_verifier, redirect_url). |
| **TokenExchangeRequestDto** | Запрос: Внутренняя структура (S2S) для обмена authorization code на токены у провайдера. |
| **TokenExchangeResponseDto** | Ответ: Структура, возвращаемая от STEOS ID (содержит access_token, id_token, refresh_token). |
| **TokenIntrospectionResponseDto** | Ответ: S2S структура ответа от эндпоинта валидации токенов (если не используется in-memory проверка). |
| **JwksCacheDto** | Ответ: Внутренняя структура для in-memory хранения и десериализации публичных ключей RSA (JWKS). |
| **GlobalLogoutEventDto** | Ответ (Событие): Структура сообщения от RabbitMQ для мгновенного Back-Channel Logout (блокировка/выход). |

# 5. Управление гостевым доступом (Guest Sessions)

Данные DTO обслуживают демо-режим Платформы. Позволяют неавторизованным пользователям получить теневую сессию с привязкой к аппаратному отпечатку браузера (Fingerprint) и отслеживают квоты.

| **Название DTO** | **Назначение** |
| :--- | :--- |
| **GuestSessionCreateDto** | Запрос: Явная инициализация "теневой" сессии (Shadow Session) для неавторизованного пользователя. |
| **GuestSessionResponseDto** | Ответ: Метаданные созданной гостевой сессии (ID, квоты, TTL), аналогично `SessionDto`, но с пометкой гостя. |
| **ConvertGuestRequestDto** | Запрос: Инициирует процесс привязки накопленных данных гостевой сессии к новому авторизованному STEOS ID. |
| **GuestQuotaStatusDto** | Ответ: Текущее состояние лимитов (Rate Limits / Business Quotas) для гостевого пользователя. |
| **GuestSessionContextDto** | Ответ: Урезанный контекст для гостя, используемый фронтендом для адаптации UI. |
| **GuestMergeEventDto** | Ответ (Событие): Сообщение для RabbitMQ, информирующее микросервисы о конвертации гостя в авторизованного пользователя (`shadow_guest_id` -> `real_global_id`). |
| **MergeGuestDataRequest** | Запрос: Параметры RPC слияния данных гостя (идентификаторы, scope). |
| **MergeGuestDataResponse** | Ответ: Подтверждение приёма задачи слияния (идентификатор операции). |
| **GetGuestAccessStatusRequest** | Запрос: Идентификатор гостевой сессии из Cookie/контекста для `GetGuestAccessStatus`. |

# 6. Одноразовые билеты (One-Time Tickets)

Группа структур для работы с механизмом эфемерных токенов (живут 15 секунд), которые используются там, где передача Cookie невозможна или небезопасна (WebSocket Handshake).

| **Название DTO** | **Назначение** |
| :--- | :--- |
| **TicketCreateRequestDto** | Запрос: Создание билета для определенного действия (скачивание файла, WebSocket). |
| **TicketResponseDto** | Ответ: Сгенерированный токен билета (URL-safe строка). |
| **TicketValidateRequestDto** | Запрос: (Внутреннее API) Валидация билета целевым микросервисом перед выполнением действия. |
| **TicketValidateResponseDto** | Ответ: (Внутреннее API) Решение Auth Service (VALID / INVALID) и распакованный контекст пользователя. |
| **FileDownloadUrlDto** | Ответ: Специфичный DTO (обертка), содержащий готовую presigned-ссылку для скачивания/стриминга файла. |
| **WsConnectUrlDto** | Ответ: Специфичный DTO (обертка), содержащий WSS-ссылку с прикрепленным билетом для инициализации сокета. |
| **TicketContextPayloadDto** | Внутренний объект: Структура, сериализуемая в Redis при создании билета (содержит actor_id, workspace_id, action_scope). |

# 7. Аудит и безопасность (Audit & Security)

Эти DTO обеспечивают функционал "Режима Бога" (бесшовная имперсонация для техподдержки), а также формируют структуры для записи неизменяемых логов безопасности (WORM Audit) и инцидентов (Fail2Ban).

| **Название DTO**                | **Назначение**                                                                                                                |
| :------------------------------ | :---------------------------------------------------------------------------------------------------------------------------- |
| **AuditLogEventDto**            | Ответ: Запись неизменяемого журнала аудита (событие, актор, IP, изменения).                                                   |
| **AuditLogQueryDto**            | Запрос: Параметры фильтрации и поиска по журналу безопасности (даты, типы событий, пользователи).                             |
| **SecurityAlertDto**            | Ответ: Уведомление о подозрительной активности (например, вход с нового IP или подмена User-Agent).                           |
| **BlockListAddRequestDto**      | Запрос: Внесение IP-адреса, подсети или отпечатка устройства в черный список (Local Firewall).                                |
| **BlockListQueryDto**           | Запрос: Фильтры и пагинация для просмотра черного списка (RPC `QueryBlocklist`).                                                |
| **BlocklistEntryDto**           | Ответ: Одна запись черного списка (цель, причина, TTL, активность).                                                           |
| **GetExportArchiveJobStatusRequest** | Запрос: Опрос статуса задачи экспорта WORM по `job_id`.                                                                  |
| **ExportArchiveJobStatusDto**   | Ответ: Статус задачи экспорта и presigned URL при готовности.                                                                 |
| **ImpersonateRequestDto**       | Запрос: Команда от сотрудника поддержки на запуск режима God Mode (Impersonation) с указанием причины (Ticket ID).            |
| **GodModeContextDto**           | Ответ: Специальный расширенный контекст сессии для режима имперсонации (инкапсулирует оригинального актора и целевого).       |
| **ImpersonationStopRequestDto** | Запрос: Сигнал для принудительного и явного выхода из God Mode.                                                               |
| **AuditMacroContextDto**        | Вложенный объект: JSON-структура для WORM логов, содержащая расширенный контекст события (TargetWorkspaceId, ImpersonatorId). |
| **RateLimitConfigDto**          | Ответ/Запрос: Структура для получения и конфигурации лимитов (Token Bucket) защитного периметра (Fail2Ban).                   |

# 8. Управление доступом и политики Workspace (Access Control)

Структуры для PAT и geo-политик; детальные поля — в [07 - Управление доступом и политики Workspace (Access Control)](07%20-%20Управление%20доступом%20и%20политики%20Workspace%20(Access%20Control).md). | **SR** | **Название DTO** | **Назначение** |
| :--- | :--- | :--- |
| SR-AUTH-AC-04 | **CreatePatRequestDto** | Запрос: Имя ключа, срок действия, набор `scopes`. |
| SR-AUTH-AC-04 | **PatResponseDto** | Ответ: Полный токен при создании (один раз), `id`, предупреждение. |
| SR-AUTH-AC-04 | **PatDetailsDto** | Ответ: Элемент списка PAT (маскированный токен, даты, id). |
| SR-AUTH-AC-04 | **ListPersonalAccessTokensRequest** | Запрос: Список PAT текущего пользователя (контекст из вызова). |
| SR-AUTH-AC-04 | **ListPersonalAccessTokensResponse** | Ответ: Список `PatDetailsDto`. |
| SR-AUTH-AC-04 | **RevokePersonalAccessTokenRequest** | Запрос: Отзыв по `key_id`. |
| SR-AUTH-AC-05 | **WorkspaceGeoPolicyDto** | Ответ/Запрос: `workspaceId`, `allowedIps`, `allowedCountries`, `blockVpnProxies`. |
| SR-AUTH-AC-05 | **GetWorkspaceGeoPolicyRequest** | Запрос: Идентификатор Workspace. |
