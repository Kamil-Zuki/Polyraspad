# Введение

Данный документ описывает структуры данных (DTO), используемые для генерации, валидации и управления жизненным циклом Одноразовых Билетов (One-Time Tickets). Этот механизм критически важен для безопасной передачи контекста авторизации в ситуациях, когда стандартная передача Phantom Token через Cookie невозможна или небезопасна (например, при загрузке файлов напрямую на CDN/Storage Service, при скачивании приватных вложений, инициализации WebSocket/SSE соединений или шаринге временных ссылок).

Билеты инкапсулируют целевой URL, ограниченный TTL (время жизни), бизнес-контекст пользователя и одноразовый криптографический токен (Nonce), защищая ресурсы от несанкционированного прямого доступа.

# 1. Список DTO

В таблице ниже перечислены DTO, обеспечивающие работу механизма One-Time Tickets.

| **Название DTO** | **Назначение** |
| :--- | :--- |
| **TicketCreateRequestDto** | Запрос: Создание билета для определенного действия (скачивание файла, WebSocket). |
| **TicketResponseDto** | Ответ: Сгенерированный токен билета (URL-safe строка). |
| **TicketValidateRequestDto** | Запрос: (Внутреннее API) Валидация билета целевым микросервисом перед выполнением действия. |
| **TicketValidateResponseDto** | Ответ: (Внутреннее API) Решение Auth Service (VALID / INVALID) и распакованный контекст пользователя. |
| **FileDownloadUrlDto** | Ответ: Специфичный DTO (обертка), содержащий готовую presigned-ссылку для скачивания/стриминга файла. |
| **WsConnectUrlDto** | Ответ: Специфичный DTO (обертка), содержащий WSS-ссылку с прикрепленным билетом для инициализации сокета. |
| **TicketContextPayloadDto** | Внутренний объект: Структура, сериализуемая в Redis при создании билета (содержит actor_id, workspace_id, action_scope). |

# DTO: TicketCreateRequestDto

## Контекст и назначение

Объект отправляется клиентским приложением (или другим внутренним микросервисом) на Auth Service для генерации одноразового билета. В запросе указывается, **какое именно действие** (Intent) хочет совершить пользователь (например, "скачать файл ID 123", "подключиться к WebSocket чата 456"). Auth Service генерирует билет, сохраняет его в Redis с коротким TTL (от 30 секунд до 5 минут) и привязывает к нему текущий контекст сессии (из Cookie/Phantom Token запросившего).

**Назначение:** Запрос (Генерация билета).
**Реализация сущности:** Запись в Redis (Ticket ID -> Context).

## Структура данных

Включает тип намерения и метаданные целевого ресурса.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `intent` | `string` | Тип действия (напр., `DOWNLOAD_ATTACHMENT`, `WEBSOCKET_INIT`, `EXPORT_REPORT`). |
| `resourceId` | `string` | Идентификатор ресурса (например, UUID файла или ID канала WS). Опционально, но рекомендуется для жесткой привязки билета к конкретному объекту. |
| `ttlSeconds` | `integer` | Желаемое время жизни билета в секундах (может быть переопределено политиками сервера). По умолчанию 60 сек. |

## Пример работы (JSON)

Запрос на генерацию билета для скачивания отчета.

```json
{
  "intent": "EXPORT_REPORT",
  "resourceId": "report-uuid-7777-8888",
  "ttlSeconds": 120
}
```

# DTO: TicketResponseDto

## Контекст и назначение

Ответ, содержащий сгенерированный токен билета. Клиент использует этот токен как параметр в URL (например, `?ticket=...`) или в заголовке `Authorization: Ticket ...` при обращении к целевому ресурсу (Storage, WS Gateway), который не умеет читать куки (или куда куки не отправляются из-за CORS/SameSite ограничений).

**Назначение:** Ответ (Сгенерированный токен).
**Реализация сущности:** URL-safe строка (UUID v4 или подписанный JWT-образный токен).

## Структура данных

Содержит только сам токен и срок его истечения для корректной обработки на клиенте (чтобы не пытаться использовать протухший билет).

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `ticketToken` | `string` | Значение билета, которое нужно передать целевому сервису. |
| `expiresAt` | `datetime` | Время (UTC), после которого билет будет автоматически удален из Redis. |

## Пример работы (JSON)

Пример ответа со сгенерированным билетом.

```json
{
  "ticketToken": "tkt_abc123def456ghi789",
  "expiresAt": "2026-03-25T10:02:00Z"
}
```

# DTO: TicketValidateRequestDto

## Контекст и назначение

Это **внутренний** DTO, используемый между микросервисами по gRPC или HTTP. Когда целевой сервис (например, Storage Service) получает запрос на скачивание файла с параметром `?ticket=...`, он должен обратиться к Auth Service для проверки валидности этого билета и получения контекста пользователя (кто это качает, какие у него роли). Одновременно Auth Service "сжигает" (удаляет) билет из Redis, обеспечивая его одноразовость.

**Назначение:** Запрос (Внутренняя валидация).
**Реализация сущности:** gRPC / HTTP (Internal).

## Структура данных

Содержит токен билета и ожидаемое действие (чтобы предотвратить использование билета от скачивания картинки для подключения к вебсокету).

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `ticketToken` | `string` | Значение билета, полученное сервисом от клиента. |
| `expectedIntent` | `string` | Намерение, для которого предназначался билет (напр., `DOWNLOAD_ATTACHMENT`). |
| `expectedResourceId` | `string` | ID ресурса, который клиент запрашивает у сервиса (для проверки привязки билета). Опционально. |

## Пример работы (JSON)

Запрос от Storage Service к Auth Service на проверку билета.

```json
{
  "ticketToken": "tkt_abc123def456ghi789",
  "expectedIntent": "EXPORT_REPORT",
  "expectedResourceId": "report-uuid-7777-8888"
}
```

# DTO: TicketValidateResponseDto

## Контекст и назначение

Это **внутренний** DTO-ответ от Auth Service целевому микросервису. Если билет валиден, не протух, intent совпадает и он еще не был использован, Auth Service возвращает статус `VALID` и полный бизнес-контекст пользователя (`SessionContextDto`), как если бы пользователь обратился к сервису напрямую через API Gateway с кукой. Если билет недействителен (протух, неверный intent, или уже был использован), возвращается `INVALID`.

**Назначение:** Ответ (Результат валидации и инъекция контекста).
**Реализация сущности:** gRPC / HTTP (Internal).

## Структура данных

Включает статус валидации и распакованный контекст (аналог Header Routing).

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `isValid` | `boolean` | Результат проверки билета. |
| `userId` | `uuid` | Глобальный ID пользователя (если `isValid = true`). |
| `workspaceId` | `uuid` | Текущий активный Workspace (если `isValid = true`). |
| `roles` | `array<string>` | Список ролей пользователя в данном Workspace (если `isValid = true`). |
| `errorCode` | `string` | Код ошибки (напр., `TICKET_EXPIRED`, `TICKET_NOT_FOUND`, `INTENT_MISMATCH`), если `isValid = false`. |

## Пример работы (JSON)

Успешный ответ Auth Service (билет сожжен, доступ разрешен).

```json
{
  "isValid": true,
  "userId": "user-uuid-1111-2222-3333",
  "workspaceId": "ws-uuid-4444-5555",
  "roles": ["viewer"],
  "errorCode": null
}
```

# DTO: FileDownloadUrlDto

## Контекст и назначение

Этот DTO представляет собой высокоуровневую обертку, часто используемую как ответ фронтенду на запрос экспорта или скачивания. Вместо того чтобы фронтенд сам конструировал URL вида `https://storage.steos.io/file/123?ticket=xyz`, бэкенд возвращает сразу готовую подписанную ссылку.

**Назначение:** Ответ (Готовая ссылка).
**Реализация сущности:** Сгенерированная строка.

## Структура данных

Включает полностью сформированный URL.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `downloadUrl` | `string` | Полный абсолютный URL для скачивания файла (уже содержит параметр `ticket`). |
| `expiresInSeconds` | `integer` | Время жизни ссылки (соответствует TTL билета). |

## Пример работы (JSON)

Пример ответа фронтенду на экспорт в CSV.

```json
{
  "downloadUrl": "https://api.steos.io/v1/storage/reports/report-uuid-7777-8888?ticket=tkt_abc123def456ghi789",
  "expiresInSeconds": 120
}
```

# DTO: WsConnectUrlDto

## Контекст и назначение

Аналог `FileDownloadUrlDto`, но для протокола WebSocket (wss://). Содержит готовую строку подключения к WebSocket-шлюзу платформы, защищенную одноразовым билетом (часто передаваемым как субпротокол или query-параметр).

**Назначение:** Ответ (Готовая WSS ссылка).
**Реализация сущности:** Сгенерированная строка.

## Структура данных

Включает wss-ссылку.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `wsUrl` | `string` | Полный URL для `new WebSocket(wsUrl)` (содержит параметр `ticket`). |

## Пример работы (JSON)

Пример ответа для инициализации чата.

```json
{
  "wsUrl": "wss://realtime.steos.io/notifications?ticket=tkt_ws_999888777"
}
```

# DTO: TicketContextPayloadDto

## Контекст и назначение

Этот DTO представляет собой внутреннюю структуру, которая сериализуется в JSON и сохраняется в Redis под ключом сгенерированного токена билета (`ticket:{ticketToken}`). Она содержит полный "снимок" (Snapshot) бизнес-контекста пользователя (его ID, Workspace, роли, и оригинальное намерение) на момент запроса билета. При успешной валидации (`TicketValidateRequestDto`) Auth Service распаковывает этот DTO из Redis, возвращает целевому сервису и затем удаляет ключ, обеспечивая одноразовость использования (Burn-after-Read).

**Назначение:** Внутренний объект (Состояние).
**Реализация сущности:** Значение ключа в Redis.

## Структура данных

Включает параметры намерений, метаданные целевого ресурса и снимок контекста сессии.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `intent` | `string` | Тип действия (напр., `DOWNLOAD_ATTACHMENT`, `WEBSOCKET_INIT`). |
| `resourceId` | `string` | ID ресурса, который клиент запросил при генерации билета (может быть пустым). |
| `actorId` | `uuid` | Глобальный ID пользователя, запросившего билет. |
| `workspaceId` | `uuid` | ID текущего рабочего пространства (если был установлен). |
| `roles` | `array<string>` | Массив эффективных ролей на момент выдачи билета. |
| `createdAt` | `datetime` | Точное время (UTC) генерации билета (сохраняется для аудита). |

## Пример работы (JSON)

Пример содержимого билета в Redis.

```json
{
  "intent": "EXPORT_REPORT",
  "resourceId": "report-uuid-7777-8888",
  "actorId": "user-uuid-1111-2222-3333",
  "workspaceId": "ws-uuid-4444-5555",
  "roles": ["viewer", "reporter"],
  "createdAt": "2026-03-25T10:00:00Z"
}
```
