# Введение

Данный документ описывает события WebSocket группы **«Управление сессиями и правами (Session & Access Management)»**. События доставляют уведомления об отзыве сессий, «горячем» обновлении авторизационного контекста и режиме имперсонации (God Mode).

**Источник SR:** [01 - Управление Сессиями и Контекстом — Session Management](../../../../01%20-%20Функциональная%20спецификация/Возможности%20сервиса/01%20-%20Управление%20Сессиями%20и%20Контекстом%20-%20Session%20Management.md).

Общий контекст канала и поток **API Gateway → gRPC** — в [00 - WebSocket API - Общая информация](00%20-%20WebSocket%20API%20-%20Общая%20информация.md).

# 1. Список событий

| **Код требования** | **Событие** | **Направление** | **Описание** |
| :----------------- | :---------- | :-------------- | :----------- |
| **SR-AUTH-SM-06** / **SR-AUTH-OI-04** | `session_revoked` | Server → Client | Принудительное завершение сессии (одна или все), немедленный выход из SPA. |
| **SR-AUTH-SM-10** | `context_updated` | Server → Client | Сигнал перезагрузить контекст (роли, лицензии, Workspace) без полного логина. |
| **SR-AUTH-SM-05** | `impersonation_started` | Server → Client | Сотрудник поддержки вошёл в аккаунт пользователя (прозрачность для владельца). |
| **SR-AUTH-SM-05** | `impersonation_stopped` | Server → Client | Имперсонация корректно завершена. |

# Событие: `session_revoked`

| **Название события**        | `session_revoked`                                                                                                                                                                                                                                                                                                         |
| :-------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Тип**                     | Входящее сообщение (Server → Client)                                                                                                                                                                                                                                                                                      |
| **Описание**                | Уведомление о том, что сервер **отозвал** текущую или указанную сессию. Требование **SR-AUTH-SM-06** (точечный отзыв, «выйти с других устройств»); глобальный сценарий — также **SR-AUTH-OI-04** (Back-Channel Logout). Клиент обязан прекратить использование локального состояния и перейти к безопасному экрану входа. |
| **DTO / полезная нагрузка** | [SessionRevokedNotificationDto](../DTO/08%20-%20WebSocket%20и%20real-time%20уведомления%20(WebSocket%20Notifications).md#dto-SessionRevokedNotificationDto)                                                                                                                                                               |

**Параметры сообщения** (канонические имена полей JSON — в DTO)

| Название параметра | Тип данных | Описание |
| :--- | :--- | :--- |
| **sessionId** | string (uuid) | Идентификатор отозванной сессии (для сопоставления с текущей вкладкой). |
| **reasonCode** | string | Код причины (`ADMIN_REVOKED`, `TERMINATED_FROM_OTHER_DEVICE`, `SECURITY_BREACH`, `OIDC_BACKCHANNEL` и т.д.). |
| **message** | string | Текст для отображения пользователю. |
| **timestamp** | string (ISO 8601 UTC) | Время отзыва. |

**Логика обработки**

1. API Gateway принимает запрос от клиента или внутренний вызов и проксирует в микросервис один из Unary-RPC: `RevokeSession`, `RevokeAllUserSessions` или `TerminateOtherSessions` (см. [02 - Session Lifecycle](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md)); при глобальном отзыве по событию IdP возможен цепной вызов `RevokeAllUserSessions`.
2. При срабатывании периметра отзыв может быть инициирован после `BanIpAddress` или `BanDeviceFingerprint` (см. [04 - Security & Quotas](../gRPC/04%20-%20Защита%20периметра%20и%20Гостевые%20квоты%20(Security%20&%20Quotas).md)) с последующим отзывом затронутых сессий.
3. Микросервис удаляет состояние сессии в Redis/БД и пишет аудит (**SR-AUTH-LA-01**).
4. Через **SR-AUTH-WS-01** (backplane) рассылается `session_revoked` в группу сессии/пользователя.
5. Клиент очищает хранилища и выполняет редирект на логин; следующий HTTP без валидной сессии отклоняется шлюзом при вызове `ValidateSession` ([01 - Validation Core](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md)).

# Событие: `context_updated`

| **Название события** | `context_updated`                                                                                                                                                                           |
| :------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Тип**              | Входящее сообщение (Server → Client)                                                                                                                                                        |
| **Описание**         | Сигнал **SR-AUTH-SM-10**: контекст пользователя (роли, биллинг, feature flags, активный Workspace) изменился на сервере; полный снимок в событии обычно **не** передаётся (только триггер). |
| **DTO**              | [ContextUpdatedNotificationDto](../DTO/08%20-%20WebSocket%20и%20real-time%20уведомления%20(WebSocket%20Notifications).md#dto-ContextUpdatedNotificationDto)                                 |

**Параметры сообщения** (канонические имена полей JSON — в DTO)

| Название параметра | Тип данных | Описание |
| :--- | :--- | :--- |
| **userId** | string (uuid) | Глобальный идентификатор пользователя. |
| **triggerEvent** | string | Причина (`ROLES_CHANGED`, `SUBSCRIPTION_UPGRADED`, `WORKSPACE_MEMBERSHIP` и т.п.). |
| **timestamp** | string (ISO 8601 UTC) | Время фиксации изменения. |

**Логика обработки**

1. Внутренний процесс или вызов завершает мутацию контекста в микросервисе через один или несколько Unary-RPC: `UpdateSessionContext` ([02 - Session Lifecycle](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md)), при смене Workspace — `ForceContextSwitch`, при обновлении профиля из IdP — `SyncIdentityClaims` ([03 - OIDC Infrastructure](../gRPC/03%20-%20Интеграция%20OIDC%20и%20Внутренние%20токены%20(OIDC%20Infrastructure).md)).
2. После фиксации состояния публикуется `context_updated` через **SR-AUTH-WS-01** (backplane) в каналы пользователя/сессии.
3. Клиент запрашивает актуальный контекст: REST `GET /sessions/me` → на стороне Auth `GetSessionContext` ([01 - Validation Core](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md)), тело ответа — [SessionContextDto](../DTO/02%20-%20Управление%20сессиями%20(Session%20Management).md#dto-SessionContextDto).
4. Обновить state (Redux/Zustand) и перерисовать навигацию без полной перезагрузки страницы.

# Событие: `impersonation_started`

| **Название события** | `impersonation_started`                                                                                                                                                         |
| :------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Тип**              | Входящее сообщение (Server → Client)                                                                                                                                            |
| **Описание**         | **SR-AUTH-SM-05**: пользователь должен видеть, что поддержка работает от его имени (прозрачность, аудит).                                                                       |
| **DTO**              | [ImpersonationNotificationDto](../DTO/08%20-%20WebSocket%20и%20real-time%20уведомления%20(WebSocket%20Notifications).md#dto-ImpersonationNotificationDto) (`action`: `STARTED`) |

**Параметры сообщения** (канонические имена полей JSON — в DTO)

| Название параметра | Тип данных | Описание |
| :--- | :--- | :--- |
| **ticketId** | string | Номер тикета helpdesk / обоснование. |
| **supportAgentName** | string | Отображаемое имя агента (маскирование по политике). |
| **action** | string | Значение `STARTED`. |
| **timestamp** | string (ISO 8601 UTC) | Время старта. |

**Логика обработки**

1. API Gateway передаёт в микросервис Unary-RPC `StartImpersonation` ([02 - Session Lifecycle](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md)).
2. После фиксации режима имперсонации публикуется `impersonation_started` (**SR-AUTH-WS-01**).

# Событие: `impersonation_stopped`

| **Название события** | `impersonation_stopped` |
| :------------------- | :---------------------- |
| **Тип** | Входящее сообщение (Server → Client) |
| **Описание** | Завершение режима имперсонации (**SR-AUTH-SM-05**); UI снимает баннеры/блокировки, связанные с сессией поддержки. |
| **DTO** | [ImpersonationNotificationDto](../DTO/08%20-%20WebSocket%20и%20real-time%20уведомления%20(WebSocket%20Notifications).md#dto-ImpersonationNotificationDto) (`action`: `STOPPED`) |

**Параметры сообщения** — те же поля, что в DTO; для остановки **`action`** = `STOPPED`, плюс **ticketId**, **timestamp**.

**Логика обработки**

1. API Gateway передаёт в микросервис Unary-RPC `StopImpersonation` ([02 - Session Lifecycle](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md)).
2. После фиксации завершения имперсонации публикуется `impersonation_stopped` (**SR-AUTH-WS-01**).
