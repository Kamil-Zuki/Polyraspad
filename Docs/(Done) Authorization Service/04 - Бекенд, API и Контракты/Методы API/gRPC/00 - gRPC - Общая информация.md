# Введение

Настоящий документ содержит полное описание **gRPC** интерфейса микросервиса **Authorization Service**. Это — **основной машинный контракт** сервиса: публичные **REST**-маршруты и **WebSocket**-каналы для браузеров описаны отдельно как контракт **API Gateway (агрегатора)** и по смыслу маппятся на перечисленные ниже RPC, а не дублируют логику контроллеров внутри процесса Auth.

В соответствии с принятой архитектурой Zero Trust, gRPC является критическим звеном Платформы Enterprise-уровня: его вызывает **API Gateway (Envoy/BFF)** для проверки каждого входящего запроса на наличие прав, а также другие внутренние микросервисы — для безопасной передачи контекста пользователя (Header Routing), межсервисной (M2M) аутентификации, генерации одноразовых билетов и записи логов безопасности.

Цель документа — определить исчерпывающий набор высокопроизводительных процедур (RPC), покрывающих все задачи аутентификации, гранулярной авторизации (ABAC/RBAC), динамического контроля сессий и квот, защиты периметра и иммутабельного аудита (WORM), скрывая при этом сложность работы с Phantom Tokens от остальной системы.


# 1. Группы методов gRPC

Ниже представлена сводная таблица всех логических групп методов gRPC, реализуемых сервисом.

| Группа | Описание |
| :--- | :--- |
| **Ядро валидации и инъекции (Validation Core)** | Самые высоконагруженные методы, вызываемые API Gateway для каждого запроса. Включают обмен Phantom Token на бизнес-заголовки, гранулярную проверку прав и межсервисную (M2M) аутентификацию. |
| **Управление жизненным циклом сессий (Session Lifecycle)** | Внутренние методы динамического управления состоянием: отзыв сессий, принудительная смена Workspace, обновление контекста "на лету" и управление режимом God Mode. |
| **Интеграция OIDC и Внутренние токены (OIDC Infrastructure)** | Инфраструктурные крипто-механизмы: ротация JWKS-ключей, интроспекция токенов, синхронизация Claims и выдача внутренних M2M JWT. |
| **Защита периметра и Гостевые квоты (Security & Quotas)** | Слой защиты и лимитирования: управление локальным фаерволом (Fail2Ban), контроль аномалий, динамический Rate Limiting, расход демо-квот гостями и полный жизненный цикл гостевой сессии (инициализация, статус, конвертация, слияние данных). |
| **Аудит доступа и Аналитика (Audit & Analytics)** | Получение и потоковая передача (Streaming) данных безопасности: история WORM-аудита, выгрузка архивов для Compliance, опрос статуса задачи экспорта и интеграция с SIEM-системами. |
| **Управление доступом, PAT и политики Workspace (Access Control)** | Программные ключи (Personal Access Tokens), локальный **Step-up MFA** (challenge / verify внутри уже установленной сессии), чтение и изменение политик периметра Workspace (Geo-Fencing / IP Whitelisting) с делегированием персистентности в Workspace Service по gRPC. |

# 2. Ядро валидации и инъекции (Validation Core)

Методы данной группы обеспечивают непосредственную защиту периметра Платформы. Они работают в связке с API Gateway (паттерн Token Translation/Header Routing) и отвечают за конвертацию непрозрачных идентификаторов в доверенный бизнес-контекст, а также за выдачу разрешений.

| Код требования | gRPC Метод          | Тип RPC | Описание                                                                                                                                                    |
| :------------- | :------------------ | :-----: | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SR-AUTH-LA-03  | `ValidateSession`   |  Unary  | Валидирует Phantom Token (`Cookie`) или Personal Access Token (`Authorization: Bearer`), извлекает контекст из Redis/БД и возвращает набор HTTP-заголовков для маршрутизации во внутренние сервисы.                  |
| SR-AUTH-OT-01  | `IssueTicket`       |  Unary  | Выпуск одноразового билета (Intent, Resource ID) для последующей валидации через `ValidateTicket`. |
| SR-AUTH-OT-02  | `ValidateTicket`    |  Unary  | Проверяет и "сжигает" одноразовый билет (паритет REST `POST /tickets/validate`; родительское доменное требование — SR-AUTH-SM-04).                                |
| SR-AUTH-OT-03  | `BuildFileDownloadUrl` | Unary | Утилитарная сборка готового URL с билетом для скачивания файла (внутренне использует `IssueTicket`). |
| SR-AUTH-OT-03  | `BuildWsConnectUrl` |  Unary  | Утилитарная сборка WSS-URL с билетом для защищённого WebSocket-handshake. |
| SR-AUTH-SM-06  | `GetSessionContext` |  Unary  | Полный `SessionContext` по сессии или пользователю (паритет REST `GET /sessions/me` в [REST 00](../REST%20API/00%20-%20REST%20API%20-%20Общая%20информация.md)); JSON-форма — [02 - DTO](../DTO/02%20-%20Управление%20сессиями%20(Session%20Management).md).        |
| SR-AUTH-AC-01  | `CheckPermission`   |  Unary  | Тонкая гранулярная проверка прав (ABAC/RBAC) на стороне Auth Service (например, `can_edit_invoice`). Разгружает целевые сервисы от хранения политик.        |
| SR-AUTH-M2M-01 | `ValidateM2MToken`  |  Unary  | Высокоскоростная проверка Machine-to-Machine JWT-токенов, используемых для общения внутренних систем платформы (например, от Task Service к Email Service). |


# 3. Управление жизненным циклом сессий (Session Lifecycle)

Методы для администраторов и системных процессов (например, Back-Channel Logout), позволяющие принудительно изменять состояние локальных сессий пользователей в реальном времени.

| Код требования | gRPC Метод | Тип RPC | Описание |
| :--- | :--- | :---: | :--- |
| SR-AUTH-SM-06 | `RevokeSession` | Unary | Принудительное завершение конкретной сессии по её идентификатору с записью причины в WORM-аудит. |
| SR-AUTH-OI-04 | `RevokeAllUserSessions` | Unary | Глобальный логаут: удаление всех активных сессий пользователя со всех устройств, обычно запускаемое внутренним обработчиком событий `OIDC Back-Channel Logout` из `RabbitMQ`. |
| SR-AUTH-SM-06 | `TerminateOtherSessions` | Unary | Безопасный логаут пользователя со всех остальных устройств (оставляя текущую сессию активной). |
| SR-AUTH-SM-02 | `ForceContextSwitch` | Unary | Принудительное переключение рабочего пространства пользователя на уровне бэкенда. |
| SR-AUTH-SM-10 | `UpdateSessionContext` | Unary | Динамическое фоновое обновление прав в кэше (например, при покупке лицензии) без принудительного перелогина пользователя. |
| SR-AUTH-SM-05 | `StartImpersonation` | Unary | Инициализация режима "God Mode" для сотрудника поддержки с проверкой прав и привязкой номера тикета. |
| SR-AUTH-SM-05 | `StopImpersonation` | Unary | Корректное завершение сессии имперсонации и возврат к оригинальному контексту сотрудника. |
| SR-AUTH-SM-06 | `ListActiveSessions` | Unary | Список всех активных сессий пользователя (устройства, гео, User-Agent) для UI «Мои устройства». |
| SR-AUTH-SM-09 | `KeepSessionAlive` | Unary | Продление TTL Phantom-сессии в Redis при активности SPA (keep-alive). |
| SR-AUTH-SM-08 | `ListTrustedDevices` | Unary | Список устройств, помеченных пользователем как доверенные. |
| SR-AUTH-SM-08 | `RememberTrustedDevice` | Unary | Добавление отпечатка текущего устройства в белый список пользователя. |
| SR-AUTH-SM-08 | `RemoveTrustedDevice` | Unary | Удаление устройства из списка доверенных. |

# 4. Интеграция OIDC и Внутренние токены (OIDC Infrastructure)

Группа методов, обеспечивающих криптографическую безопасность, синхронизацию идентичности и совместимость с сервисами, которые требуют математически доказуемых токенов.

| Код требования | gRPC Метод | Тип RPC | Описание |
| :--- | :--- | :---: | :--- |
| SR-AUTH-OI-02 | `IntrospectToken` | Unary | Внутренняя проверка валидности OIDC Access-токена (если он был передан напрямую, а не через Cookie). |
| SR-AUTH-OI-02 | `GetCachedJwks` | Unary | Получение актуального набора публичных ключей (JWKS) STEOS ID из кэша Authorization Service. |
| SR-AUTH-OI-05 | `ForceJwksRotation` | Unary | Аварийный триггер на немедленный сброс кэша и скачивание новых публичных ключей (JWKS) при подозрении на компрометацию. |
| SR-AUTH-OI-06 | `SyncIdentityClaims` | Unary | Принудительная фоновая синхронизация профиля (Claims) из STEOS ID для актуализации локальных данных пользователя. |
| SR-AUTH-M2M-02 | `ExchangeInternalToken` | Unary | Генерация короткоживущего внутреннего подписанного JWT (M2M) на основе текущего бизнес-контекста для интеграции с legacy-системами. |

**Замечание по JWKS:** `GetCachedJwks` относится к **SR-AUTH-OI-02** (кэш публичных ключей **STEOS ID**). Публичный HTTP `GET /.well-known/jwks.json` на стороне Authorization Service для ключей подписи **платформенных M2M** JWT — в REST [07 - Межсервисные процессы](../REST%20API/07%20-%20Межсервисные%20процессы%20и%20Здоровье.md) помечен как **SR-AUTH-M2M-01**; это другое назначение, не дублирование одной строки таблицы.

# 5. Защита периметра и Гостевые квоты (Security & Quotas)

Интерфейсы для автоматизированных систем защиты и отдельных бизнес-микросервисов, которые могут вызывать контракты `Authorization Service` для контроля гостевых лимитов и инцидентов. Сами эти внешние сервисы не описываются и не реализуются в рамках данного документа.

| Код требования | gRPC Метод                 | Тип RPC | Описание                                                                                                                          |
| :------------- | :------------------------- | :-----: | :-------------------------------------------------------------------------------------------------------------------------------- |
| SR-AUTH-SQ-02  | `CheckGuestQuota`          |  Unary  | Проверка наличия доступных лимитов (например, "осталось 2 генерации") у гостевой сессии перед выполнением дорогостоящей операции. |
| SR-AUTH-SQ-02  | `ConsumeGuestQuota`        |  Unary  | Атомарное списание части квоты гостевой сессии после успешного выполнения бизнес-действия.                                        |
| SR-AUTH-SQ-03  | `BanIpAddress`             |  Unary  | Добавление IP-адреса или подсети в черный список (Local Firewall) на заданное время (TTL).                                        |
| SR-AUTH-SQ-03  | `BanDeviceFingerprint`     |  Unary  | Принудительная блокировка аппаратного отпечатка устройства (защита от мультиаккаунтинга злоумышленников).                         |
| SR-AUTH-SQ-05  | `UnbanSubject`             |  Unary  | Явное удаление IP-адреса или Fingerprint из черного списка администратором ИБ (снятие блокировки).                                |
| SR-AUTH-SQ-03  | `CheckBanStatus`           |  Unary  | Высокоскоростная проверка (в Redis) IP-адреса или Fingerprint-а на предмет наличия в черном списке.                               |
| SR-AUTH-SQ-06  | `ReportSuspiciousActivity` |  Unary  | Внутренний RPC для получения сигналов от других сервисов (например, массовые ошибки) для динамического включения Throttling.      |
| SR-AUTH-SQ-04  | `GetRateLimitStatus`       |  Unary  | Запрос текущего состояния Token Bucket для конкретного клиента (для заголовков `X-RateLimit-Remaining`).                          |
| SR-AUTH-GQ-01  | `InitGuestSession`         |  Unary  | Создание гостевой сессии и начальной квоты (демо-режим).                                                                          |
| SR-AUTH-GQ-02  | `GetGuestAccessStatus`     |  Unary  | Текущее состояние гостевых лимитов и метаданных сессии.                                                                           |
| SR-AUTH-GQ-03  | `ConvertGuestSession`      |  Unary  | Привязка гостевой сессии к авторизованному пользователю после OIDC.                                                               |
| SR-AUTH-GQ-04  | `MergeGuestData`           |  Unary  | Инициация асинхронного слияния данных гостя в постоянный профиль (публикация в RabbitMQ при необходимости).                       |
| SR-AUTH-SQ-03  | `QueryBlocklist`           |  Unary  | Пагинированный просмотр записей локального черного списка (IP/Fingerprint) для админки.                                           |

# 6. Аудит доступа и Аналитика (Audit & Analytics)

Методы, предоставляющие доступ к иммутабельным журналам безопасности (WORM) и агрегированной аналитике инцидентов. Спроектированы с учетом требований Enterprise-комплаенса и интеграции с системами SIEM.

| Код требования | gRPC Метод             |     Тип RPC      | Описание                                                                                                                            |
| :------------- | :--------------------- | :--------------: | :---------------------------------------------------------------------------------------------------------------------------------- |
| SR-AUTH-LA-01  | `QueryAccessLogs`      |      Unary       | Постраничный поиск и фильтрация по таблице `access_audit_logs` с учетом прав вызывающего администратора.                             |
| SR-AUTH-LA-06  | `GetAuditLogDetails`   |      Unary       | Получение детальной информации (AuditMacroContext) по конкретному событию безопасности.                                             |
| SR-AUTH-LA-04  | `StreamAccessLogs`     | Server Streaming | Потоковая (в реальном времени) передача неизменяемых WORM-логов для непрерывной интеграции с внешними SIEM-системами (Splunk, ELK). |
| SR-AUTH-LA-05  | `ExportAuditArchive`   |      Unary       | Асинхронный запуск подготовки архива логов за указанный период с последующей выдачей временной ссылки на готовый результат.         |
| SR-AUTH-LA-05  | `GetExportArchiveJobStatus` | Unary       | Опрос статуса фоновой задачи экспорта и получение presigned URL при готовности (паритет REST `GET /audit/export-jobs/{jobId}`).       |
| SR-AUTH-SQ-07  | `QuerySecurityAlerts`  |      Unary       | Получение списка активных предупреждений безопасности (например, обнаружен Session Hijacking или Brute Force).                      |
| SR-AUTH-SQ-07  | `ResolveSecurityAlert` |      Unary       | Пометка инцидента безопасности как обработанного (resolved) администратором или автоматизированным скриптом.                        |
| SR-AUTH-LA-07  | `GetAuthStats`         |      Unary       | Агрегированная аналитика: количество активных сессий, гостевых пользователей, блокировок, квот и событий безопасности.              |

**Паритет REST:** в [REST 00](../REST%20API/00%20-%20REST%20API%20-%20Общая%20информация.md), раздел «Аудит…», перечислены unary-маршруты, соответствующие `QueryAccessLogs`, `GetAuditLogDetails`, экспорту и т.д. RPC **`StreamAccessLogs` (SR-AUTH-LA-04)** и **`GetAuthStats` (SR-AUTH-LA-07)** в той же сводке HTTP не дублируются: обычно вызываются интеграциями SIEM или админ-контурами по gRPC (см. [05 - Аудит доступа и Аналитика (gRPC)](05%20-%20Аудит%20доступа%20и%20Аналитика%20(Audit%20&%20Analytics).md)).

# 7. Управление доступом, PAT и политики Workspace (Access Control)

Методы для программного доступа (CLI/CI/CD) и настройки Enterprise-периметра Workspace. Персистентность geo-политик — в **Workspace Service**; `Authorization Service` вызывает его по **gRPC** (конкретные имена RPC — в документации Workspace Service; детали — [06 - Управление доступом, PAT и политики Workspace (Access Control)](06%20-%20Управление%20доступом,%20PAT%20и%20политики%20Workspace%20(Access%20Control).md)).

| Код требования | gRPC Метод | Тип RPC | Описание |
| :--- | :--- | :---: | :--- |
| SR-AUTH-AC-04 | `CreatePersonalAccessToken` | Unary | Создание PAT: хэш в БД, открытый токен в ответе один раз. |
| SR-AUTH-AC-04 | `ListPersonalAccessTokens` | Unary | Список PAT пользователя с маскированными значениями. |
| SR-AUTH-AC-04 | `RevokePersonalAccessToken` | Unary | Отзыв PAT по идентификатору ключа. |
| SR-AUTH-AC-05 | `GetWorkspaceGeoPolicy` | Unary | Чтение политик Geo-Fencing / IP Whitelisting для Workspace (делегирование чтения в Workspace Service по gRPC). |
| SR-AUTH-AC-05 | `UpdateWorkspaceGeoPolicy` | Unary | Обновление политик (только Owner); запись в Workspace Service по gRPC, аудит в Auth. |
| SR-AUTH-AC-02 | `StartStepUpMfaChallenge` | Unary | Требование SR-AUTH-AC-02: инициация step-up MFA (challenge). Публичное отображение для BFF — `POST /auth/mfa/challenge`. |
| SR-AUTH-AC-02 | `VerifyStepUpMfa` | Unary | Требование SR-AUTH-AC-02: проверка фактора и выдача временного права на критичную операцию. Публичное отображение для BFF — `POST /auth/mfa/verify`. |
