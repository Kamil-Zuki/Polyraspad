# Введение

Настоящий документ создан для описания ключевых алгоритмов и методов, реализованных на стороне сервера в рамках микросервиса **Authorization Service**. Его цель — обеспечить разработчиков, архитекторов и специалистов по информационной безопасности полным пониманием внутренней логики, принципов работы и особенностей реализации функций защиты, аутентификации и маршрутизации контекста.

Документ служит техническим справочником на всех этапах жизненного цикла разработки. Он позволяет команде принимать обоснованные решения при внесении изменений, обеспечивая сохранение целостности сессий, соблюдение политик Zero Trust и требований высокой производительности (low latency).

Документ разработан на основе анализа **функциональных требований (SR-AUTH-xxx)** и архитектурных решений (КАР-xxx) и предназначен для бэкенд-разработчиков, архитекторов и инженеров по эксплуатации.

# 1. Группы алгоритмов

Ниже представлены основные группы алгоритмов, разделенные по их функциональному назначению и роли в архитектуре сервиса авторизации.

| **Группа возможностей** | **Описание и назначение** |
| :--- | :--- |
| **Управление Сессиями и Контекстом (Session Management)** | Включает базовые алгоритмы для генерации, валидации и отзыва локальных сессий (Phantom Tokens). Отвечает за маршрутизацию контекста Workspace, одноразовые билеты и имперсонацию. |
| **Инфраструктура OIDC и Интеграция (OIDC Infrastructure)** | Содержит алгоритмы криптографического взаимодействия с глобальным STEOS ID, включая OIDC Flow, кэширование ключей (JWKS) и обработку асинхронного выхода (Back-Channel Logout). |
| **Защита Периметра и Гостевые Квоты (Security & Quotas)** | Объединяет алгоритмы защиты инсталляции на уровне Gateway: валидацию отпечатков (Anti-Hijacking), управление гостевым доступом и многоуровневое лимитирование (Local Firewall). |
| **Локальный Аудит Доступа (Local Access Audit)** | Отвечает за алгоритмы формирования иммутабельного WORM-журнала безопасности и внедрения доверенных заголовков (Header Routing) для внутренних сервисов. |

# 2. Управление Сессиями и Контекстом (Session Management)

Данная группа собирает базовые и наиболее критичные алгоритмы, обеспечивающие конвертацию глобальной идентичности в безопасные локальные сессии. Именно здесь происходит "магия" защиты от XSS через Phantom Tokens и бесшовная маршрутизация запросов пользователя без изменения клиентского состояния.

| **Название алгоритма** | **Краткое описание** |
| :--- | :--- |
| **Алгоритм валидации и инъекции Phantom Token** | Обеспечивает извлечение HttpOnly Cookie, сверхбыструю проверку сессии в Redis и извлечение пользовательского контекста (ID, Роли). |
| **Алгоритм серверной маршрутизации контекста** | Обрабатывает смену `workspace_id` в стейте Redis для перенаправления всех последующих запросов пользователя в нужное пространство без участия фронтенда. |
| **Алгоритм генерации и гашения одноразовых билетов** | Управляет созданием 15-секундных эфемерных токенов в Redis и их атомарным уничтожением (Burn-on-Read) при открытии WebSocket или скачивании файлов. |
| **Алгоритм бесшовной имперсонации (God Mode)** | Создает "двойную" сессию, маскирующую ID сотрудника под ID клиента, обеспечивая прозрачность для бизнес-сервисов и строгость для систем аудита. |
| **Алгоритм тихого серверного продления (Silent Refresh)** | Выполняет фоновую S2S-дешифровку `refresh_token` и запрашивает новый Access-токен у STEOS ID для продления сессии без переадресации пользователя. |

# 3. Инфраструктура OIDC и Интеграция (OIDC Infrastructure)

Алгоритмы этой группы обеспечивают криптографически безопасный мост между локальной инсталляцией Платформы и глобальным корневым провайдером (STEOS ID). Они гарантируют легитимность входящих токенов и синхронизацию состояния аккаунтов.

| **Название алгоритма** | **Краткое описание** |
| :--- | :--- |
| **Алгоритм обработки OIDC Authorization Code Flow** | Оркестрирует защищенный обмен авторизационного кода на токены с использованием PKCE и строгой проверкой параметров `state` и `nonce`. |
| **Алгоритм фонового кэширования и In-Memory валидации JWKS** | Загружает публичные ключи STEOS ID в фоне и выполняет математическую проверку RSA-подписей JWT в оперативной памяти за доли миллисекунды. |
| **Алгоритм асинхронной инвалидации (Back-Channel Logout)** | Прослушивает брокер RabbitMQ на предмет глобальных банов и мгновенно уничтожает все локальные сессии (Redis) скомпрометированного пользователя. |

# 4. Защита Периметра и Гостевые Квоты (Security & Quotas)

Эти алгоритмы реализуют паттерны защиты платформы от злоупотреблений, ботов и несанкционированного доступа до того, как запрос достигнет глубоких бизнес-слоев или глобального IdP.

| **Название алгоритма** | **Краткое описание** |
| :--- | :--- |
| **Алгоритм защиты от угона сессий (Session Hijacking)** | Сравнивает входящий аппаратный отпечаток браузера (`device_fingerprint`) и IP с эталонным стейтом сессии, отзывая Cookie при аномалиях. |
| **Алгоритм выдачи и конвертации гостевых сессий** | Управляет анонимным доступом: выделяет изолированные теневые сессии по фингерпринту и бесшовно переносит наработанные ресурсы при регистрации гостя. |
| **Алгоритм многоуровневого лимитирования (Local Firewall)** | Использует In-Memory счетчики (Redis) для блокировки IP-адресов и фингерпринтов (Rate Limiting, Throttling), защищая инфраструктуру от брутфорса и DDoS. |

# 5. Локальный Аудит Доступа (Local Access Audit)

Группа алгоритмов, обеспечивающая выполнение концепции Zero Trust и сбор юридически значимых доказательств (Compliance) для расследования инцидентов информационной безопасности.

| **Название алгоритма** | **Краткое описание** |
| :--- | :--- |
| **Алгоритм иммутабельного журналирования (WORM Audit)** | Гарантирует синхронную запись критических событий (Login, Context Switch, Impersonation) в Append-Only таблицу без возможности удаления или изменения. |
| **Алгоритм инъекции бизнес-заголовков (Header Routing)** | Формирует доверенные HTTP-заголовки (например, `X-Global-Actor-Id`, `X-Workspace-Id`) на границе API Gateway для передачи контекста во внутренние сервисы Платформы. |
