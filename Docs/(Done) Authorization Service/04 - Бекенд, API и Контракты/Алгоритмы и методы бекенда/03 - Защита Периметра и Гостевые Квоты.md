# Введение

Группа алгоритмов защиты периметра и гостевых квот — это первая линия обороны микросервиса авторизации (и платформы в целом). Эти алгоритмы работают на самых ранних стадиях обработки HTTP-запроса, до того, как запрос попадет в слой бизнес-логики.

Их основная задача — предотвратить угон сессий (Session Hijacking) за счет отслеживания цифровых отпечатков (Device Fingerprint) и IP-адресов, обеспечить безопасный механизм анонимного (гостевого) доступа к платформе с жесткими лимитами, а также защитить API от атак перебором (Brute Force) и DDoS на уровне приложения с помощью многоуровневого лимитирования запросов (Rate Limiting и Fail2Ban).

# 1. Список алгоритмов защиты периметра

В данном разделе представлены алгоритмы, отвечающие за безопасность сессий, управление гостевыми аккаунтами и защиту от спам-запросов.

| **Название алгоритма** | **Краткое описание** |
| :--- | :--- |
| **Алгоритм защиты от угона сессий (Session Hijacking)** | При каждом запросе сверяет текущий IP-адрес и Device Fingerprint клиента с теми, что были зафиксированы при создании сессии. При несовпадении немедленно инвалидирует сессию. |
| **Алгоритм выдачи и конвертации гостевых сессий** | Управляет временными анонимными сессиями (`guest_sessions`) с привязкой к устройству (предотвращение абуза квот) и обеспечивает их "бесшовную" конвертацию (Merge) в полноценные аккаунты после OIDC-логина. |
| **Алгоритм многоуровневого лимитирования (Local Firewall)** | Реализует паттерн Token Bucket в Redis для ограничения частоты запросов (Rate Limiting) по IP/Fingerprint и автоматическое помещение нарушителей в локальный "черный список" (Fail2Ban). |

# Алгоритм защиты от угона сессий (Session Hijacking)

## Контекст и область применения

### Почему был создан

Даже при использовании защищенных (Secure, HttpOnly) Cookie с Phantom Token, существует риск кражи сессии (например, вредоносным ПО на компьютере пользователя или при атаках типа Man-in-the-Middle в публичных сетях). Алгоритм защиты от угона минимизирует этот риск, "привязывая" сессию к физическим характеристикам клиента (IP-адрес и уникальный отпечаток устройства - Fingerprint).

### Бизнес-требование

Система должна гарантировать, что сессия не может быть использована с другого устройства или из другой сети без повторной авторизации (SR-AUTH-SQ-01).

### Область применения

| **№** | **Описание** |
| :--- | :--- |
| **1** | Любой входящий HTTP-запрос к API платформы, требующий авторизации. |
| **2** | Операции обновления сессии (Silent Refresh). |

### Ограничения применения

| **№** | **Описание** |
| :--- | :--- |
| **1** | В мобильных сетях IP-адрес может часто меняться (при переключении вышек связи). Для таких случаев алгоритм должен иметь настраиваемую толерантность к смене IP (например, проверка только по подсети или опираться преимущественно на Fingerprint). |

## Входные данные

| **Параметр** | **Тип данных** | **Описание** | **Ограничения** | **Обязательность** |
| :--- | :--- | :--- | :--- | :--- |
| `CurrentIpAddress` | `string` | IP-адрес текущего запроса | Должен извлекаться из заголовка `X-Forwarded-For` (если за Proxy) | Да |
| `CurrentFingerprint` | `string` | Отпечаток браузера/устройства из заголовка `X-Device-Fingerprint` | Хэш (MD5/SHA256) | Да |
| `SessionMetadata` | `SessionDataDto` | Метаданные сессии, извлеченные из Redis | Должны содержать оригинальные IP и Fingerprint | Да |

## Выходные данные

| **Параметр** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `ValidationResult` | `bool` | `true`, если проверка пройдена, иначе генерируется исключение безопасности (Session Invalidated) |

## Логика работы (Псевдокод)

```csharp
public bool ValidateSessionEnvironment(HttpRequest request, SessionDataDto sessionFromRedis)
{
    // 1. Извлекаем текущие параметры окружения клиента
    string currentIp = GetClientIpAddress(request);
    string currentFingerprint = request.Headers["X-Device-Fingerprint"].FirstOrDefault();

    bool isSuspicious = false;
    string violationReason = string.Empty;

    // 2. Строгая проверка отпечатка устройства (Device Fingerprint)
    // Если отпечаток передан, но не совпадает с тем, с которого был логин - это 100% угон
    if (!string.IsNullOrEmpty(currentFingerprint) && 
        sessionFromRedis.OriginalDeviceFingerprint != currentFingerprint)
    {
        isSuspicious = true;
        violationReason = "FINGERPRINT_MISMATCH";
    }

    // 3. Проверка изменения IP-адреса
    // Если IP изменился, проверяем политику безопасности (настраивается для каждого инстанса)
    if (!isSuspicious && sessionFromRedis.OriginalIpAddress != currentIp)
    {
        bool isMobileNetwork = IsIpInMobileRanges(currentIp); // Проверка по GeoIP/ASN базе

        if (_securitySettings.StrictIpBinding && !isMobileNetwork)
        {
            // В строгом режиме любое изменение IP вне мобильных сетей - это угон
            isSuspicious = true;
            violationReason = "IP_ADDRESS_MISMATCH";
        }
        else if (_securitySettings.SubnetBindingOnly && !isMobileNetwork)
        {
            // Менее строгий режим: проверяем совпадение только первых октетов (подсети /24)
            if (!AreInSameSubnet(sessionFromRedis.OriginalIpAddress, currentIp, 24))
            {
                isSuspicious = true;
                violationReason = "SUBNET_MISMATCH";
            }
        }
    }

    // 4. Реакция на нарушение
    if (isSuspicious)
    {
        // Немедленная инвалидация сессии (удаление из Redis)
        RevokeSession(sessionFromRedis.SessionId, "HIJACK_DETECTED");
        
        // Запись в WORM Audit (Критическое событие безопасности)
        LogSecurityAlert(sessionFromRedis.GlobalSteosId, violationReason, currentIp, currentFingerprint);
        
        throw new SecurityException($"Session environment validation failed: {violationReason}");
    }

    return true; // Сессия валидна
}
```

# Алгоритм выдачи и конвертации гостевых сессий

## Контекст и область применения

### Почему был создан

Для снижения барьера входа Платформа должна позволять пользователям начинать работу (создавать проекты, заполнять данные) без предварительной регистрации ("Гостевой режим"). Однако гостевые ресурсы потребляют серверные мощности. Алгоритм решает две задачи: 1) привязывает анонима к `device_fingerprint` для предотвращения массовой регистрации ботами (абуз квот), 2) переносит накопленные гостевые данные в полноценный аккаунт, если гость решил зарегистрироваться (бесшовная конвертация).

### Бизнес-требование

Система должна поддерживать гостевые сессии с лимитированным временем жизни (TTL) и обеспечивать миграцию данных (Merge) при успешной OIDC-авторизации (SR-AUTH-SM-03 / SR-AUTH-SQ-02).

### Область применения

| **№** | **Описание** |
| :--- | :--- |
| **1** | Инициализация работы неавторизованного пользователя (нажатие "Попробовать бесплатно"). |
| **2** | OIDC Callback (возврат после успешной регистрации/авторизации из гостевого режима). |

## Логика работы (Псевдокод)

Алгоритм разбит на инициализацию гостя и последующую конвертацию.

```csharp
// ЧАСТЬ 1: ИНИЦИАЛИЗАЦИЯ (POST /api/auth/guest/start)
public async Task<GuestSessionResultDto> StartGuestSessionAsync(string deviceFingerprint)
{
    // 1. Защита от спама: Проверяем, сколько активных гостевых сессий висит на этом Fingerprint
    // Redis (O(1)) - предотвращаем создание фермы ботов с одного устройства
    long activeGuestsOnDevice = await _redisDatabase.SetLengthAsync($"guest_tracking:{deviceFingerprint}");
    
    if (activeGuestsOnDevice >= _guestSettings.MaxGuestsPerDevice)
    {
        throw new DomainException("GUEST_QUOTA_EXCEEDED_FOR_DEVICE");
    }

    // 2. Создаем теневого пользователя (Shadow User)
    Guid guestSteosId = Guid.NewGuid(); // Имитация STEOS ID
    Guid guestSessionId = Guid.NewGuid();

    // 3. Формируем метаданные гостевой сессии
    var guestSessionData = new SessionDataDto
    {
        SessionId = guestSessionId,
        GlobalSteosId = guestSteosId,
        IsGuest = true,
        DeviceFingerprint = deviceFingerprint,
        Roles = new[] { "Guest" } // Жестко ограниченная роль
    };

    // 4. Сохраняем в Redis с жестким TTL (например, 24 часа). 
    // Гостевые сессии НЕ сохраняются в PostgreSQL (эфемеридны)
    TimeSpan guestTtl = TimeSpan.FromHours(24);
    await _redisDatabase.StringSetAsync(
        $"steos:sess:{guestSessionId}", 
        JsonSerializer.Serialize(guestSessionData), 
        guestTtl
    );

    // Добавляем в Set отслеживания (с тем же TTL)
    await _redisDatabase.SetAddAsync($"guest_tracking:{deviceFingerprint}", guestSessionId.ToString());
    await _redisDatabase.KeyExpireAsync($"guest_tracking:{deviceFingerprint}", guestTtl);

    // 5. Отправляем HttpOnly Cookie (аналогично Phantom Token)
    SetHttpOnlyCookie("steos_session", guestSessionId.ToString(), guestTtl);

    return new GuestSessionResultDto { GuestSteosId = guestSteosId, ExpiresAt = DateTime.UtcNow.Add(guestTtl) };
}

// ЧАСТЬ 2: БЕСШОВНАЯ КОНВЕРТАЦИЯ (Во время OIDC Callback)
public async Task ConvertGuestToAuthenticatedUserAsync(string guestSessionIdStr, Guid realGlobalSteosId)
{
    // 1. Ищем гостевую сессию в Redis
    string guestSessionJson = await _redisDatabase.StringGetAsync($"steos:sess:{guestSessionIdStr}");
    if (string.IsNullOrEmpty(guestSessionJson)) return; // Гостем не был или TTL истек

    var guestSession = JsonSerializer.Deserialize<SessionDataDto>(guestSessionJson);
    if (!guestSession.IsGuest) return; // Защита: это уже не гость

    Guid shadowGuestId = guestSession.GlobalSteosId;

    // 2. Отправляем асинхронное событие в RabbitMQ (Merge Request)
    // Все остальные микросервисы (Workspace, Task, CRM) слушают это событие
    // и меняют владельца ресурсов (owner_id = shadowGuestId -> owner_id = realGlobalSteosId)
    var mergeEvent = new GuestMergeEventDto
    {
        ShadowGuestSteosId = shadowGuestId,
        RealGlobalSteosId = realGlobalSteosId,
        MergedAt = DateTime.UtcNow
    };
    
    await _eventBus.PublishAsync("platform.auth.guest_merged", mergeEvent);

    // 3. Уничтожаем гостевую сессию в Redis (очищаем мусор)
    await _redisDatabase.KeyDeleteAsync($"steos:sess:{guestSessionIdStr}");
    await _redisDatabase.SetRemoveAsync($"guest_tracking:{guestSession.DeviceFingerprint}", guestSessionIdStr);
    
    // Пользователь получает новую, полноценную сессию (Phantom Token) в конце OIDC Flow
}
```

# Алгоритм многоуровневого лимитирования (Local Firewall)

## Контекст и область применения

### Почему был создан

Открытые API (даже внутренние) подвержены риску перебора паролей (Brute Force), скрапинга данных (Scraping) и DDoS-атак уровня приложения (L7). Так как Authorization Service часто выступает публичной точкой входа (Login, Registration, Password Reset), он обязан иметь локальный защитный периметр, не дожидаясь реакции внешнего WAF (Web Application Firewall).

### Бизнес-требование

Система должна ограничивать количество запросов к критичным эндпоинтам (Rate Limiting) на базе IP-адресов и Device Fingerprint, а также временно блокировать нарушителей (Fail2Ban) (SR-AUTH-SQ-04 / SR-AUTH-SQ-03).

### Область применения

| **№** | **Описание** |
| :--- | :--- |
| **1** | Попытки авторизации (`POST /api/auth/login`). |
| **2** | Запросы на сброс пароля или получение одноразовых кодов. |
| **3** | Любые высоконагруженные эндпоинты, определенные конфигурацией. |

## Логика работы (Псевдокод)

Алгоритм реализует паттерн Token Bucket с использованием атомарных операций Redis (Lua-скрипты) для максимальной производительности.

```csharp
public async Task<bool> IsRequestAllowedAsync(string endpointName, string clientIp, string fingerprint)
{
    // 1. Проверка Fail2Ban (Локальный черный список)
    // O(1) проверка в Redis
    bool isBannedIp = await _redisDatabase.KeyExistsAsync($"ban:ip:{clientIp}");
    bool isBannedFingerprint = !string.IsNullOrEmpty(fingerprint) && 
                               await _redisDatabase.KeyExistsAsync($"ban:fingerprint:{fingerprint}");
                               
    if (isBannedIp || isBannedFingerprint)
    {
        // Немедленный отказ без обработки логики
        throw new HttpResponseException(HttpStatusCode.Forbidden, "YOUR_ACCESS_IS_TEMPORARILY_BLOCKED");
    }

    // 2. Rate Limiting (Алгоритм Token Bucket / Sliding Window)
    // Формируем уникальный ключ корзины: "rl:<endpoint>:<ip>"
    string bucketKey = $"rl:{endpointName}:{clientIp}";
    
    // Получаем лимиты из конфигурации для этого эндпоинта (например, 5 попыток в минуту для логина)
    var limits = _rateLimitConfig.GetLimitsFor(endpointName);

    // Выполняем атомарный Lua-скрипт в Redis (чтобы избежать Race Condition)
    // Скрипт: Инкрементирует счетчик, устанавливает TTL, если счетчик новый
    // Возвращает текущее значение счетчика
    long currentRequests = (long)await _redisDatabase.ScriptEvaluateAsync(
        TokenBucketLuaScript, 
        new { keys = new[] { bucketKey }, argv = new[] { limits.WindowSeconds.ToString() } }
    );

    // 3. Анализ результата
    if (currentRequests > limits.MaxRequests)
    {
        // Превышен лимит (Rate Limited - HTTP 429 Too Many Requests)
        
        // 4. Эвристика Fail2Ban
        // Если пользователь "долбит" API даже после HTTP 429, помещаем его в бан
        long blockThreshold = limits.MaxRequests * 3; // В 3 раза больше лимита = явный Brute Force
        
        if (currentRequests >= blockThreshold)
        {
            // Блокируем IP на 1 час
            await _redisDatabase.StringSetAsync($"ban:ip:{clientIp}", "BRUTE_FORCE_DETECTED", TimeSpan.FromHours(1));
            
            // Запись в WORM Audit
            await _auditLogger.LogSecurityAlertAsync(null, "FAIL2BAN_TRIGGERED", clientIp, fingerprint);
            
            throw new HttpResponseException(HttpStatusCode.Forbidden, "YOUR_ACCESS_IS_TEMPORARILY_BLOCKED");
        }

        // Обычный Rate Limit
        throw new HttpResponseException(HttpStatusCode.TooManyRequests, "RATE_LIMIT_EXCEEDED");
    }

    // Запрос разрешен
    return true;
}
```
