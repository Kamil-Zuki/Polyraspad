# Введение

Данная группа REST API методов предназначена для генерации короткоживущих (Burn-after-Read) токенов, называемых «Одноразовые билеты» (One-Time Tickets). Эти билеты позволяют преодолеть архитектурные ограничения протоколов, где невозможно передать Phantom Cookie или HTTP-заголовки аутентификации напрямую (например, при загрузке файлов браузером через тег `<img src="">` или при инициализации `WebSocket (WSS)` соединения из SPA).

Группа методов абстрагирует сложность криптографии билетов от клиентов, гарантируя, что каждый сгенерированный билет будет использован строго один раз для заранее определенной цели (Intent).

# 1. Список эндпоинтов

Ниже приведен список методов REST API для генерации и проверки билетов.

| Код требования | Метод | Эндпоинт                | Назначение                                                                                         |
| :------------- | :---: | :---------------------- | :------------------------------------------------------------------------------------------------- |
| SR-AUTH-OT-01  | POST  | `/tickets`              | Базовая генерация одноразового билета с указанием цели (Intent) и ID ресурса.                      |
| SR-AUTH-OT-02  | POST  | `/tickets/validate`     | HTTP-эндпоинт для проверки билета внешними шлюзами (если недоступен gRPC).                         |
| SR-AUTH-OT-03  | POST  | `/tickets/download-url` | Утилитарный метод быстрой сборки готового URL (с билетом в Query) для скачивания приватного файла. |
| SR-AUTH-OT-03  | POST  | `/tickets/ws-url`       | Утилитарный метод сборки WSS-ссылки с билетом в протоколе для открытия защищенного сокета.         |

# SR-AUTH-OT-01: Генерация одноразового билета: Generate Ticket

## Общая информация

Основной метод, который вызывается фронтендом (SPA) *перед* выполнением целевого действия. Клиент отправляет запрос, аутентифицированный Phantom Cookie, и просит Auth Service создать временный токен для конкретной задачи (например, `download_invoice`).

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса** | TicketCreateRequestDto |
| **DTO успешного ответа** | TicketResponseDto |

## Параметры URL

Параметры отсутствуют (все настройки передаются в теле JSON).

## Логика обработки запроса

*   BFF проверяет Phantom Cookie и валидирует тело `TicketCreateRequestDto` (intent, resource).
*   BFF вызывает gRPC [`IssueTicket`](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md#grpc-IssueTicket).
*   Клиенту возвращается `TicketResponseDto`.

## Успешный ответ

```json
{
  "success": true,
  "data": {
    "ticket": "tkt_8f2b...",
    "expiresIn": 60,
    "intent": "download_invoice"
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **400 Bad Request** | Не указана обязательная цель (Intent) билета. |
| **401 Unauthorized** | Вызывающий клиент не аутентифицирован. |

# SR-AUTH-OT-02: Валидация и "Гашение" билета: Validate

## Общая информация

Внутренний эндпоинт, используемый другими микросервисами или API Gateway (Edge Proxy) для проверки предъявленного пользователем билета. В идеале сервисы платформы используют gRPC [`ValidateTicket`](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md#grpc-ValidateTicket), но этот REST-эндпоинт оставлен для интеграции со сторонними или Legacy системами (например, Nginx с `auth_request`).

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса** | TicketValidateRequestDto |
| **DTO успешного ответа** | TicketValidateResponseDto (с контекстом пользователя) |

## Параметры URL

Параметры отсутствуют.

## Логика обработки запроса

*   BFF (или edge) принимает тело с билетом и ожидаемым intent.
*   BFF вызывает gRPC [`ValidateTicket`](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md#grpc-ValidateTicket).
*   При успехе возвращается контекст для downstream (`TicketValidateResponseDto`).

## Успешный ответ

```json
{
  "success": true,
  "data": {
    "userId": "usr_9982",
    "workspaceId": "ws_alpha_1",
    "roles": ["admin"],
    "intent": "download_invoice",
    "resourceId": "file_8829"
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **403 Forbidden** | Билет недействителен (уже погашен) или истек его срок жизни (TTL 60 сек). |
| **409 Conflict** | Несовпадение ожидаемой цели (Intent) билета с запрошенной. |

# SR-AUTH-OT-03: Генерация URL скачивания: Download URL

## Общая информация

"Умный" метод-хэлпер для фронтенда. Вместо того чтобы SPA самостоятельно генерировал билет (через `/tickets`), а затем вручную приклеивал его в Query-параметр ссылки на файл, клиент может передать ID файла и базовый URL сюда. Auth Service сам создаст билет и вернет готовую полную ссылку.

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса** | TicketCreateRequestDto (с `target_url` и `resource_id`) |
| **DTO успешного ответа** | FileDownloadUrlDto |

## Параметры URL

Параметры отсутствуют.

## Логика обработки запроса

*   BFF аутентифицирует пользователя по Cookie и передаёт `target_url`, `resource_id` и intent скачивания.
*   BFF вызывает gRPC [`BuildFileDownloadUrl`](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md#grpc-BuildFileDownloadUrl) — выпуск билета и сборка URL в одном шаге.
*   Клиент получает готовый `FileDownloadUrlDto`.

## Успешный ответ

```json
{
  "success": true,
  "data": {
    "url": "https://api.steos.com/storage/files/invoice_102.pdf?ticket=tkt_8f2b...",
    "expiresIn": 60
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **400 Bad Request** | Не указан базовый `target_url` для сборки. |

# SR-AUTH-OT-03: Генерация WSS-адреса: WebSocket URL

## Общая информация

Аналогичный предыдущему метод-хэлпер, но предназначенный для установления соединения с микросервисами реального времени (например, Platform Service WebSockets или Notification Service). Так как WSS-клиенты в браузере не могут передавать кастомные HTTP-заголовки, билет встраивается прямо в субпротокол (Subprotocol) или URL подключения.

| Тип метода | POST |
| :--- | :--- |
| **DTO запроса** | TicketCreateRequestDto (с `intent="websocket_connect"`) |
| **DTO успешного ответа** | WsConnectUrlDto |

## Параметры URL

Параметры отсутствуют.

## Логика обработки запроса

*   BFF проверяет сессию и тело с intent `websocket_connect` (и параметрами целевого realtime-шлюза).
*   BFF вызывает gRPC [`BuildWsConnectUrl`](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md#grpc-BuildWsConnectUrl).
*   Возвращается `WsConnectUrlDto` с готовой `wsUrl` и подсказкой по subprotocol.

## Успешный ответ

```json
{
  "success": true,
  "data": {
    "wsUrl": "wss://realtime.steos.com/v1/socket?ticket=tkt_9x1c...",
    "protocol": "steos-auth-v1",
    "expiresIn": 30
  }
}
```

## Ошибки

| Статус-код | Описание ошибки |
| :--- | :--- |
| **401 Unauthorized** | Отсутствует активная сессия для генерации билета. |
