# Введение

Данная группа gRPC-методов реализует слой Compliance и наблюдаемости (Observability) для микросервиса Authorization Service. В соответствии с концепцией WORM (Write Once, Read Many), все критические изменения состояния безопасности (создание сессий, отзыв, смена ролей, имперсонация) фиксируются в иммутабельных базах данных (PostgreSQL Audit Log).

Методы этой группы предоставляют высокопроизводительный, безопасный и стандартизированный (для интеграции с SIEM-системами вроде Splunk/ELK) доступ к сырым логам и аналитике, а также реализуют механизмы ручного разрешения инцидентов ИБ.

Важно: упоминаемые ниже SIEM-системы, объектные хранилища и внешние консьюмеры являются отдельными интеграциями или внешними системами. Они не реализуются в рамках данной документации `Authorization Service`; здесь фиксируются только контракты и поведение `Authorization Service` при работе с ними.

# SR-AUTH-LA-01: Поиск в журнале аудита: QueryAccessLogs

## Общая информация

**Источник требования:** [[01 - Функциональная спецификация/Возможности сервиса/04 - Локальный Аудит Доступа - Local Access Audit#SR-AUTH-LA-01: Журнал Локального Доступа (WORM)]]

Основной метод административной панели платформы для просмотра истории действий пользователей (кто, откуда, когда и зачем). Позволяет специалистам поддержки и ИБ-аналитикам отслеживать цепочки событий безопасности. Фильтры и форма строк списка в JSON на BFF — [06 - Аудит и безопасность (DTO)](../DTO/06%20-%20Аудит%20и%20безопасность%20(Audit%20&%20Security).md).

| Сигнатура             | `rpc QueryAccessLogs(QueryAccessLogsRequest) returns (QueryAccessLogsResponse)`        |
| :-------------------- | :---------------------------------------------------------------------------------------------- |
| **Сообщение запроса** | `QueryAccessLogsRequest` (временные рамки, типы событий, IP, Actor ID, Target ID, limit/offset)       |
| **Сообщение ответа**  | `QueryAccessLogsResponse` (`repeated AuditLogEvent`, `total_count`) |

## Логика обработки запроса

1. Проверить, что вызывающий субъект действительно имеет право читать локальный WORM-аудит.
2. Нормализовать фильтры запроса: период, actor, workspace, тип события, IP и другие поля.
3. Построить выборку к `access_audit_logs` и связанным представлениям без нарушения append-only характера журнала.
4. Выполнить пагинацию и устойчивую сортировку результата для повторяемого расследования.
5. Замаскировать чувствительные поля в соответствии с моделью прав конкретного аудитора.

## Статус-коды gRPC при ошибках

| Статус-код | Описание ошибки |
| :--- | :--- |
| **PERMISSION_DENIED** | Отсутствуют права на чтение WORM-аудита платформы. |
| **INVALID_ARGUMENT** | Некорректно заданы диапазоны дат или размер страницы (Limit > 1000). |

# SR-AUTH-LA-06: Детализация лога аудита: GetAuditLogDetails

## Общая информация

**Источник требования:** [[01 - Функциональная спецификация/Возможности сервиса/04 - Локальный Аудит Доступа - Local Access Audit#SR-AUTH-LA-06: Детализация события аудита]]

Дополняет `QueryAccessLogs`. Так как списочный запрос может возвращать тысячи строк с базовыми метаданными, этот метод позволяет запросить "тяжелый" JSONB-контекст конкретного инцидента (состояние объекта до изменения, состояние после изменения, номер тикета саппорта).

| Сигнатура | `rpc GetAuditLogDetails(GetAuditLogDetailsRequest) returns (GetAuditLogDetailsResponse)` |
| :--- | :--- |
| **Сообщение запроса** | `GetAuditLogDetailsRequest` (ID события `event_id`) |
| **Сообщение ответа** | `GetAuditLogDetailsResponse` (макроконтекст: состояния до/после, trace; JSON-форма — [06 - DTO](../DTO/06%20-%20Аудит%20и%20безопасность%20(Audit%20&%20Security).md)) |

## Логика обработки запроса

1. Проверить, что вызывающий субъект имеет право читать расширенный макроконтекст конкретного события.
2. Выбрать каноническую запись из `access_audit_logs` и связанный metadata-контекст по `event_id`.
3. Десериализовать поля `before/after`, actor, trace и reason в поля ответа `GetAuditLogDetailsResponse`.
4. Вернуть расширенную карточку инцидента без какого-либо изменения исходной WORM-записи.

## Статус-коды gRPC при ошибках

| Статус-код | Описание ошибки |
| :--- | :--- |
| **NOT_FOUND** | Событие с таким ID не существует. |

# SR-AUTH-LA-04: Стрим логов для SIEM: StreamAccessLogs

## Общая информация

**Источник требования:** [[01 - Функциональная спецификация/Возможности сервиса/04 - Локальный Аудит Доступа - Local Access Audit#SR-AUTH-LA-04: Потоковая передача WORM-аудита в SIEM]]

Метод Enterprise-класса (Server Streaming), предназначенный для интеграции Платформы с внешними Security Information and Event Management (SIEM) решениями (например, Splunk, Elastic, Datadog). Он открывает долгоживущее HTTP/2 (gRPC) соединение, в которое Auth Service "пушит" каждое новое событие безопасности в реальном времени.

| Сигнатура | `rpc StreamAccessLogs(StreamAccessLogsRequest) returns (stream AuditLogEvent)` |
| :--- | :--- |
| **Сообщение запроса** | `StreamAccessLogsRequest` (фильтр минимального уровня серьезности `min_severity`, например, только `CRITICAL` и `WARNING`) |
| **Сообщение ответа** | `stream AuditLogEvent` (непрерывный поток иммутабельных событий) |

## Логика обработки запроса

1. Проверить M2M-контекст клиента и его право на получение потокового аудита.
2. Подписать gRPC-обработчик на внутренний канал публикации уже зафиксированных WORM-событий.
3. Передавать в стрим только те события, которые уже успешно записаны в локальный аудит.
4. Сериализовать каждое новое событие в сообщение `AuditLogEvent` и отправлять его внешнему консьюмеру почти в реальном времени.
5. При обрыве соединения или остановке клиента корректно закрыть стрим без утечки ресурсов.

## Статус-коды gRPC при ошибках

| Статус-код | Описание ошибки |
| :--- | :--- |
| **UNAUTHENTICATED** | Для открытия стрима требуется M2M токен с правами SIEM-интеграции. |
| **DEADLINE_EXCEEDED** | Сервер принудительно разорвал соединение (плановый рестарт). |

# SR-AUTH-LA-05: Выгрузка архива: ExportAuditArchive

## Общая информация

**Источник требования:** [[01 - Функциональная спецификация/Возможности сервиса/04 - Локальный Аудит Доступа - Local Access Audit#SR-AUTH-LA-05: Экспорт архива аудита]]

Метод для регуляторного комплаенса (Compliance). ИБ-офицеры периодически обязаны выгружать срезы журналов безопасности (напр., "Все логи за 1 квартал 2026 года") для аудита внешними регуляторами (PCI-DSS, SOC2).

| Сигнатура | `rpc ExportAuditArchive(ExportArchiveRequest) returns (ExportArchiveResponse)` |
| :--- | :--- |
| **Сообщение запроса** | `ExportArchiveRequest` (диапазон дат, формат выгрузки `CSV`, `JSONL`) |
| **Сообщение ответа** | `ExportArchiveResponse` (идентификатор задачи экспорта, статус и опциональная временная ссылка на готовый архив) |

## Логика обработки запроса

1. Проверить диапазон дат, формат выгрузки и полномочия инициатора.
2. Создать фоновую задачу экспорта и сразу вернуть клиенту ее идентификатор или текущий статус.
3. В фоне считать нужные записи из `access_audit_logs`, сформировать архив, посчитать checksum/подпись и сохранить артефакт в защищенное хранилище.
4. После завершения задачи опубликовать временную ссылку на готовый архив.
5. Вернуть клиенту либо готовую ссылку, либо статус задачи, которую нужно опросить повторно.

## Статус-коды gRPC при ошибках

| Статус-код | Описание ошибки |
| :--- | :--- |
| **RESOURCE_EXHAUSTED** | Запрос архива за слишком большой период (свыше года), необходимо сузить диапазон. |
| **INTERNAL** | Сбой загрузки в объектное хранилище S3. |

# SR-AUTH-LA-05: Статус задачи экспорта: GetExportArchiveJobStatus

## Общая информация

Дополняет `ExportAuditArchive`: асинхронная выгрузка возвращает `job_id`; BFF опрашивает готовность по этому RPC (паритет REST `GET /audit/export-jobs/{jobId}`). Поля запроса/ответа в JSON — [06 - Аудит и безопасность (DTO)](../DTO/06%20-%20Аудит%20и%20безопасность%20(Audit%20&%20Security).md).

| Сигнатура | `rpc GetExportArchiveJobStatus(GetExportArchiveJobStatusRequest) returns (GetExportArchiveJobStatusResponse)` |
| :--- | :--- |
| **Сообщение запроса** | `GetExportArchiveJobStatusRequest` (`job_id`, опционально инициатор для проверки прав) |
| **Сообщение ответа** | `GetExportArchiveJobStatusResponse` (статус `PENDING` / `RUNNING` / `SUCCEEDED` / `FAILED`; при успехе — presigned URL и время истечения ссылки) |

## Логика обработки запроса

1. Проверить, что вызывающий имеет право видеть статус данной задачи (сопоставить с создателем `ExportAuditArchive` или ролью ИБ).
2. Прочитать состояние фоновой задачи из PostgreSQL и/или Redis.
3. Если архив загружен в объектное хранилище (S3-совместимое), сгенерировать или вернуть кэшированный presigned URL; загрузка выполняется воркером Auth Service, **без** отдельного gRPC к Storage — используется SDK хранилища из процесса экспорта.
4. Вернуть актуальный статус; идемпотентность при повторных опросах.

## Статус-коды gRPC при ошибках

| Статус-код | Описание ошибки |
| :--- | :--- |
| **NOT_FOUND** | Задача с таким `job_id` не существует или принадлежит другому тенанту. |

# SR-AUTH-SQ-07: Управление инцидентами ИБ: QuerySecurityAlerts / ResolveSecurityAlert

## Общая информация

**Источник требования:** [[01 - Функциональная спецификация/Возможности сервиса/03 - Защита Периметра и Гостевые Квоты - Security Quotas#SR-AUTH-SQ-07: Алерты безопасности и обработка инцидентов]]

Два метода, образующие цикл обработки инцидентов (Incident Response). Автоматика Auth Service (или `ReportSuspiciousActivity`) генерирует алерты в хранилище; представление записей в JSON для BFF — [06 - DTO](../DTO/06%20-%20Аудит%20и%20безопасность%20(Audit%20&%20Security).md). Пользователь или администратор просматривает алерты (Query) и подтверждает (Resolve) устранение угрозы.

| Сигнатура | `rpc QuerySecurityAlerts(QuerySecurityAlertsRequest) returns (QuerySecurityAlertsResponse)` |
| :--- | :--- |
| **Сообщение запроса** | `QuerySecurityAlertsRequest` (фильтры, в т.ч. только неразрешённые) |
| **Сообщение ответа** | `QuerySecurityAlertsResponse` (`repeated SecurityAlert`, пагинация) |

| Сигнатура | `rpc ResolveSecurityAlert(ResolveAlertRequest) returns (ResolveAlertResponse)` |
| :--- | :--- |
| **Сообщение запроса** | `ResolveAlertRequest` (ID алерта, резолюция: `FALSE_POSITIVE`, `MITIGATED`) |
| **Сообщение ответа** | `ResolveAlertResponse` (статус успеха) |

## Логика обработки запросов

1. Для `QuerySecurityAlerts` проверить права и выполнить paginated-чтение из `security_alerts` с фильтрами по статусу, субъекту и `severity`.
2. Для `ResolveSecurityAlert` проверить допустимость перехода состояния и зафиксировать выбранную резолюцию (`MITIGATED`, `FALSE_POSITIVE` и т.д.).
3. Если инцидент закрыт как `FALSE_POSITIVE`, при необходимости скорректировать локальные эвристики защиты, не стирая историю исходного инцидента.
4. Зафиксировать любую резолюцию в WORM-аудите как отдельное административное действие.

## Статус-коды gRPC при ошибках

| Статус-код | Описание ошибки |
| :--- | :--- |
| **NOT_FOUND** | Попытка разрешить несуществующий или уже обработанный Alert. |

# SR-AUTH-LA-07: Аналитика безопасности: GetAuthStats

## Общая информация

**Источник требования:** [[01 - Функциональная спецификация/Возможности сервиса/04 - Локальный Аудит Доступа - Local Access Audit#SR-AUTH-LA-07: Агрегированная аналитика доступа]]

Метод для построения дашбордов (Dashboard) в панели управления платформы. Возвращает агрегированные числовые метрики, не требуя от клиента выкачивать сырые логи.

| Сигнатура | `rpc GetAuthStats(GetStatsRequest) returns (AuthStatsResponse)` |
| :--- | :--- |
| **Сообщение запроса** | `GetStatsRequest` (период, гранулярность по времени: `day`, `hour`) |
| **Сообщение ответа** | `AuthStatsResponse` (количество блокировок, активных сессий, гостевых пользователей, распределение OIDC провайдеров) |

## Логика обработки запроса

1. Проверить период, гранулярность и права на чтение агрегированной аналитики.
2. Считать оперативные показатели из Redis и других hot-state агрегатов активных сессий, блокировок и гостевых лимитов.
3. Если нужен исторический срез, построить агрегаты по `access_audit_logs` и связанным производным представлениям.
4. Собрать итоговую сводку по активным сессиям, блокировкам, гостевым квотам и событиям безопасности.

## Статус-коды gRPC при ошибках

*Стандартные HTTP/gRPC ошибки (UNAUTHENTICATED, PERMISSION_DENIED).*
