# Введение

Данный документ описывает структуры данных (DTO), относящиеся к группе "Управление гостевым доступом" (Guest Sessions). Эти объекты предназначены для реализации бесшовного пользовательского опыта (Seamless Onboarding), когда неавторизованный пользователь (гость) заходит на Платформу и начинает работу (например, в песочнице или публичном дашборде) до прохождения процедуры полноценной регистрации/авторизации (Lazy Registration).

Использование этих DTO позволяет выделять анонимным пользователям аппаратные идентификаторы, устанавливать им изолированные "теневые" сессии с жесткими ограничениями (Guest Quotas) и в дальнейшем конвертировать весь накопленный гостевой контекст (например, созданные проекты) в полноценный аккаунт после успешного логина через STEOS ID.

# 1. Список DTO

В таблице ниже перечислены DTO, обеспечивающие жизненный цикл гостевых сессий.

| **Название DTO** | **Назначение** |
| :--- | :--- |
| **GuestSessionCreateDto** | Запрос: Явная инициализация "теневой" сессии (Shadow Session) для неавторизованного пользователя. |
| **GuestSessionResponseDto** | Ответ: Метаданные созданной гостевой сессии (ID, квоты, TTL), аналогично `SessionDto`, но с пометкой гостя. |
| **ConvertGuestRequestDto** | Запрос: Инициирует процесс привязки накопленных данных гостевой сессии к новому авторизованному STEOS ID. |
| **GuestQuotaStatusDto** | Ответ: Текущее состояние лимитов (Rate Limits / Business Quotas) для гостевого пользователя. |
| **GuestSessionContextDto** | Ответ: Урезанный контекст для гостя, используемый фронтендом для адаптации UI. |
| **GuestMergeEventDto** | Ответ (Событие): Сообщение для RabbitMQ, информирующее микросервисы о конвертации гостя в авторизованного пользователя (`shadow_guest_id` -> `real_global_id`). |
| **GetGuestAccessStatusRequest** | Запрос: Идентификатор гостевой сессии (из Cookie/контекста) для опроса квот и TTL (`GetGuestAccessStatus`). |

# DTO: GuestSessionCreateDto

## Контекст и назначение

Объект используется Frontend-приложением для явного запроса на выделение гостевой сессии. Обычно это происходит при первом заходе пользователя на лендинг платформы или при попытке выполнить действие, доступное без регистрации (например, запустить демо-стенд). В ответ бэкенд создает в Redis изолированную сессию (с ролью `guest`) и устанавливает `Set-Cookie` с гостевым Phantom Token.

**Назначение:** Запрос (Инициализация).
**Реализация сущности:** Запись в Redis (Shadow Session).

## Структура данных

Включает метаданные устройства для антифрода и привязки сессии к конкретному браузеру/аппарату.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `deviceFingerprint` | `string` | Аппаратный отпечаток устройства (Client Hints, Canvas Hash, etc.) для предотвращения абуза (масс-регистрации). |
| `intent` | `string` | Опциональное поле, описывающее намерение гостя (например, `DEMO_WORKSPACE`, `PUBLIC_DASHBOARD`). |

## Пример работы (JSON)

Запрос фронтенда на выдачу гостевого доступа для демо-стенда.

```json
{
  "deviceFingerprint": "hash_guest_1a2b3c4d",
  "intent": "DEMO_WORKSPACE"
}
```

# DTO: GuestSessionResponseDto

## Контекст и назначение

Ответ сервера на успешное создание (или подтверждение) гостевой сессии. По своей структуре DTO похож на `SessionDto`, но не содержит ссылок на глобальный `userId` или реальный Workspace. Вместо этого он возвращает информацию о жестких временных рамках жизни "теневой" сессии и выделенном эфемерном ID.

**Назначение:** Ответ (Метаданные сессии).
**Реализация сущности:** Содержимое кэша Redis (гостевой профиль).

## Структура данных

Содержит идентификатор гостевой сессии, даты жизни и базовую информацию. Токен (Cookie) возвращается в заголовках.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `guestSessionId` | `uuid` | Временный (эфемерный) идентификатор гостя в системе. |
| `createdAt` | `datetime` | Время выделения гостевого доступа (UTC). |
| `expiresAt` | `datetime` | Жесткое время "сгорания" гостевой сессии (обычно 24-72 часа, без возможности продления). |
| `status` | `string` | Текущий статус сессии (`ACTIVE`, `EXPIRED`, `CONVERTED`). |

## Пример работы (JSON)

Пример ответа с метаданными выданной гостевой сессии.

```json
{
  "guestSessionId": "guest-uuid-1111-2222-3333",
  "createdAt": "2026-03-25T10:00:00Z",
  "expiresAt": "2026-03-28T10:00:00Z",
  "status": "ACTIVE"
}
```

# DTO: ConvertGuestRequestDto

## Контекст и назначение

Объект используется для запуска процесса конвертации (Lazy Registration). После того как гость успешно авторизовался через STEOS ID (получив `code` из OIDC Flow), фронтенд отправляет этот запрос (вместе с авторизационной Cookie гостя), чтобы бэкенд Auth Service "связал" старый эфемерный `guestSessionId` с новым реальным `userId`. В процессе конвертации Auth Service также публикует событие в RabbitMQ (`GuestConvertedEvent`), чтобы другие сервисы (Workspace, Task) могли перевесить созданные гостем ресурсы (сущности) на его новый постоянный аккаунт.

**Назначение:** Запрос (Миграция/Конвертация).
**Реализация сущности:** Событие `GuestConvertedEvent` и обновление БД.

## Структура данных

Содержит токены, необходимые для подтверждения успешного логина, и идентификатор старой гостевой сессии.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `guestSessionId` | `uuid` | Идентификатор теневой сессии, данные которой нужно перенести. |
| `oidcCode` | `string` | Authorization Code, полученный от STEOS ID в результате логина. |
| `preserveData` | `boolean` | Флаг, указывающий, нужно ли переносить данные (если false, гостевая сессия просто уничтожается, а создается чистая новая). |

## Пример работы (JSON)

Запрос на привязку демо-пространства гостя к его новому аккаунту после регистрации через Google.

```json
{
  "guestSessionId": "guest-uuid-1111-2222-3333",
  "oidcCode": "SplxlOBeZQQYbYS6WxSbIA",
  "preserveData": true
}
```

# DTO: GetGuestAccessStatusRequest

## Контекст и назначение

Запрос для RPC `GetGuestAccessStatus` и REST `GET /guests/status`: идентификация текущей гостевой сессии (Cookie или явный `guest_session_id` в теле/заголовке — по контракту Gateway).

**Назначение:** Запрос (опрос квот и TTL гостя).  
**Реализация:** Контекст вызова (Cookie/BFF) или явное поле в теле gRPC.

## Структура данных

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `guestSessionId` | `string` | Идентификатор гостевой сессии, если передаётся явно (иначе извлекается из контекста вызова). |

## Пример работы (JSON)

Явная передача идентификатора в теле gRPC (в REST идентификатор чаще берётся из Cookie без тела):

```json
{
  "guestSessionId": "guest-uuid-1111-2222-3333"
}
```

Пустое тело или отсутствие поля — идентификатор берётся из Cookie/контекста Gateway:

```json
{}
```

# DTO: GuestQuotaStatusDto

## Контекст и назначение

Этот DTO возвращается фронтенду для отображения пользователю прогресс-бара или предупреждений об исчерпании гостевых лимитов. Так как гостевые сессии подвержены риску абуза (DDoS, спам), им выделяются жесткие квоты на использование платформы (например, создание не более 3 проектов, выполнение не более 100 запросов API в час).

**Назначение:** Ответ (Состояние лимитов).
**Реализация сущности:** Счетчик Redis (Throttling / Quotas).

## Структура данных

Содержит текущие значения бизнес-квот и лимитов API.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `requestsRemaining` | `integer` | Количество оставшихся HTTP-запросов к API в текущем окне (Local Firewall / Rate Limit). |
| `quotaUsagePct` | `integer` | Процент использования бизнес-квот (например, 80% означает, что скоро потребуется авторизация). |
| `requiresVerification` | `boolean` | Флаг, указывающий, что гость исчерпал лимиты и должен быть перенаправлен на страницу входа/регистрации. |
| `activeQuotas` | `object` | Key-Value объект с конкретными бизнес-лимитами (например, `{"projects_created": 2, "max_projects": 3}`). |

## Пример работы (JSON)

Пример ответа со статусом квот для пользователя демо-стенда.

```json
{
  "requestsRemaining": 45,
  "quotaUsagePct": 66,
  "requiresVerification": false,
  "activeQuotas": {
    "projects_created": 2,
    "max_projects": 3,
    "storage_mb": 50,
    "max_storage_mb": 100
  }
}
```

# DTO: GuestSessionContextDto

## Контекст и назначение

Этот DTO представляет собой сильно урезанный аналог `SessionContextDto`, который возвращается фронтенду, когда пользователь находится в демо-режиме (теневая сессия). В отличие от полноправного контекста, он содержит только базовые данные, необходимые UI для переключения в "гостевой режим" (ограничение некоторых функций, баннеры с призывом к регистрации). 

**Назначение:** Ответ (Урезанное состояние контекста).
**Реализация сущности:** Таблица `session_contexts` или кэш.

## Структура данных

Включает только основные идентификаторы демо-режима.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `guestSessionId` | `uuid` | Временный идентификатор гостя. |
| `activeWorkspaceId` | `uuid` | ID созданного для гостя демо-пространства (песочницы). |
| `roles` | `array<string>` | Всегда содержит только роль `guest_viewer` или `guest_editor`. |
| `isGuest` | `boolean` | Флаг, явно указывающий UI, что это неполноценный аккаунт. |

## Пример работы (JSON)

Пример ответа с контекстом гостевой сессии.

```json
{
  "guestSessionId": "guest-uuid-1111-2222-3333",
  "activeWorkspaceId": "demo-ws-4242-8888",
  "roles": ["guest_editor"],
  "isGuest": true
}
```

# DTO: GuestMergeEventDto

## Контекст и назначение

Это сообщение (Событие), которое Authorization Service публикует в RabbitMQ после успешной конвертации гостевой сессии (Lazy Registration) через запрос `ConvertGuestRequestDto`. Оно предназначено для других микросервисов Платформы (например, Workspace Service, Task Service), чтобы они могли обновить свои базы данных, заменив временный `guestSessionId` в таблицах (владелец проектов, автор задач) на новый, постоянный `realUserId`. Это ключевой механизм "сшивания" (Merge) демо-опыта с реальным аккаунтом.

**Назначение:** Ответ (Событие RabbitMQ).
**Реализация сущности:** Сообщение в шине данных.

## Структура данных

Включает временные идентификаторы и новый целевой ID.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `eventId` | `uuid` | ID события миграции (идемпотентность). |
| `timestamp` | `datetime` | Время миграции данных. |
| `shadowGuestId` | `uuid` | Старый, эфемерный идентификатор гостя (подлежит замене везде). |
| `realGlobalId` | `uuid` | Новый, постоянный STEOS ID пользователя. |
| `targetWorkspaceId` | `uuid` | Демо-пространство (если есть), которое должно стать персональным. |

## Пример работы (JSON)

Событие конвертации в RabbitMQ.

```json
{
  "eventId": "merge-evt-8888-9999",
  "timestamp": "2026-03-25T11:00:00Z",
  "shadowGuestId": "guest-uuid-1111-2222-3333",
  "realGlobalId": "user-uuid-4444-5555-6666",
  "targetWorkspaceId": "demo-ws-4242-8888"
}
```
