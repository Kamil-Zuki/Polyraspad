# Введение

Настоящий документ содержит описание регламента работы с Redis микросервиса **Authorization Service**. В архитектуре безопасности Платформы Redis играет критическую роль In-Memory Data Grid, обеспечивая сверхбыстрый доступ к данным сессий, защиту от брутфорса (Rate Limiting), JIT-кэширование контекста, реализацию паттернов "Phantom Token" и "Zero Trust" (КАР-1, КАР-2), а также синхронизацию состояния между узлами кластера.

Цель документа — определить правила именования ключей (Key Naming Conventions), политики TTL (Time-To-Live) и механизмы инвалидации кэша, которые инженеры должны применять при разработке. Документ базируется на функциональных требованиях (SR-AUTH-xxx) и КАР.

# 1. Группы операций работы с Redis

Ниже представлена сводная информация по всем группам операций кэширования и управления состоянием в Redis.

| Группа | Описание |
| :--- | :--- |
| **Управление сессиями и Phantom Tokens** | Использование Redis как основного Session Store. Хранение активных токенов, Blacklist и состояния "двойной идентичности" (Impersonation). |
| **Защита периметра и Throttling** | Реализация паттернов Sliding Window и Token Bucket для Rate Limiting, защита от подбора паролей (Fail2Ban) и учет квот. |
| **Кэширование политик и Контекста** | JIT-кэширование RBAC-ролей, пермиссий, Geo-политик и API-ключей для минимизации нагрузки на базу данных. |
| **Одноразовые билеты и Интеграции** | Хранение короткоживущих данных (One-Time Tickets, OIDC State/Nonce, кэш JWKS ключей) для безопасных интеграций. |
| **Внутренние процессы и автоматизация** | Механизмы распределенных блокировок (Redlock), идемпотентности REST API и синхронизации WebSocket (SignalR Backplane). |

# 2. Управление сессиями и Phantom Tokens

Обеспечивает работу механизма Phantom Token (КАР-1) и позволяет мгновенно инвалидировать сессии без отзыва JWT.

| Метод (SR) | Описание операции |
| :--- | :--- |
| КАР-1 / SR-AUTH-SM-01 | Хранение и валидация активных Refresh-сессий пользователей. |
| КАР-1 / SR-AUTH-SM-04 | Хранение Blacklist (Черного списка) для отозванных токенов (до истечения их TTL). |
| КАР-6 / SR-AUTH-SM-05 | Хранение контекста Impersonation (God Mode) — кто под кем залогинен. |
| SR-AUTH-GQ-01 | Хранение эфемерных гостевых сессий с аппаратной привязкой. |

# 3. Защита периметра и Throttling (Rate Limiting)

Данная группа отвечает за обеспечение безопасности публичных API и защиту от DoS/DDoS-атак на уровне приложения.

| Метод (SR) | Описание операции |
| :--- | :--- |
| КАР-10 / SR-AUTH-SQ-04 | Rate Limiting (Sliding Window) для защиты эндпоинтов авторизации от брутфорса. |
| КАР-10 / SR-AUTH-SQ-03 | Fail2Ban: Временная блокировка IP-адресов при подозрительной активности. |
| SR-AUTH-SM-09 | Throttling и кэширование счетчиков ошибок MFA. |
| SR-AUTH-GQ-02 | Token Bucket: In-Memory счетчики API-запросов и лимитов потребления (Квот) для гостевых сессий перед сбросом в БД/RabbitMQ. |

# 4. Кэширование политик и Контекста (Zero Trust JIT)

Ускоряет вычисление прав доступа при проверке токенов (gRPC `ValidateToken`), реализуя концепцию Zero Trust (КАР-2) с минимальной задержкой.

| Метод (SR) | Описание операции |
| :--- | :--- |
| КАР-2 / SR-AUTH-AC-01 | JIT-кэширование (Just-In-Time) рассчитанных RBAC/ABAC ролей пользователя в воркспейсе. |
| SR-AUTH-AC-04 / SR-AUTH-M2M-01 | In-Memory кэширование хэшей валидных PAT (Personal Access Tokens) и M2M-токенов для быстрой валидации gRPC. |
| SR-AUTH-AC-05 | Кэширование Geo-политик (разрешенные IP/Страны) для Workspace. |
| SR-AUTH-SM-08 | Кэширование списка Доверенных Устройств (Trusted Devices) пользователя. |

# 5. Одноразовые билеты и Интеграции (Tickets & Infra)

Управляет короткоживущими транзакционными состояниями и кэшированием внешних OIDC ключей.

| Метод (SR) | Описание операции |
| :--- | :--- |
| КАР-5 / SR-AUTH-SM-04 | Хранение и валидация Эфемерных Одноразовых Билетов (One-Time Tickets) для загрузки файлов/WSS. |
| КАР-8 / SR-AUTH-OI-02 | In-Memory кэширование публичных ключей (JWKS) от глобального STEOS ID. |
| SR-AUTH-OI-01 | Хранение OIDC-параметров `state` и `nonce` для защиты от CSRF/Replay атак в процессе логина. |

# 6. Внутренние процессы и автоматизация

Группа критических инфраструктурных механизмов, обеспечивающих идемпотентность и консистентность распределенной системы.

| Метод (SR) | Описание операции |
| :--- | :--- |
| КАР-3 / SR-AUTH-WS-01 | SignalR Redis Backplane: Синхронизация WebSocket-событий между множеством подов (реплик) Authorization Service. |
| КАР-11 / SR-AUTH-LA-05 | Distributed Locks (Redlock): Распределенные блокировки для защиты фоновых выгрузок WORM-аудита и консьюмеров RabbitMQ от состояния гонки. |
| SR-AUTH-REST-01 | Idempotency Keys: Кэширование `Idempotency-Key` для защиты мутирующих REST API методов (например, слияние гостя) от случайных двойных списаний/вызовов. |
