# Введение

Данный документ описывает синхронную интеграцию по протоколу HTTP/REST с глобальным провайдером идентичности — **STEOS ID**. Эта интеграция является фундаментом безопасности Authorization Service. Она реализует защищенный обмен авторизационных кодов на OIDC-токены, а также механизмы фонового поддержания доверия (скачивание публичных ключей JWKS и тихое серверное продление сессий).

# Общая информация

Обеспечение OIDC-аутентификации, валидации подписей JWT и поддержания жизненного цикла сессий. Authorization Service выступает здесь как `Relying Party` (RP) или `OIDC Client`.

| Параметр | Описание |
| :--- | :--- |
| **Версия API** | OAuth 2.1 / OpenID Connect 1.0 |
| **Название сервиса** | STEOS ID (Глобальный провайдер идентичности) |
| **Официальная документация** | RFC 6749 (OAuth 2.0), OIDC Core 1.0 |
| **Владелец** | Core Identity Team |

# Доступ и аутентификация

Механизмы защиты Server-to-Server (S2S) взаимодействия между локальной Платформой и глобальным STEOS ID.

| Параметр | Описание |
| :--- | :--- |
| **Метод аутентификации** | Basic Authentication (`client_id` и `client_secret`) или mTLS для эндпоинта `/token`. Эндпоинт `/jwks.json` публичен. |
| **Хранение учетных данных** | `client_secret` хранится в **HashiCorp Vault** или Kubernetes Secrets и никогда не передается фронтенду. |
| **Среды (Environments)** | Разные `client_id` и `client_secret` для Prod, Stage и Dev окружений. |
| **Протокол** | Строго HTTPS (TLS 1.2+). |

# Ключевые методы HTTP/REST

Перечень S2S-вызовов к глобальному IdP для инициации и поддержки сессий.

| Метод | Описание | Использование в Authorization Service |
| :--- | :--- | :--- |
| `POST /oauth/token` (grant_type: authorization_code) | Обмен Authorization Code на Access, ID и Refresh токены. | Вызывается при возврате пользователя (Callback) с портала логина (**SR-AUTH-OI-01**). |
| `GET /.well-known/jwks.json` | Получение массива публичных ключей RSA (JSON Web Key Set). | Вызывается фоновым воркером для локального кэширования ключей проверки подписей (**SR-AUTH-OI-02**). |
| `POST /oauth/token` (grant_type: refresh_token) | Получение нового Access-токена в обмен на валидный Refresh-токен. | Вызывается асинхронно для "Тихого продления" локальной сессии пользователя (**SR-AUTH-SM-07**). |

# Логика обработки запросов

Правила взаимодействия с провайдером, включая стратегии кэширования и обеспечения отказоустойчивости.

*   **PKCE (Proof Key for Code Exchange):** При S2S-вызове `/token` обязательно передается `code_verifier`, сгенерированный локально до начала логина, для защиты от перехвата кода.
*   **Graceful Degradation (JWKS):** Локальный сервис кэширует ответ от `/.well-known/jwks.json` в памяти (In-Memory). Если STEOS ID временно падает, Authorization Service продолжает успешно валидировать JWT-токены пользователей силами процессора (CPU), используя кэш.
*   **Force Refresh JWKS:** При получении валидного на вид JWT-токена с неизвестным Key ID (`kid`), Auth Service делает синхронный форсированный вызов за свежим JWKS, предполагая, что произошла ротация ключей на стороне IdP.
*   **JIT-расшифровка:** `refresh_token` хранится в БД в зашифрованном виде. Он расшифровывается в оперативной памяти непосредственно за миллисекунды перед S2S-вызовом `/token` для тихого продления.

# Обработка ошибок

Реакция Authorization Service на отказы или технические сбои со стороны STEOS ID.

| Тип ошибки | Описание причины | Реакция сервиса |
| :--- | :--- | :--- |
| `invalid_grant` (при Authorization Code) | Код просрочен, использован дважды или не совпадает с `code_verifier`. | Возврат `400 Bad Request` фронтенду, прерывание флоу логина. Возможна атака Replay. |
| `invalid_grant` (при Refresh Token) | `refresh_token` отозван глобально, пользователь забанен или сменил пароль. | **Смерть сессии**. Локальная сессия в Redis немедленно удаляется, статус в БД меняется на `revoked`. Пользователь выкидывается из системы (`401 Unauthorized`). |
| `SERVICE_UNAVAILABLE` (при `/token`) | STEOS ID недоступен. | При логине — возврат `503 Service Unavailable`. При тихом продлении (Silent Refresh) — повторная попытка (Retry) через несколько минут (если локальный TTL еще позволяет). |
| `cache_miss_flood` (при JWKS) | Хакер шлет тысячи токенов со случайными `kid`. | Срабатывает защита от DDoS. Включается Rate Limiting на форсированное обновление JWKS (не чаще 1 раза в минуту). Запросы сверх лимита получают `401 Unauthorized`. |
