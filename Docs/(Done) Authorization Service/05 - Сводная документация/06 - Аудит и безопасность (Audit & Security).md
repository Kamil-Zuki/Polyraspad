# Введение

Данный документ описывает структуры данных (DTO), связанные с подсистемой Аудита и Безопасности. Они обеспечивают механизмы защиты от несанкционированного доступа, логирования критических событий (WORM Audit), анализа подозрительной активности (Session Hijacking) и предоставления администраторам инструментов для контроля за поведением пользователей. 

Использование этих DTO позволяет реализовать строгие корпоративные требования к ИБ, такие как неизменяемость журналов, алертинг на аномалии и проактивное управление рисками (Local Firewall).

# 1. Список DTO

В таблице ниже перечислены DTO, обеспечивающие функции аудита и безопасности.

| **Название DTO** | **Назначение** |
| :--- | :--- |
| **AuditLogEventDto** | Ответ: Запись неизменяемого журнала аудита (событие, актор, IP, изменения). |
| **AuditLogQueryDto** | Запрос: Параметры фильтрации и поиска по журналу безопасности (даты, типы событий, пользователи). |
| **SecurityAlertDto** | Ответ: Уведомление о подозрительной активности (например, вход с нового IP или подмена User-Agent). |
| **BlockListAddRequestDto** | Запрос: Внесение IP-адреса, подсети или отпечатка устройства в черный список (Local Firewall). |
| **ImpersonateRequestDto** | Запрос: Команда от сотрудника поддержки на запуск режима God Mode (Impersonation) с указанием причины (Ticket ID). |
| **GodModeContextDto** | Ответ: Специальный расширенный контекст сессии для режима имперсонации (инкапсулирует оригинального актора и целевого). |
| **ImpersonationStopRequestDto** | Запрос: Сигнал для принудительного и явного выхода из God Mode. |
| **AuditMacroContextDto** | Вложенный объект: JSON-структура для WORM логов, содержащая расширенный контекст события (TargetWorkspaceId, ImpersonatorId). |
| **RateLimitConfigDto** | Ответ/Запрос: Структура для получения и конфигурации лимитов (Token Bucket) защитного периметра (Fail2Ban). |
| **BlockListQueryDto** | Запрос: Фильтры и пагинация для `QueryBlocklist` (REST `GET /security/blocklist`). |
| **BlocklistEntryDto** | Ответ: Одна строка черного списка (IP или Fingerprint, причина, TTL). |
| **GetExportArchiveJobStatusRequest** | Запрос: Идентификатор задачи экспорта WORM (`job_id`). |
| **ExportArchiveJobStatusDto** | Ответ: Статус асинхронного экспорта и presigned URL при успехе. |

# DTO: AuditLogEventDto

## Контекст и назначение

Этот DTO представляет собой единичную запись в Иммутабельном Локальном Журнале Доступа (WORM Audit). Он возвращается администраторам или системам SIEM при запросе истории критических действий (кто, когда и откуда совершил авторизацию, смену ролей или попытку доступа к запрещенному ресурсу).

**Назначение:** Ответ (Справочник / Сущность).
**Реализация сущности:** Таблица `audit_logs` (append-only) или внешнее хранилище.

## Структура данных

Включает метаданные события, актора и снимок измененных данных (до/после).

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `eventId` | `uuid` | Уникальный идентификатор события аудита. |
| `timestamp` | `datetime` | Точное время фиксации события (UTC). |
| `eventType` | `string` | Стандартизированный код события (напр., `USER_LOGIN`, `ROLE_ASSIGNED`, `SESSION_REVOKED`). |
| `severity` | `string` | Уровень критичности (`INFO`, `WARNING`, `CRITICAL`). |
| `actorId` | `uuid` | Глобальный ID пользователя (или сервиса), инициировавшего действие. |
| `targetId` | `uuid` | ID субъекта или ресурса, над которым было совершено действие (опционально). |
| `ipAddress` | `string` | IP-адрес источника запроса. |
| `deviceFingerprint` | `string` | Отпечаток устройства (частично маскированный). |
| `metadata` | `object` | Произвольный JSON с деталями события (например, `{"reason": "support_ticket_123"}`). |

## Пример работы (JSON)

Пример записи об отзыве сессии администратором.

```json
{
  "eventId": "audit-uuid-1111-2222",
  "timestamp": "2026-03-25T14:30:15Z",
  "eventType": "SESSION_REVOKED",
  "severity": "WARNING",
  "actorId": "admin-uuid-4444",
  "targetId": "user-uuid-5555",
  "ipAddress": "192.168.1.10",
  "deviceFingerprint": "hash_xyz...",
  "metadata": {
    "sessionId": "session-uuid-9999",
    "reasonCode": "ADMIN_REVOKE",
    "comment": "Жалоба на подозрительную активность"
  }
}
```

# DTO: AuditLogQueryDto

## Контекст и назначение

Этот DTO используется для гибкого поиска и фильтрации записей в журнале аудита через панель управления безопасностью. Он расширяет стандартные параметры пагинации специфичными для ИБ критериями (периоды времени, типы событий, конкретные акторы или IP-адреса).

**Назначение:** Запрос (Фильтрация списка).
**Реализация сущности:** Параметры WHERE в SQL-запросе к `audit_logs`.

## Структура данных

Включает временные рамки и массивы фильтров. Наследует (или дополняет) логику пагинации.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `startDate` | `datetime` | Начало периода поиска (UTC). |
| `endDate` | `datetime` | Конец периода поиска (UTC). |
| `eventTypes` | `array<string>` | Фильтр по типам событий (опционально). |
| `actorId` | `uuid` | Фильтр по конкретному инициатору (опционально). |
| `ipAddress` | `string` | Поиск всех событий с указанного IP-адреса или подсети (опционально). |
| `minSeverity` | `string` | Минимальный уровень критичности (`WARNING` вернет WARNING и CRITICAL). Опционально. |

## Пример работы (JSON)

Запрос всех критических событий за последние сутки от определенного IP.

```json
{
  "startDate": "2026-03-24T00:00:00Z",
  "endDate": "2026-03-25T00:00:00Z",
  "eventTypes": null,
  "actorId": null,
  "ipAddress": "203.0.113.42",
  "minSeverity": "CRITICAL"
}
```

# DTO: SecurityAlertDto

## Контекст и назначение

Объект представляет собой уведомление (Alert), генерируемое подсистемой анализа аномалий Auth Service. Он возвращается пользователю в личный кабинет (раздел "Безопасность") или отправляется администраторам. Алерты создаются при обнаружении Session Hijacking (резкая смена IP/User-Agent в рамках одной сессии), попытках брутфорса или входах с новых, нетипичных устройств.

**Назначение:** Ответ (Уведомление / Аномалия).
**Реализация сущности:** Таблица `security_alerts`.

## Структура данных

Содержит тип угрозы, статус резолюции и контекст обнаружения.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `alertId` | `uuid` | Уникальный идентификатор уведомления об угрозе. |
| `timestamp` | `datetime` | Время фиксации аномалии (UTC). |
| `alertType` | `string` | Тип угрозы (`NEW_DEVICE`, `GEO_JUMP`, `BRUTEFORCE_ATTEMPT`, `HIJACK_DETECTED`). |
| `userId` | `uuid` | ID пользователя, чей аккаунт находится под угрозой. |
| `isResolved` | `boolean` | Статус реагирования (false — угроза активна/не просмотрена, true — подтверждена или отклонена). |
| `details` | `object` | JSON с деталями аномалии (например, старый и новый IP при Geo Jump). |

## Пример работы (JSON)

Пример предупреждения о входе с нового устройства.

```json
{
  "alertId": "alert-uuid-7777",
  "timestamp": "2026-03-25T10:05:00Z",
  "alertType": "NEW_DEVICE",
  "userId": "user-uuid-1111",
  "isResolved": false,
  "details": {
    "ipAddress": "45.33.22.11",
    "location": "Лондон, Великобритания",
    "userAgent": "Firefox 120 on Linux"
  }
}
```

# DTO: BlockListAddRequestDto

## Контекст и назначение

Этот запрос инициируется администратором ИБ (или автоматизированной системой защиты) для внесения IP-адреса, CIDR-подсети или конкретного отпечатка устройства в локальный Firewall микросервиса авторизации (Local Firewall / Rate Limiting). Все последующие запросы с этих источников будут отклоняться на раннем этапе.

**Назначение:** Запрос (Мутация / Блокировка).
**Реализация сущности:** Запись в Redis (Blocklist Set).

## Структура данных

Включает тип блокировки, значение и причину.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `blockType` | `string` | Тип блокируемого субъекта (`IP`, `CIDR`, `FINGERPRINT`). |
| `value` | `string` | Значение (например, `203.0.113.42` или `hash_bad_device`). |
| `ttlSeconds` | `integer` | Время жизни блокировки (если null — перманентно). |
| `reason` | `string` | Обязательное описание причины блокировки (для WORM Audit). |

## Пример работы (JSON)

Внесение атакующего IP-адреса в бан на 24 часа.

```json
{
  "blockType": "IP",
  "value": "203.0.113.42",
  "ttlSeconds": 86400,
  "reason": "Обнаружена автоматизированная попытка подбора паролей"
}
```

# DTO: ImpersonateRequestDto

## Контекст и назначение

Опасный DTO, используемый исключительно системными администраторами и сотрудниками поддержки высшего уровня (Support Tier 3). Позволяет инициировать режим "God Mode" — войти в Workspace клиента от его имени для отладки сложной проблемы, не запрашивая пароль. Требует обязательного указания номера тикета в Helpdesk системе (Jira/Zendesk) для аудита.

**Назначение:** Запрос (Мутация / Эскалация привилегий).
**Реализация сущности:** Установка специального состояния в Redis-сессии саппорта.

## Структура данных

Содержит идентификатор целевого пользователя (или Workspace) и обязательное обоснование.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `targetUserId` | `uuid` | ID пользователя платформы, чью сессию необходимо сымитировать. |
| `targetWorkspaceId` | `uuid` | ID рабочего пространства, в которое нужно зайти (опционально). |
| `ticketId` | `string` | Обязательный номер задачи/тикета в системе поддержки (например, `SUP-4042`). |
| `reason` | `string` | Краткое описание проблемы, требующей имперсонации. |

## Пример работы (JSON)

Запрос саппорта на вход в профиль клиента для проверки бага с биллингом.

```json
{
  "targetUserId": "client-uuid-9999",
  "targetWorkspaceId": "client-ws-4242",
  "ticketId": "SUP-4042",
  "reason": "Клиент жалуется на некорректное отображение скидки в инвойсе"
}
```

# DTO: GodModeContextDto

## Контекст и назначение

Это расширение или замена `SessionContextDto`, возвращаемое фронтенду саппорта *после* успешной имперсонации. Он содержит как данные целевого клиента (чтобы UI отображал нужный контент), так и данные оригинального саппорта (чтобы UI выводил красную плашку "Вы находитесь в режиме Impersonation: Выход"). Кроме того, эта двойная идентичность будет транслироваться во все внутренние сервисы (Header Routing), чтобы любые действия, совершенные в этом режиме, логировались под именем саппорта, а не клиента.

**Назначение:** Ответ (Состояние).
**Реализация сущности:** Двойной контекст сессии.

## Структура данных

Инкапсулирует оригинального актора и целевую среду.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `impersonatorId` | `uuid` | ID реального сотрудника саппорта (Actor). |
| `impersonatorEmail` | `string` | Email саппорта (для UI). |
| `targetUserId` | `uuid` | ID сымитированного клиента (Subject). |
| `activeWorkspaceId` | `uuid` | ID текущего рабочего пространства клиента. |
| `targetRoles` | `array<string>` | Эффективные роли, вычисленные как пересечение прав клиента и ограничений God Mode (read-only by default). |
| `ticketId` | `string` | Номер тикета, привязанного к этой сессии. |

## Пример работы (JSON)

Пример контекста активного God Mode.

```json
{
  "impersonatorId": "admin-uuid-1111",
  "impersonatorEmail": "support.bob@steos.io",
  "targetUserId": "client-uuid-9999",
  "activeWorkspaceId": "client-ws-4242",
  "targetRoles": ["viewer", "support_auditor"],
  "ticketId": "SUP-4042"
}
```

# DTO: ImpersonationStopRequestDto

## Контекст и назначение

Этот запрос инициируется фронтендом саппорта, когда администратор нажимает кнопку "Выйти из режима Impersonation". Auth Service удаляет двойной контекст из сессии, восстанавливая оригинальный `SessionContextDto` сотрудника поддержки. Операция логируется в WORM Audit как `IMPERSONATION_ENDED`.

**Назначение:** Запрос (Мутация / Откат привилегий).
**Реализация сущности:** Удаление специального состояния из Redis.

## Структура данных

Включает пустую структуру или метаданные завершения (отчет).

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `closingComment` | `string` | Необязательный текстовый отчет (например, "Баг подтвержден, завел таску в Jira") для сохранения в аудите. |

## Пример работы (JSON)

Запрос на штатный выход.

```json
{
  "closingComment": "Проверил отображение инвойсов, все работает корректно, проблема на стороне клиента."
}
```

# DTO: AuditMacroContextDto

## Контекст и назначение

Это вложенный JSON-объект, который используется как значение поля `metadata` в записях `AuditLogEventDto` (WORM Audit). В отличие от простого Key-Value, данный DTO жестко структурирует контекстные данные, специфичные для микросервисов, чтобы обеспечить единообразие логов (кто был сымитирован, в каком Workspace произошло действие). Этот макроконтекст прозрачно извлекается из `GodModeContextDto` и `SessionContextDto` при логировании любых действий.

**Назначение:** Вложенный объект (Формат метаданных).
**Реализация сущности:** Поле `metadata` (типа JSONB) в `audit_logs`.

## Структура данных

Включает детальные параметры бизнес-среды.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `activeWorkspaceId` | `uuid` | Рабочее пространство, где произошло событие (если применимо). |
| `impersonatorId` | `uuid` | Реальный сотрудник саппорта (присутствует, если действие совершено в режиме God Mode). |
| `impersonatorTicket` | `string` | Номер тикета саппорта (из God Mode). |
| `previousState` | `object` | JSON со старыми значениями полей (до изменения). |
| `newState` | `object` | JSON с новыми значениями полей (после изменения). |

## Пример работы (JSON)

Пример макроконтекста при смене настроек Workspace саппортом.

```json
{
  "activeWorkspaceId": "client-ws-4242",
  "impersonatorId": "admin-uuid-1111",
  "impersonatorTicket": "SUP-4042",
  "previousState": { "billingPlan": "free" },
  "newState": { "billingPlan": "pro" }
}
```

# DTO: RateLimitConfigDto

## Контекст и назначение

Этот DTO используется в административном API Authorization Service для управления параметрами локального фаервола (Local Firewall & Throttling). Он позволяет ИБ-офицерам гибко настраивать алгоритм Token Bucket для защиты от DDoS и брутфорс-атак (Fail2Ban), задавая размер корзины (Burst) и скорость её пополнения (Refill Rate) для разных групп эндпоинтов (Login, API, Public).

**Назначение:** Ответ/Запрос (Конфигурация Throttling).
**Реализация сущности:** Конфигурация Redis (или In-Memory Cache).

## Структура данных

Включает параметры Token Bucket и пороги блокировки.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `endpointGroup` | `string` | Идентификатор группы (напр., `GLOBAL_API`, `AUTH_LOGIN`). |
| `capacity` | `integer` | Максимальное количество запросов в корзине (Burst). |
| `refillRatePerSec` | `number` | Скорость добавления новых токенов в корзину (запросов в секунду). |
| `fail2BanThreshold` | `integer` | Количество 429 ошибок подряд, после которых IP отправляется в BlockList. |
| `banDurationSeconds` | `integer` | Время автоматической блокировки (TTL в BlockList). |

## Пример работы (JSON)

Настройки лимитов для эндпоинта логина (защита от брутфорса).

```json
{
  "endpointGroup": "AUTH_LOGIN",
  "capacity": 5,
  "refillRatePerSec": 0.1,
  "fail2BanThreshold": 10,
  "banDurationSeconds": 3600
}
```

# DTO: GetExportArchiveJobStatusRequest / ExportArchiveJobStatusDto

## Контекст и назначение

Паритет REST `GET /audit/export-jobs/{jobId}` и gRPC `GetExportArchiveJobStatus`.

## Структура данных

**GetExportArchiveJobStatusRequest**

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `jobId` | `string` | Идентификатор, возвращённый `ExportAuditArchive`. |

**ExportArchiveJobStatusDto**

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `status` | `string` | `PENDING`, `RUNNING`, `SUCCEEDED`, `FAILED`. |
| `downloadUrl` | `string` | Presigned URL (когда `SUCCEEDED`). |
| `urlExpiresAt` | `datetime` | Срок действия ссылки. |
| `errorMessage` | `string` | При `FAILED`. |

## Пример работы (JSON)

**Запрос** статуса задания экспорта:

```json
{
  "jobId": "export_job_01HZY1"
}
```

**Ответ** при успешном завершении:

```json
{
  "status": "SUCCEEDED",
  "downloadUrl": "https://storage.example/presigned/…",
  "urlExpiresAt": "2026-04-14T18:00:00Z",
  "errorMessage": null
}
```
