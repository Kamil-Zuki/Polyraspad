# Введение

Media Service использует **S3-совместимое object storage** (MinIO в Polyraspad Docker) как **единственный** персистентный слой — без PostgreSQL и Redis.

## Контекст и проблема

Карточки, Reader и library import генерируют бинарные файлы (images, audio, PDF/EPUB). Нужен централизованный store с публичными URL и единым bucket policy, без размазывания upload logic в Vocabulary или Aggregator.

## Принятое решение

1. Выделить **Media Service** с AWS SDK `IAmazonS3`.
2. Bucket `polyraspad-media` (configurable) с префиксами `images/`, `audio/`, `documents/`.
3. UUID как object key suffix — нет коллизий, простой резолв URL.
4. `EnsureBucketExistsAsync` на первом write (dev-friendly).
5. Ошибки S3 → gRPC `Unavailable` с логом.

## Обоснование и последствия

### Плюсы

* Один сервис и один bucket для всех media assets.
* Horizontal scale Media pods без shared DB state.
* Совместимость с production nginx → MinIO public path.

### Последствия

* Нет транзакций между blob и metadata — library JSON и documents могут рассинхронизироваться при partial failure.
* *Решение:* BFF orchestrates upload → save book; orphan blobs — manual/ops cleanup.
