# Введение

Нефункциональные требования к **Media Service** — качество, безопасность и эксплуатация object-storage backend.

# 1. Назначение

## 1.1 Цель

Зафиксировать ожидания по latency upload, лимитам размера, доступности storage и границам ответственности (gRPC-only, no JWT).

## 1.2 Область

| Компонент | Область |
| :--- | :--- |
| **MediaGrpcService** | Валидация payload, gRPC handlers |
| **S3MediaStorageService** | PutObject, JSON index read/write, bucket ensure |
| **Kestrel** | HTTP/2 gRPC на порту 5121 |

# 2. Категории NFR

## 2.1 Производительность

| ID | Требование | Метрика | Приоритет |
| :--- | :--- | :--- | :--- |
| **NFR-MEDIA-001** | Upload image ≤ 5 MB без OOM на типичном payload | p99 < 2 s при 5 MB | Средний |
| **NFR-MEDIA-002** | gRPC max message 1 GB (config) для large documents | `MaxReceiveMessageSize` | Низкий |
| **NFR-MEDIA-003** | List shared collections — scan prefix; acceptable для beta | < 3 s при < 10k index files | Средний |

## 2.2 Надёжность

| ID | Требование | Метрика | Приоритет |
| :--- | :--- | :--- | :--- |
| **NFR-MEDIA-010** | S3 unavailable → gRPC `Unavailable` | Нет silent data loss | Высокий |
| **NFR-MEDIA-011** | Bucket auto-create on first write (dev) | `EnsureBucketExistsAsync` | Средний |
| **NFR-MEDIA-012** | Health endpoint для docker compose | `GET /healthz` 200 | Высокий |

## 2.3 Безопасность

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| **NFR-MEDIA-020** | Нет публичного REST без gateway | Высокий |
| **NFR-MEDIA-021** | Library ops только с валидным `user_id` header | Высокий |
| **NFR-MEDIA-022** | Content-type validation на upload (image/audio/document) | Высокий |
| **NFR-MEDIA-023** | Credentials MinIO только через env/config, не в коде | Высокий |

## 2.4 Эксплуатация

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| **NFR-MEDIA-030** | Конфиг через `Storage:*` (endpoint, bucket, URLs) | Высокий |
| **NFR-MEDIA-031** | Structured logging на S3 errors | Средний |
