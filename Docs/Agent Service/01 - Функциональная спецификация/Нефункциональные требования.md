# Нефункциональные требования

## Производительность и масштабирование

| ID | Требование |
| :--- | :--- |
| NFR-AGENT-01 | ListMessages: limit clamp 1..100; default 100 при `limit <= 0`. |
| NFR-AGENT-02 | gRPC MaxSend/ReceiveMessageSize: до 1 GB (large metadata payloads). |
| NFR-AGENT-03 | LLM HttpClient timeout: 5..600 s (из `Ai:TimeoutSeconds`). |
| NFR-AGENT-04 | PostgreSQL connection retry: до 5 попыток, delay до 10 s. |

## Безопность и изоляция

| ID | Требование |
| :--- | :--- |
| NFR-AGENT-05 | Все thread/message/run операции фильтруются по `user_id` ownership. |
| NFR-AGENT-06 | Project access проверяется через Vocabulary ContentService до list/create thread и ExecuteRun. |
| NFR-AGENT-07 | Domain policy блокирует LLM-tools для out-of-scope (programming, general homework). |
| NFR-AGENT-08 | Identity не принимается из proto body для authorization — только gRPC metadata / validated context. |

## Надёжность

| ID | Требование |
| :--- | :--- |
| NFR-AGENT-09 | CreateRun — одна DB transaction (messages + run + domain + tools). |
| NFR-AGENT-10 | Tool execution errors → assistant error message + tool call status `failed`, run still persisted. |
| NFR-AGENT-11 | Archive thread — idempotent (повторный archive OK). |

## Эксплуатация

| ID | Требование |
| :--- | :--- |
| NFR-AGENT-12 | EF migrations at startup (Docker-friendly; review before production breaking changes). |
| NFR-AGENT-13 | `/healthz` liveness без deep dependency checks. |
| NFR-AGENT-14 | Detailed gRPC errors только в Development environment. |

## LingQ / term-first

| ID | Требование |
| :--- | :--- |
| NFR-AGENT-15 | Ответы sanitizing: удаление `Lemma:` labels из LLM output (`SanitizeLemmaLabels`). |
| NFR-AGENT-16 | Card/word tools работают с exact quoted surface forms, не леммами. |
