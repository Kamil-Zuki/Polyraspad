# Roadmap: Проактивный ИИ-Ментор

> [!IMPORTANT]
> Фокус сместился: сначала делаем **интеллект**, потом **визуал**.  
> Без умного Агента все фичи (Writing, Shadowing, Диктанты) — мёртвые экраны. С умным Агентом — они оживут сами.

---

## Принцип: Агент — главный оркестратор

Сейчас архитектура выглядит так:

```
Пользователь → открывает чат → пишет вопрос → Агент отвечает
```

Целевая архитектура:

```
Пользователь → открывает дашборд → Агент УЖЕ знает контекст →
сам приветствует → предлагает конкретный план → ведёт за руку
```

---

## Этап 1 (Критический): Агент получает контекст о пользователе

*Цель: Агент больше не слепой. При каждом запуске он знает состояние пользователя.*

### 1.1 Новый инструмент `get_daily_plan`

**Где:** `AgentOrchestrator.cs` → `AvailableTools[]` + `ExecuteToolCoreAsync()`  
**Что делает:** вызывает `AutopilotService.GetDailyPlanAsync()` через gRPC-клиент и возвращает Агенту структурированный план дня:
- Количество карточек в очереди (`dueCardsCount`)
- Слабейший навык (`weakestSkill`: reading / listening / writing / speaking)
- Следующий урок по curriculum (`nextLesson.Title`, `nextLesson.CefrLevel`)
- Общий уровень CEFR по каждому навыку

**Результат:** Агент впервые видит полный срез состояния ученика и может давать осмысленные советы.

### 1.2 Контекстный System Prompt

**Где:** `AgentSystemPromptBuilder.Build()`  
**Что меняем:** Метод принимает `DailyPlanContext?` и вплетает его в промпт:

```
[LEARNER CONTEXT — сегодня, {date}]
- Due flashcards: {dueCount}
- Weakest skill: {weakestSkill} (CEFR level: {cefrLevel})
- Next lesson: "{lessonTitle}" ({cefrLevel})

Your mission today: prioritize {weakestSkill} practice.
When the user opens the chat without a specific request, start with this context.
```

**Результат:** Агент всегда отвечает с учётом реального состояния пользователя, а не абстрактно.

### 1.3 Проактивное приветствие (первое сообщение)

**Где:** `AgentGrpcService.cs` (CreateThread) или фронтенд `useAgentWorkspace`  
**Что делает:** Если тред новый и история пустая — Агент автоматически получает первый run с текстом `"__INIT__"` (или специальным флагом `IsInitialGreeting = true`). Промпт для этого run-а: *"Поприветствуй пользователя, расскажи что у него сегодня запланировано и предложи начать с самого важного."*  

**Результат:** Пользователь открывает чат — и Агент уже говорит *"Привет! Сегодня у тебя 23 карточки на повторение и урок по Past Simple. Твой Speaking пока на A2 — давай сначала его?"*

## Этап 2: Агент умеет генерировать задания (Output Skills)

*Цель: Агент не только советует, но и сам создаёт упражнения на письмо и перевод.*

### 2.1 Новый инструмент `generate_writing_task`

**Где:** `AgentOrchestrator.cs`  
**Что делает:**
1. Забирает 5–7 `Learning`-слов пользователя из `VocabularyService`
2. Формирует промпт: *"Сгенерируй задание: напиши деловое письмо, используя эти слова: {список}"*
3. Возвращает Агенту готовое задание, которое он выводит пользователю

**Нет необходимости в отдельном экране.** Задание происходит прямо в чате — пользователь пишет ответ, Агент проверяет.

### 2.2 Инструмент `evaluate_user_response`

**Где:** `AgentOrchestrator.cs`  
**Что делает:** принимает ответ пользователя на задание и текущие `Learning`-слова, вызывает LLM с промптом-оценщиком, возвращает фидбек: какие слова использованы правильно, какие ошибки в грамматике, итоговый score.  
**После успешной оценки** — вызывает `submit_knowledge_check` с полученными скорами.

**Результат:** Writing занятие полностью проходит внутри чата. Радар Chart автоматически обновляется.

## Этап 3: Агент замечает паттерны (Weakness Detection)

*Цель: Агент видит историю ошибок и сам предлагает целенаправленную практику.*

### 3.1 Новый инструмент `get_skill_assessment_history`

**Где:** `VocabularyService` → новая таблица `SkillAssessmentLog` (минимальная — `UserId`, `Skill`, `Score`, `CreatedAt`)  
**Что делает:** Агент спрашивает историю оценок и видит тренд: "Writing стабильно низкий уже 5 сессий".

### 3.2 Обогащение `AgentIntentRouter`

**Где:** `AgentIntentRouter.cs`  
**Что меняем:** Если пользователь пишет просто *"начнём"* или *"что делаем сегодня"* — Intent маршрутизируется к `get_daily_plan` автоматически, без вызова LLM на этом шаге. Быстро и дёшево.

---

## Этап 4: Проактивные уведомления (Агент инициирует сам)

*Цель: Агент не ждёт пользователя — он зовёт его.*

### 4.1 Background Job в AgentService

Фоновая задача (Hosted Service / Hangfire) раз в день:
- Берёт всех пользователей с активными проектами
- Для каждого запускает `AutopilotService.GetDailyPlanAsync()`
- Если есть просроченные карточки или пропущенный урок — генерирует push/email уведомление

**Scope:** Требует `NotificationService` или интеграцию с email (SMTP уже настроен). Самый сложный этап — ставим в очередь.

## Перспектива развития: Переход к AGI-Tutor (Domain-Specific AGI)

Для эволюции `AgentService` в полностью автономного, адаптивного ИИ-преподавателя определены следующие концептуальные векторы развития:

### 1. Автономия и Event-Driven цикл (Background Agent Loop)
Переход от реактивной модели (ответ на реплику) к проактивной фоновой жизнедеятельности:
- Запуск фонового процесса (`Agent Loop`), который анализирует активность и интересы пользователя без его присутствия на платформе.
- Самостоятельный скрапинг свежего контента под вкусы пользователя (новости, статьи, медиа), адаптация под его CEFR-уровень и отправка в виде микро-заданий.

### 2. Роевая многоагентная архитектура (Society of Mind)
Разделение монолитного `AgentOrchestrator` на группу специализированных сабагентов, координирующих свои действия:
- **Tutor Agent**: отвечает за интерфейс общения с пользователем, эмпатию, тон и мотивацию.
- **Scout Agent**: занимается автономным поиском и фильтрацией релевантных учебных материалов.
- **Critic Agent**: анализирует ошибки, ведет аудит ответов и корректирует учебную траекторию.
- **Meta-Agent**: управляет всей системой, следит за глобальной метрикой удержания знаний (retention) и адаптирует параметры FSRS.

### 3. Глубокая долговременная память (Episodic & Semantic Memory)
Внедрение векторного хранилища (pgvector / Qdrant) для создания целостного цифрового портрета ученика:
- Сохранение не только численных показателей, но и поведенческих паттернов (какие типы объяснений лучше усваиваются, темы интересов, психологический профиль).
- Использование семантического поиска по истории взаимодействий при каждом формировании системного промпта.

### 4. Мультимодальность в реальном времени (Voice & Vision)
- Голосовое общение без задержек (потоковые аудио-модели, интеграция по WebRTC).
- Анализ визуального контекста (разбор скриншотов, разметка видео на лету, объяснение выражений из фильмов).

### 5. Мета-обучение и самооптимизация (Self-Improvement)
- Систематический анализ эффективности собственных методик Агента (A/B тестирование подходов к объяснению грамматики).
- Автоматическая корректировка внутренних промптов (Prompt Optimization) на основе изменения скорости прогресса ученика.
