# Введение

Данный документ описывает protobuf-сообщения группы **Запуски и оркестрация**, используемые RPC `CreateRun` и `ExecuteRun`. Включает input DTO для persist и read model run + messages.

**SR:** SR-AGENT-RUN-01, SR-AGENT-RUN-02. gRPC: [[../gRPC/02 - Запуски и оркестрация (Runs)]].

# 1. Список DTO

| **Название DTO** | **Назначение** |
| :--- | :--- |
| **AgentMessageInput** | Вложенный input: role, content, optional id и metadata. |
| **AgentDomainDecisionInput** | Input: domain gate audit (allowed, category, reason). |
| **AgentToolCallInput** | Input: запись tool call (name, input/output JSON, status). |
| **CreateAgentRunRequest** | Запрос persist run. |
| **ExecuteAgentRunRequest** | Запрос orchestrated run. |
| **AgentRunItem** | Read model run summary. |
| **CreateAgentRunResponse** | Ответ: run + user + assistant messages. |

# DTO: AgentMessageInput

## Контекст и назначение

Payload сообщения при `CreateRun`. Client может задать optional id для idempotency; orchestrator генерирует ids автоматически.

**Назначение:** Запрос (вложенный).
**Реализация сущности:** INSERT в `agent_messages`.

## Структура данных

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `id` | `uuid \| null` | Optional client-provided id. |
| `role` | `string` | `user` \| `assistant` \| `system` \| `tool`. |
| `content` | `string` | Non-empty text. |
| `metadata_json` | `string \| null` | JSON string (assistant UI metadata). |

## Пример работы (JSON)

```json
{
  "role": "user",
  "content": "Explain the word \"slept\""
}
```

# DTO: AgentDomainDecisionInput

## Контекст и назначение

Audit domain gate для каждого run. Category — одно из: `language_learning`, `product_navigation`, `progress`, `out_of_scope`.

**Назначение:** Запрос (вложенный).
**Реализация сущности:** Таблица `agent_domain_decisions`.

## Структура данных

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `allowed` | `boolean` | Разрешён ли LLM-tool path. |
| `category` | `string` | Domain category (lowercase in DB). |
| `reason` | `string \| null` | Machine-readable reason code. |

# DTO: ExecuteAgentRunRequest

## Контекст и назначение

Server-side orchestration input для `#grpc-ExecuteRun`. Aggregator передаёт user text и optional lang/deck hints.

**Назначение:** Запрос.
**gRPC:** [[../gRPC/02 - Запуски и оркестрация (Runs)#grpc-ExecuteRun]].

## Структура данных

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `thread_id` | `uuid` | Тред диалога. |
| `project_id` | `uuid` | Project scope. |
| `user_text` | `string` | Required user input. |
| `source_lang` | `string \| null` | Override project source language. |
| `target_lang` | `string \| null` | Override project target language. |
| `first_deck_id` | `string \| null` | Hint для Study navigation href. |
| `is_initial_greeting` | `boolean` | Флаг первичности приветственного обращения. |

## Пример работы (JSON)

```json
{
  "thread_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "project_id": "42424242-4242-4242-4242-424242424242",
  "user_text": "How is my progress?",
  "first_deck_id": "deck-uuid-001",
  "is_initial_greeting": false
}
```

# DTO: AgentRunItem

## Контекст и назначение

Краткая проекция run после persist. v1 всегда `status = completed` (synchronous execution).

**Назначение:** Ответ (вложенный).
**Реализация сущности:** Таблица `agent_runs`.

## Структура данных

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `id` | `uuid` | Run id. |
| `thread_id` | `uuid` | Parent thread. |
| `status` | `string` | `completed` (v1). |
| `model` | `string \| null` | LLM model id. |
| `started_at` | `datetime` | UTC start. |
| `completed_at` | `datetime` | UTC completion. |
