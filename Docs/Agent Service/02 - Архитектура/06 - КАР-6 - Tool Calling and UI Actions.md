# Механизм Tool Calling и UI-действий Агента

## Контекст и проблема
LLM-агент (Study Copilot) должен уметь как получать скрытые данные через бэкенд, так и инициировать действия на стороне клиента (UI), такие как навигация или открытие редакторов с предзаполненными данными. Необходимо четко разделить фоновые вызовы функций, которые не видны пользователю в чате, и интерфейсные команды, которые должны превращаться в интерактивные карточки-действия.

## Решение

Работа агента строится на комбинации двух механизмов: **Tool Calling (API)** и **текстовых UI-команд (парсинг ответа)**.

### 1. Как агент получает информацию о своих возможностях?

В процессе формирования контекста (`AgentSystemPromptBuilder`) нейросети передается **системный промпт**, который определяет:
- **Роль и ограничения:** Позиционирование как Study Copilot.
- **Инструкции по UI-командам:** Строгие форматы текстового вывода для управления интерфейсом (например, `NAVIGATE|/library|Open Library` или `OPEN_EDITOR_DRAFT|word|expression|...`).
- **Спецификации Tools:** Через нативный механизм Tool Calling (OpenAI/Mistral API) передаются JSON-схемы доступных фоновых функций (`create_deck`, `get_user_vocabulary_stats` и т.д.).

### 2. Фоновые API-вызовы (Tool Calling)

Используется для взаимодействия с другими сервисами (например, `VocabularyService`), когда результат нужен самому агенту для формирования ответа.

1. **Инициация:** Нейросеть решает вызвать инструмент и возвращает объект `ToolCall` (вместо обычного текста).
2. **Перехват и исполнение:** Оркестратор (`AgentOrchestrator`) перехватывает вызов, проверяет валидность и исполняет реальный C# код (чаще всего это gRPC запрос).
3. **Возврат результата:** Оркестратор отдает результат выполнения (JSON) обратно в LLM с ролью `tool`.
4. **Финальный ответ:** Получив результат (например, ID созданной колоды), нейросеть формулирует итоговый текстовый ответ для пользователя.

### 3. UI-карточки (Действия в интерфейсе)

Используется, когда агенту нужно делегировать выполнение действия клиенту (открыть модальное окно, перейти на другую страницу), так как LLM не имеет прямого доступа к DOM браузера.

1. **Вывод команды:** Нейросеть генерирует в тексте ответа строку в строго заданном формате (например, `OPEN_EDITOR_DRAFT||New Deck|Создать новую карточку...`).
2. **Парсинг:** Перед сохранением ответа и отправкой его клиенту, `AgentOrchestrator` построчно парсит ответ (`assistantContent.Split('\n')`).
3. **Извлечение и скрытие:** Если строка совпадает с известным паттерном (`NAVIGATE|`, `OPEN_EDITOR_DRAFT|`), она вырезается из текста сообщения, чтобы не отображаться пользователю в виде "сырого" машинного кода.
4. **Формирование DTO:** На основе вырезанной строки формируется структура `AgentActionCard` (Action, Kind, Href, Payload), которая прикрепляется к метаданным сообщения (`MetadataJson`).
5. **Рендеринг:** Фронтенд, получив сообщение с массивом `actions`, рендерит их в виде красивых, интерактивных React-компонентов (кнопок), которые реагируют на клик, вызывая функции приложения (Next.js Router, контексты редактора и т.д.).

## Последствия
- Строгое разделение ответственности: бэкенд не пытается управлять UI, а фронтенд не делает прямых запросов к LLM.
- Возможность легко расширять набор UI-действий простым добавлением новых паттернов в системный промпт и парсер оркестратора.
- Чистый лог чата без технических команд.
