# Polyraspad Core Methodology & Vision: Четыре Столпа Языка

## 1. Фундаментальная Идея (The Core Philosophy)
Главная цель платформы Polyraspad — не просто накапливать словарный запас (как это делают обычные карточные системы), а формировать **комплексное владение языком**. Настоящее владение языком состоит из 4 независимых, но взаимосвязанных навыков:
1. **Чтение (Reading)** — пассивный навык (потребление).
2. **Аудирование (Listening)** — пассивный навык (восприятие).
3. **Письмо (Writing)** — активный навык (конструирование).
4. **Говорение (Speaking)** — активный навык (спонтанное конструирование и произношение).

Система должна бесшовно проводить пользователя через все эти этапы, балансируя нагрузку и выявляя слабые места.

---

## 2. Модель Трекинга: Единый Профиль Навыков

Чтобы эффективно развивать пользователя, нам нужна глубокая аналитика его способностей. Вместо абстрактных "очков опыта" (XP), мы трекаем:

### А. Словарная База (Knowledge Graph)
Каждое слово (ProjectTerm) имеет статус (New, Learning, Known). Однако теперь мы расширяем понимание "Known":
- **Passive Known**: Пользователь узнает слово при чтении или слушании.
- **Active Known**: Пользователь может использовать слово при письме или в речи.

### Б. Тестирование и Срезы Знаний (Checkpoints)
Мы вводим систему **Регулярного тестирования**:
- **Микро-тесты (Ежедневные):** В рамках Study Session пользователю предлагаются не только flashcards, но и мини-задачи (вставить слово в аудио, перевести фразу голосом).
- **Экзамены / Ролевые игры с ИИ (Еженедельные):** AgentService инициирует диалог (например, собеседование на работу). Агент анализирует:
  - Скорость реакции (Speaking).
  - Грамматическую точность (Writing/Speaking).
  - Понимание на слух (Listening).

### В. Аналитика Слабых Мест (Weakness Detection)
На основе собранных данных система строит лепестковую диаграмму (Radar Chart) навыков.
*Пример: Если пользователь прочитал 10 книг, но постоянно ошибается в аудио-диктантах, система помечает "Listening" как слабое место.*

---

## 3. Мотивация и Продвижение (Autopilot & Push)

Пользователь не должен сам решать, что ему делать сегодня. Для этого работает **Daily Autopilot** (SR-AUTO).

- **Фокус на отстающие навыки:** Если "Говорение" проседает, автопилот включает в план 15 минут Shadowing и 5 минут диалога с Агентом.
- **Сценарии переключения (Skill Cross-Pollination):**
  - *Прочитал статью (Reading) -> Выписал новые слова (Vocabulary) -> Агент просит написать краткое саммари по этим словам (Writing) -> Агент читает саммари вслух, а пользователь повторяет (Speaking).*
- **Геймификация и Прогресс:** Четкое понимание "Я нахожусь на уровне B1, чтобы перейти на B2, мне не хватает разговорной практики".

## 4. Дорожная Карта: Что нужно создать / изменить (Roadmap)

Для достижения этого видения, архитектура и фичи должны быть доработаны следующим образом:

### 1. Чтение (Reading) [Текущий статус: Выполнено на 70%]
- **Есть:** Reader, LingQ-подход, клики по словам, парсинг субтитров.
- **Что добавить:**
  - Поддержка EPUB / PDF с сохранением верстки.
  - Анализ сложности текста (Readability Score) до начала чтения, чтобы предлагать тексты подходящего уровня.

### 2. Аудирование (Listening) [Текущий статус: Базовый]
- **Есть:** TTS-озвучка, импорт YouTube.
- **Что добавить:**
  - **Диктанты (Dictations):** Модуль, где звучит фраза, и пользователь должен её набрать.
  - **Слепое аудирование:** Режим в ридере, когда текст скрыт, и открывается только после прослушивания фрагмента.

### 3. Говорение (Speaking) [Текущий статус: В разработке (Shadowing)]
- **Есть:** UI для Shadowing (в планах).
- **Что добавить:**
  - **Voice Input & STT (Speech-to-Text):** Интеграция Whisper / браузерного STT.
  - **Pronunciation Assessment:** Оценка произношения (сравнение аудио пользователя с эталоном с помощью ИИ).
  - **AI Ролевые игры (Voice Chat):** Полноценные уроки-разговоры (Lessons Module, который мы начали) должны поддерживать голосовое общение.

### 4. Письмо (Writing) [Текущий статус: Нулевой]
- **Есть:** Ничего специализированного.
- **Что добавить:**
  - **Writing Challenges:** Агент задает тему ("Напиши email клиенту о задержке"). Пользователь пишет. Агент проверяет грамматику, стиль и использование целевых (Learning) слов.
  - **Translation Exercises:** Карточки с переводом полного предложения (L1 -> L2), где нужно написать ответ руками.

### 5. Инфраструктура и Тестирование (Core Changes)
- **Модуль Тестирования (Evaluation Module):** В `VocabularyService` (или новом `EvaluationService`) нужно добавить сущности `SkillAssessment` и `TestResult`.
- **Расширение StudyService:** Текущий FSRS хорош для отдельных карточек. Нужно добавить FSRS для *фраз* и *грамматических паттернов*.
- **Agent Orchestrator:** ИИ должен стать проактивным. Он должен сам высылать уведомления: "Эй, мы давно не практиковали разговорный английский. Уделим 5 минут?"
