# Карта функционала Polyraspad: От MVP к AI-платформе

**Стратегия запуска:** Начинать нужно **ТОЛЬКО с ядра (FSRS + Library LingQ)**. 
Попытка запустить сразу "полностью с ИИ" (автономными агентами) приведет к разрастанию требований (scope creep), задержке релиза на полгода и выгоранию. Пользователи уже сейчас готовы платить за базовую, но идеально работающую и быструю механику LingQ + FSRS. ИИ должен стать "киллер-фичей" (Premium), которую мы будем наслаивать на уже работающее и приносящее деньги ядро.

---

## 🚀 Этап 1: MVP (Minimum Viable Product)
**Цель:** Дать пользователю работающий цикл "Потребление контента -> Выделение слов -> Запоминание".
**Ориентир по времени:** 1-2 месяца до паблик-релиза в РФ.
**Монетизация:** Базовая подписка (например, снятие лимитов на загрузку текстов и безлимитный тренажер FSRS).

**Модули:**
1. **Library & Reader (LingQ-style):**
   - Загрузка текстов пользователем.
   - Базовый парсинг и чтение (поддержка сырого текста). OCR можно оставить на конец этапа.
   - Читалка с кликабельными словами.
   - Разметка статусов слов (New, Saved, Known, Ignored).
   - Цветовая индикация в тексте.
2. **Vocabulary & FSRS (Ядро):**
   - Создание карточек (Термин + Перевод + Контекст).
   - Тренажер слов на базе алгоритма FSRS (Python-микросервис `inclusive`).
   - Синхронизация статусов: выучил слово в тренажере -> оно стало "Known" (белым) во всех текстах библиотеки.
3. **Capture Extension:**
   - Chrome-расширение для быстрого захвата фраз с веб-страниц (и YouTube субтитров) с отправкой прямиком в колоду пользователя.
4. **Легкий AI (Инструментальный):**
   - Простой API-колл (OpenAI/Mistral) для *перевода фразы в контексте*, когда пользователь кликает на слово. Без сложных мульти-агентов.
5. **Billing (РФ):**
   - Интеграция ЮKassa для приема первых платежей и управления доступом.

---

## ⚡ Этап 2: AI Enhancements (Умный помощник)
**Цель:** Радикально ускорить создание карточек и углубить понимание материала. 
**Монетизация:** Premium-подписка с лимитами на AI-вызовы.

**Модули:**
1. **AI Grammar Tutor:**
   - Кнопка "Объясни грамматику" в читалке: выделяешь сложное предложение, LLM разбирает конструкцию, времена и идиомы.
2. **Умный импорт медиа (YouTube/Подкасты):**
   - Вставка ссылки на YouTube -> скачивание субтитров -> формирование LingQ-текста для чтения с привязкой таймкодов видео.
3. **Smart Audio (TTS):**
   - Интеграция качественного TTS (Mistral/ElevenLabs) для авто-озвучки каждой добавляемой карточки.
4. **AI Mining Drafts:**
   - Автоматическая генерация транскрипции, картинки и нескольких вариантов контекста при создании карточки.
5. **OCR для книг (PDF/EPUB):**
   - Распознавание загруженных PDF/EPUB книг с сохранением форматирования.

---

## 🤖 Этап 3: Autonomous Agents & GenUI (Революция)
**Цель:** Превратить платформу в проактивного ИИ-репетитора (то самое, что закроет критерии на визу).
**Монетизация:** Ultimate-подписка (Global Launch со Stripe/Paddle).

**Модули:**
1. **Агент-Учитель (Proactive Agent):**
   - Агент сам анализирует статистику FSRS и слабые слова пользователя.
   - **Autopilot missions:** Агент проактивно генерирует уникальный микро-текст/историю, состоящую на 90% из известных пользователю слов и на 10% из слов, которые он постоянно забывает (чтобы закрепить их в новом контексте).
2. **Generative UI:**
   - Визуализация прогресса прямо в чате с агентом (графики, интерактивные тренировки) с использованием Vercel AI SDK RSC.
3. **Multi-Agent Pipeline:**
   - Пользователь загружает книгу -> Агент-1 парсит сложные слова -> Агент-2 генерирует для них карточки с визуальными ассоциациями -> Агент-3 составляет квиз по прочитанной главе. 
4. **Voice Agent (Спикинг):**
   - Голосовой чат с агентом для тренировки разговорной речи на базе сохраненного вокабуляра.

## 🔐 Архитектура сокрытия функционала (Feature Gating)

Чтобы запустить Этап 1 (MVP) и не показывать пользователям недоделанные модули Этапов 2 и 3, в SaaS-архитектуре **НЕ используют обычные роли** (Admin/User). Роли (RBAC) нужны только для доступа в админку. 
Для сокрытия фич в SaaS используются два других паттерна:

1. **Feature Flags (Фича-флаги)**
   - **Для чего:** Полное скрытие недоделанного функционала от ВСЕХ пользователей на проде (даже от платных).
   - **Как работает:** В `appsettings.json`, `.env` или через систему (LaunchDarkly / кастомная БД) заводится флаг, например `Features__EnableAIAgents: false`.
   - **На фронтенде (Next.js):** UI проверяет флаг и просто не рендерит кнопку "Вызвать Агента" или скрывает раздел "Агенты" из сайдбара.
   - **На бэкенде (API):** `AggregatorService` проверяет флаг и возвращает `404 Not Found` или `403 Forbidden`, если кто-то попытается дернуть эндпоинт напрямую.

2. **Entitlements (Права и Квоты)**
   - **Для чего:** Разделение *готового* функционала между бесплатными и платными пользователями (монетизация).
   - **Как работает:** Твой `BillingService` управляет подписками. Он хранит логику: "Подписка Premium дает право (Entitlement): `CanUseGrammarTutor: true`".
   - **JWT Claims:** Когда пользователь логинится, `authorization-module` (или сам API Gateway) запрашивает права у биллинга и вшивает их прямо в **JWT-токен** в виде claims.
   - **Ограничение (Paywall):** Фронтенд видит, что у пользователя нет клейма `CanUseGrammarTutor`, и вместо скрытия фичи рисует на ней иконку 🔒 "Замочка". При клике на замочек открывается модалка оплаты ЮKassa. А бэкенд (`VocabularyService`) при отсутствии клейма возвращает ошибку `402 Payment Required`.
