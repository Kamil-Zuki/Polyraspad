## Введение

Настоящий документ определяет функциональные возможности (сервисные требования) микросервиса **«Authorization Module»** — сервиса identity и аутентификации платформы Polyraspad.

**Authorization Module** владеет учётными записями пользователей (ASP.NET Core Identity + PostgreSQL), выдаёт **JWT access tokens** и **refresh tokens**, подтверждает email через SMTP и предоставляет **gRPC API** (`Pvs.Auth.Grpc.AuthService`) для Aggregator Service. Публичный REST `/api/v1/auth` сохранён как legacy/direct endpoint.

Документ предназначен для разработчиков, QA, системных аналитиков и архитекторов.

# Группы возможностей

Ниже представлен перечень из 4 групп функциональных возможностей (сервисных требований) для микросервиса Authorization Module. Требования сгруппированы по логическим блокам для удобства навигации.

| Группа | Название и Описание |
| :----- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Регистрация и подтверждение email (Registration)** | **Onboarding:** Создание учётной записи, валидация пароля, отправка confirm link и активация email. |
| **Аутентификация и JWT-токены (Authentication)** | **Login flow:** Password sign-in, выдача JWT пары, refresh rotation и logout с отзывом refresh. |
| **Управление профилем (Profile Management)** | **Self-service profile:** Чтение профиля, смена username/password/avatar и lookup по email для sharing. |
| **Платформенные контракты (Operations)** | **Platform ops:** Health, CORS, production config guard, EF migrations, Swagger (dev). |

## Описание возможностей

Ниже представлен детальный перечень сервисных требований (SR) для каждой группы. Подробное описание каждого требования находится в соответствующих вложенных документах.

### 1. Регистрация и подтверждение email (Registration)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AUTHMOD-REG-01** | **Регистрация пользователя:** Приём email/password, создание Identity user, отправка SMTP confirm link; JWT на этом шаге не выдаётся. |
| **SR-AUTHMOD-REG-02** | **Подтверждение email:** Валидация one-time token Identity, установка `EmailConfirmed`, cleanup дубликатов неподтверждённых записей. |

### 2. Аутентификация и JWT-токены (Authentication)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AUTHMOD-AUTH-01** | **Login и выдача JWT:** Password sign-in только для confirmed email; access JWT + новый refresh token (7 дней). |
| **SR-AUTHMOD-AUTH-02** | **Refresh token rotation:** Обмен refresh на новую пару; старый refresh помечается revoked. |
| **SR-AUTHMOD-AUTH-03** | **Logout:** Sign-out Identity и опциональный revoke переданного refresh token. |
| **SR-AUTHMOD-AUTH-04** | **Генерация access JWT:** HMAC-SHA256, claims `sub`, `name`, `jti`; TTL из `Jwt:Expire` (минуты). |

### 3. Управление профилем (Profile Management)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AUTHMOD-PROF-01** | **Профиль текущего пользователя:** id, userName, email, emailConfirmed, avatarUrl по userId из gRPC metadata. |
| **SR-AUTHMOD-PROF-02** | **Смена username:** Уникальность имени, обновление через UserManager. |
| **SR-AUTHMOD-PROF-03** | **Смена пароля:** ChangePasswordAsync с проверкой current password. |
| **SR-AUTHMOD-PROF-04** | **Смена avatar URL:** Абсолютный http/https или сброс (null); max 2048 символов. |
| **SR-AUTHMOD-PROF-05** | **Поиск пользователя по email:** Внутренний lookup для sharing/collaboration (gRPC, без JWT user context). |

### 4. Платформенные контракты (Operations)

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AUTHMOD-OPS-01** | **Health check (liveness):** GET `/healthz` — process up. |
| **SR-AUTHMOD-OPS-02** | **CORS:** Explicit origins, AllowCredentials; wildcard запрещён в production validation. |
| **SR-AUTHMOD-OPS-03** | **Production startup validation:** Fail-fast JWT, SMTP, ConfirmationLink, CORS. |
| **SR-AUTHMOD-OPS-04** | **EF Core migrations at startup:** Auto-migrate `auth-module` schema при старте контейнера. |

Подробные SR-блоки — во вложенных файлах групп. gRPC/REST контракты — в `04 - Бекенд, API и Контракты/`.
