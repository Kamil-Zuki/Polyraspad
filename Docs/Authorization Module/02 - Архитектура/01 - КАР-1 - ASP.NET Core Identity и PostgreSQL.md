# Введение

Polyraspad использует **ASP.NET Core Identity** с **PostgreSQL** вместо custom user tables. Это даёт проверенные flows: password hashing, email confirmation tokens, change password.

## Контекст и проблема

Custom auth schema дублирует security-sensitive код (hashing, token formats). Identity снижает риск и ускоряет onboarding (register, confirm, login).

## Принятое решение

1. `ApplicationUser : IdentityUser` с полем `AvatarUrl`.
2. `AddIdentity<ApplicationUser, IdentityRole>()` + EF stores на `DataContext`.
3. `UserManager` / `SignInManager` в `AuthService` для всех credential operations.
4. Миграции EF при старте контейнера.

## Обоснование и последствия

### Плюсы

* Стандартные API для password/email operations
* Совместимость с будущими Identity extensions (roles, 2FA)

### Последствия

* Схема `AspNet*` tables — не minimal custom schema
* *Решение:* документировать в [[Entity - Пользователь и Identity (ApplicationUser)]]
