# Введение

Данный документ описывает асинхронную часть интеграции Authorization Service с внутренними микросервисами платформы (Workspace, Task, CRM и др.) через брокер сообщений RabbitMQ. Эта интеграция используется для отправки броадкаст-событий (Broadcast/Fanout), когда происходит важное изменение в жизненном цикле пользователя, требующее реакции от множества независимых систем (например, конвертация гостевой сессии в авторизованный аккаунт).

# Общая информация

Асинхронная отправка событий о "склейке" сессий для бесшовного переноса гостевых ресурсов. Реализует паттерн **Event-Driven Architecture (EDA)**.

| Параметр | Описание |
| :--- | :--- |
| **Версия API** | RabbitMQ 3.12.x (Event-Driven) |
| **Название сервиса** | Внутренние микросервисы (Task Service, Workspace Service, CRM Service и т.д.) |

# Доступ и аутентификация

Настройки подключения к инфраструктуре локального брокера сообщений.

| Параметр | Описание |
| :--- | :--- |
| **Метод аутентификации** | Аутентификация через RabbitMQ (логин/пароль или сертификаты mTLS внутри кластера Kubernetes). |
| **Хранение учетных данных** | Учетные данные локального RabbitMQ хранятся в **HashiCorp Vault** или Kubernetes Secrets. |
