# Введение

В данном документе описаны общие Объекты Передачи Данных (DTO), которые используются повсеместно во многих эндпоинтах микросервиса Authorization Service. Эти структуры обеспечивают единый стандарт взаимодействия с клиентскими приложениями (Frontend SPA, BFF, другие микросервисы), позволяя унифицировать обработку успешных ответов, логирование инцидентов безопасности, стандартизировать ошибки и списки данных (например, списки активных сессий устройств). 

Применение стандартизированных общих DTO упрощает разработку клиентских приложений, снижает количество ошибок при парсинге ответов авторизации и обеспечивает прозрачность контрактов API на всей Платформе.

# 1. Список DTO

Ниже представлен перечень всех общих структур данных, описанных в данном разделе.

| **Название DTO** | **Назначение** |
| :--- | :--- |
| **SuccessResponseDto** | Стандартный успешный ответ для операций, не требующих возврата бизнес-данных (например, удаление сессии). |
| **ProblemDetailsDto** | Унифицированная структура ответа об ошибке авторизации и доступа (согласно RFC 7807). |

# DTO: SuccessResponseDto

## Контекст и назначение

Данная структура данных возвращается клиенту в ответ на операции мутации (создание, обновление, удаление), которые успешно завершились и не требуют возврата созданного или измененного объекта (например, успешный отзыв (Revoke) сессии с другого устройства, успешная смена контекста без возврата полной сущности Workspace). Она предоставляет простой и понятный флаг успешности выполнения запроса.

**Назначение:** Ответ (Общий).
**Реализация сущности:** N/A.

## Структура данных

Модель содержит минимальный набор полей, необходимых для подтверждения статуса операции безопасности и опциональной передачи пояснительного сообщения.

| **Имя поля (JSON)** | **Тип данных** | **Описание** |
| :--- | :--- | :--- |
| `success` | `boolean` | Флаг успешного завершения операции (всегда `true`). |
| `message` | `string` | Информационное сообщение о результате выполнения (опционально). |

## Пример работы (JSON)

Ниже приведен пример типичного ответа сервера при успешном принудительном завершении (отзыве) чужой сессии (Revoke Device).

```json
{
  "success": true,
  "message": "Session has been successfully revoked and removed from cache."
}
```
