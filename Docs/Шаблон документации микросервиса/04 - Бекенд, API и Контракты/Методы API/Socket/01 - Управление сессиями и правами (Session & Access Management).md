# Введение

Данный документ описывает события WebSocket группы **«Управление сессиями и правами (Session & Access Management)»**. События доставляют уведомления об отзыве сессий, «горячем» обновлении авторизационного контекста и режиме имперсонации (God Mode).

**Источник SR:** [01 - Управление Сессиями и Контекстом — Session Management](../../../../01%20-%20Функциональная%20спецификация/Возможности%20сервиса/01%20-%20Управление%20Сессиями%20и%20Контекстом%20-%20Session%20Management.md).

Общий контекст канала и поток **API Gateway → gRPC** — в [00 - WebSocket API - Общая информация](00%20-%20WebSocket%20API%20-%20Общая%20информация.md).

# 1. Список событий

| **Код требования** | **Событие** | **Направление** | **Описание** |
| :----------------- | :---------- | :-------------- | :----------- |
| **SR-AUTH-SM-06** / **SR-AUTH-OI-04** | `session_revoked` | Server → Client | Принудительное завершение сессии (одна или все), немедленный выход из SPA. |
| **SR-AUTH-SM-10** | `context_updated` | Server → Client | Сигнал перезагрузить контекст (роли, лицензии, Workspace) без полного логина. |

# Событие: `session_revoked`

| **Название события**        | `session_revoked`                                                                                                                                                                                                                                                                                                         |
| :-------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Тип**                     | Входящее сообщение (Server → Client)                                                                                                                                                                                                                                                                                      |
| **Описание**                | Уведомление о том, что сервер **отозвал** текущую или указанную сессию. Требование **SR-AUTH-SM-06** (точечный отзыв, «выйти с других устройств»); глобальный сценарий — также **SR-AUTH-OI-04** (Back-Channel Logout). Клиент обязан прекратить использование локального состояния и перейти к безопасному экрану входа. |

**Параметры сообщения** (канонические имена полей JSON — в DTO)

| Название параметра | Тип данных | Описание |
| :--- | :--- | :--- |
| **sessionId** | string (uuid) | Идентификатор отозванной сессии (для сопоставления с текущей вкладкой). |
| **reasonCode** | string | Код причины (`ADMIN_REVOKED`, `TERMINATED_FROM_OTHER_DEVICE`, `SECURITY_BREACH`, `OIDC_BACKCHANNEL` и т.д.). |

**Логика обработки**

1. API Gateway принимает запрос от клиента или внутренний вызов и проксирует в микросервис один из Unary-RPC: `RevokeSession`, `RevokeAllUserSessions` или `TerminateOtherSessions` (см. [02 - Session Lifecycle](../gRPC/02%20-%20Управление%20жизненным%20циклом%20сессий%20(Session%20Lifecycle).md)); при глобальном отзыве по событию IdP возможен цепной вызов `RevokeAllUserSessions`.
2. При срабатывании периметра отзыв может быть инициирован после `BanIpAddress` или `BanDeviceFingerprint` (см. [04 - Security & Quotas](../gRPC/04%20-%20Защита%20периметра%20и%20Гостевые%20квоты%20(Security%20&%20Quotas).md)) с последующим отзывом затронутых сессий.
3. Микросервис удаляет состояние сессии в Redis/БД и пишет аудит (**SR-AUTH-LA-01**).
4. Через **SR-AUTH-WS-01** (backplane) рассылается `session_revoked` в группу сессии/пользователя.
5. Клиент очищает хранилища и выполняет редирект на логин; следующий HTTP без валидной сессии отклоняется шлюзом при вызове `ValidateSession` ([01 - Validation Core](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md)).
