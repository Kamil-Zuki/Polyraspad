# Введение

Настоящий документ содержит обзор **WebSocket API** в контракте платформы для сценариев **Authorization Service** (принудительный логаут, обновление контекста, интерактивный вход, алерты ИБ, гостевые квоты и фоновые задачи). WebSocket используется для немедленной доставки событий клиентам (SPA, админки) без опроса HTTP.

Источником доменных требований и кодов **SR** является папка [Возможности сервиса — 00 - Общая информация](../../../../01%20-%20Функциональная%20спецификация/Возможности%20сервиса/00%20-%20Общая%20информация.md); детализация — по файлам групп в той же папке.

**Размещение WebSocket:** приём **WSS-handshake**, удержание соединений и рассылка сообщений клиентам выполняет **API Gateway (агрегатор / BFF)**. Шлюз **не содержит** доменной логики Authorization Service: для решений и мутаций состояния он вызывает микросервис **Authorization Service по gRPC** (см. [gRPC — общая информация](../gRPC/00%20-%20gRPC%20-%20Общая%20информация.md)). Описанные ниже пути и имена событий — **внешний контракт** поверхности платформы.

Цель набора документов — зафиксировать события, полезную нагрузку и связь с **именами вызываемых gRPC-методов** (документы групп gRPC в папке `Методы API/gRPC`). Структуры полезной нагрузки (DTO) описаны в папке `Методы API/DTO`: описание полей и примеры JSON по каждому типу уведомления — [08 - WebSocket и real-time уведомления](../DTO/08%20-%20WebSocket%20и%20real-time%20уведомления%20(WebSocket%20Notifications).md), индекс групп DTO — [00 - DTO - Общая информация](../DTO/00%20-%20DTO%20-%20Общая%20информация.md).

# 1. Поток запросов: API Gateway → Authorization Service (gRPC)

1. Клиент устанавливает WSS к **API Gateway**.
2. Шлюз при необходимости вызывает gRPC микросервиса (например, `ValidateSession`, `ValidateTicket`, `BuildWsConnectUrl` — см. [01 - Ядро валидации](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md)) и привязывает соединение к субъекту / группам рассылки.
3. Доменные изменения (отзыв сессии, обновление контекста, инцидент ИБ и т.д.) выполняются **в микросервисе** через соответствующие RPC; после фиксации состояния сервис публикует событие в real-time контур (в т.ч. **SR-AUTH-WS-01** — WebSocket Backplane между репликами, см. [07 - Платформенные Контракты и Эксплуатация](../../../../01%20-%20Функциональная%20спецификация/Возможности%20сервиса/07%20-%20Платформенные%20Контракты%20и%20Эксплуатация%20-%20Platform%20Contracts%20Operations.md)).
4. API Gateway доставляет сообщение подписанным клиентам.

Подключение без полноценной Phantom Cookie может использовать одноразовый билет (**SR-AUTH-SM-04** / **SR-AUTH-OT-01…03**): `IssueTicket`, `BuildWsConnectUrl`, `ValidateTicket` — см. [01 - Ядро валидации](../gRPC/01%20-%20Ядро%20валидации%20и%20инъекции%20(Validation%20Core).md).
