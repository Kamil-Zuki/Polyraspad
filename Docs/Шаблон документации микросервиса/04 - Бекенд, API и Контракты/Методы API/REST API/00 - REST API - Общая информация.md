# Введение

Настоящий документ задаёт **внешний HTTP-контракт** (пути и семантику методов), через который клиенты работают с возможностями **Authorization Service**. Сама доменная логика авторизации, сессий, квот, PAT и аудита реализуется в микросервисе **Authorization Service** и доступна вызывающим сторонам прежде всего по **gRPC**.

**Размещение REST:** публичные HTTP-маршруты и **контроллеры REST** не обязаны (и по целевой архитектуре **не** должны) жить в процессе микросервиса Authorization Service. Их реализует **API Gateway — агрегатор** (BFF / Edge API): он принимает запросы от SPA, админок и оркестраторов, выполняет маппинг **REST → gRPC** (или внутренний HTTP, где это оговорено) и проксирует вызовы в Authorization Service. Ниже перечисленные пути — это **контракт поверхности API платформы**, а не утверждение, что каждый маршрут реализован как отдельный контроллер внутри процесса Auth.

# 1. Группы методов REST API

Ниже представлена сводная таблица всех логических групп методов REST API в **контракте платформы** (как правило, реализуемых **API Gateway — агрегатором** с проксированием в Authorization Service по gRPC). Каждая группа отвечает за свой набор бизнес-функций в области аутентификации, сессий и безопасности Enterprise-уровня.

| Группа | Описание |
| :--- | :--- |
| **Аутентификация и OIDC (Auth & OIDC)** | Точки входа для начала OIDC Authorization Code Flow, обработки коллбэков, фонового обновления (Silent Refresh) и получения вебхуков глобального логаута от внешнего IdP. |

# 2. Аутентификация и OIDC (Auth & OIDC)

Данная группа обеспечивает сопряжение локального микросервиса авторизации с глобальным провайдером идентичности (внешний IdP) и установку защищенной Phantom Cookie в браузере клиента.

| Код требования | Метод | Эндпоинт                 | Назначение                                                                                              |
| :------------- | :---: | :----------------------- | :------------------------------------------------------------------------------------------------------ |
| SR-AUTH-OI-01  |  GET  | `/auth/oidc/login`       | Инициализация OIDC-протокола (формирование URL и редирект во внешний IdP).                                  |

# 3. Управление сессиями и Доверенными устройствами (Session & Device Management)

Эндпоинты для SPA-клиентов и пользовательского раздела "Безопасность". Позволяют клиенту узнать, "кто он", в каком рабочем пространстве находится, и прервать подозрительные сессии.

| Код требования | Метод | Эндпоинт | Назначение |
| :--- | :---: | :--- | :--- |
| SR-AUTH-SM-06 | GET | `/sessions/me` | Получение полного контекста текущей сессии (`SessionContextDto`), ролей и активного Workspace. |
