# Группа 17: Уроки и прогресс (Lessons)

## Введение

Этот раздел описывает роль **Aggregator Service** как REST-фасада для управления **структурированными уроками** и **учебным прогрессом** пользователя в Polyraspad, а также интеграцию уроков с ИИ-агентом.

Aggregator проксирует запросы от frontend во внутренний микросервис **VocabularyService** (через gRPC `LessonService`). При запуске или перезапуске урока Aggregator оркестрирует создание диалогового треда ИИ-ассистента в **AgentService**, связывая контекст урока с персональным интерактивным чатом.

Контроллер Lessons защищён feature flag **`EnableAdvancedModules`**: при выключенном флаге REST-маршруты уроков недоступны.

**Метафора:**

Представьте **экскурсионный маршрут в музее**. Экскурсовод (ИИ-агент) ведет вас от зала к залу. Вы не можете забежать в зал №5 (сложная грамматика), пока не прошли залы №1–№4. При входе на выставку вы можете сдать тест, чтобы экскурсовод определил ваш уровень и привел в нужный зал. 

Когда вы заходите в зал (запускаете урок), экскурсовод разворачивает перед вами интерактивный стенд (чат-тред ИИ) по конкретной теме. По завершении осмотра стенда (Complete) фиксируются ваши баллы и время, после чего открывается доступ к следующему залу.

REST-контракты: [[04 - Бекенд, API и Контракты/Методы API/REST API/17 - Уроки и прогресс (Lessons)|REST API — Lessons]].

## Возможности данного раздела

Ниже представлен перечень функциональных требований (SR) к модулю уроков и прогресса.

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-LESSON-01** | **Получение списка доступных уроков:** Чтение дерева/списка уроков пользователя с отслеживанием прогресса (ScorePercent, TimeSpent, CompletedAt). |
| **SR-AGG-LESSON-02** | **Получение деталей урока:** Запрос информации о конкретном уроке (SystemPrompt, CefrLevel, OrderIndex, TargetSkills, EstimatedMinutes) и текущем прогрессе. |
| **SR-AGG-LESSON-03** | **Запуск урока:** Инициализация сессии обучения. При отсутствии активного ИИ-треда для урока в AgentService автоматически создается новый тред с системным промптом урока. |
| **SR-AGG-LESSON-04** | **Перезапуск урока:** Принудительное создание нового ИИ-треда для урока для возможности повторного прохождения с чистого листа. |
| **SR-AGG-LESSON-05** | **Завершение урока:** Фиксация результатов прохождения урока (ScorePercent, TimeSpentSeconds) и отметка времени завершения. |

# Детальная спецификация требований

## SR-AGG-LESSON-01: Получение списка уроков {#SR-AGG-LESSON-01}

Пользователь должен видеть всю карту обучения (Learning Map) своего текущего языкового проекта, включая статус прохождения каждого урока, чтобы планировать дальнейшие шаги.

### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| **Авторизованный доступ** | Endpoint закрыт авторизацией (JWT Bearer). |
| **Маппинг данных** | BFF вызывает downstream gRPC `GetLessons` и возвращает массив уроков с их прогрессом. |
| **Связка с проектом** | Запрос привязан к `projectId` в пути запроса. |

### 2. Высокоуровневое описание

Пользователь переходит на страницу `/lessons`. Браузер запрашивает список уроков для текущего проекта. BFF получает этот запрос, извлекает `user_id` из JWT и отправляет gRPC запрос в `VocabularyService` для получения уроков. Downstream возвращает структуру уроков и прогресс (Completed, ScorePercent). BFF формирует плоский или иерархический список для рендеринга интерактивной карты.

### 3. Примеры взаимодействия (логические сценарии)

* **Инициатор:** Frontend (страница Learning Map).
* **Маршрут:** GET `/api/projects/{projectId}/lessons`.
* **Downstream:** gRPC `LessonService.GetLessons`.

#### Сценарий А: Успешный запрос списка (Happy Path)

1. **Запрос:** GET `/api/projects/{projectId}/lessons` с валидным JWT.
2. **BFF:** Извлекает `user_id` из JWT, передает его в параметрах `GetLessonsRequest`.
3. **gRPC:** Downstream `LessonService` возвращает список доступных уроков с прогрессом пользователя.
4. **Ответ:** HTTP **200 OK** с JSON-массивом уроков.

## SR-AGG-LESSON-02: Получение деталей урока {#SR-AGG-LESSON-02}

Пользователь должен иметь возможность прочитать описание урока, его целевые навыки, примерное время и свой текущий прогресс по нему перед запуском.

### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| **Детальное представление** | Возвращает полную информацию об уроке, включая `SystemPrompt` для ИИ-агента и `CefrLevel`. |
| **Проверка доступа** | Проверка прав пользователя на проект/урок на стороне downstream. |

### 2. Высокоуровневое описание

При клике на конкретный урок на карте, пользователю показывается модальное окно или экран старта урока. BFF запрашивает детали у `VocabularyService` по `lessonId`, проверяя контекст пользователя по JWT.

### 3. Примеры взаимодействия (логические сценарии)

* **Инициатор:** Frontend (экран деталей урока).
* **Маршрут:** GET `/api/projects/{projectId}/lessons/{lessonId}`.
* **Downstream:** gRPC `LessonService.GetLesson`.

#### Сценарий А: Успешное чтение деталей (Happy Path)

1. **Запрос:** GET `/api/projects/{projectId}/lessons/{lessonId}`.
2. **gRPC:** BFF вызывает `GetLessonAsync` с передачей `lesson_id` and `user_id`.
3. **Ответ:** HTTP **200 OK** с объектом, содержащим метаданные урока и прогресс.

#### Сценарий Б: Урок не найден (Negative Path)

1. **gRPC:** Возвращает ошибку `NotFound`.
2. **Ответ:** HTTP **404 Not Found**.

## SR-AGG-LESSON-03: Запуск урока {#SR-AGG-LESSON-03}

Запуск урока инициализирует прохождение. Если чат-тред с ИИ-репетитором для этого урока еще не создан, BFF берет на себя создание треда в AgentService и передает его ID в VocabularyService для привязки к прогрессу.

### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| **Оркестрация BFF** | BFF координирует вызовы между `AgentService` (для создания ИИ-треда) и `VocabularyService` (для старта урока). |
| **Использование промпта** | Системный промпт урока передается из Vocabulary в AgentService в качестве `SystemPromptOverride`. |
| **Idempotency** | Если тред уже создан в прогрессе, повторное создание не выполняется, возвращается существующий тред. |

### 2. Высокоуровневое описание

1. **BFF** запрашивает статус урока у VocabularyService.
2. Если в `progress` поле `AgentThreadId` отсутствует или пусто:
   * BFF вызывает gRPC `AgentService.CreateAgentThread`, передавая `projectId` и `SystemPromptOverride` (взятый из `lesson.SystemPrompt`).
   * BFF получает `threadId` нового треда.
3. BFF вызывает gRPC `LessonService.StartLesson`, передавая `lessonId` и полученный/существующий `AgentThreadId`.
4. Результат старта возвращается пользователю (включая ID треда для подключения чата).

### 3. Примеры взаимодействия (логические сценарии)

* **Инициатор:** Frontend (кнопка "Start Lesson").
* **Маршрут:** POST `/api/projects/{projectId}/lessons/{lessonId}/start`.
* **Downstream:** `LessonService.GetLesson`, `AgentServiceClient.CreateAgentThread`, `LessonService.StartLesson`.

#### Сценарий А: Первый запуск (Happy Path)

1. **Запрос:** POST `/api/projects/{projectId}/lessons/{lessonId}/start`.
2. **BFF:** Запрашивает урок, видит, что `AgentThreadId` в прогрессе пуст.
3. **BFF -> AgentService:** Вызывает создание треда с системным промптом урока. Получает `ThreadId` (например, `"thread-123"`).
4. **BFF -> VocabularyService:** Вызывает `StartLesson` с `AgentThreadId = "thread-123"`.
5. **Ответ:** HTTP **200 OK** с результатом старта урока.

#### Сценарий Б: Повторный вход в запущенный урок (Happy Path)

1. **Запрос:** POST `/api/projects/{projectId}/lessons/{lessonId}/start`.
2. **BFF:** Запрашивает урок, видит, что `AgentThreadId = "thread-123"` уже сохранен.
3. **BFF -> VocabularyService:** Вызывает `StartLesson` напрямую с `"thread-123"`.
4. **Ответ:** HTTP **200 OK**.

## SR-AGG-LESSON-04: Перезапуск урока {#SR-AGG-LESSON-04}

Пользователь должен иметь возможность сбросить текущий прогресс беседы с ИИ-агентом и начать урок заново, создав чистый чат-тред.

### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| **Сброс прогресса ИИ** | Обязательное создание нового ИИ-треда в `AgentService` независимо от того, был ли он ранее. |
| **Сохранение привязки** | Перезапись `AgentThreadId` в прогрессе урока в VocabularyService. |

### 2. Высокоуровневое описание

Когда пользователь нажимает «Начать заново», BFF игнорирует старый `AgentThreadId` в прогрессе, создает новый тред в `AgentService` с тем же системным промптом и привязывает его через `StartLesson` в `VocabularyService`.

### 3. Примеры взаимодействия (логические сценарии)

* **Инициатор:** Frontend (кнопка "Restart Lesson" / "Start Over").
* **Маршрут:** POST `/api/projects/{projectId}/lessons/{lessonId}/restart`.

#### Сценарий А: Перезапуск урока (Happy Path)

1. **Запрос:** POST `/api/projects/{projectId}/lessons/{lessonId}/restart`.
2. **BFF:** Получает детали урока, вытаскивает `SystemPrompt`.
3. **BFF -> AgentService:** Создает новый ИИ-тред. Получает новый `ThreadId` (`"thread-456"`).
4. **BFF -> VocabularyService:** Вызывает `StartLesson` с новым `"thread-456"`. Старый тред остается отключенным от прогресса урока.
5. **Ответ:** HTTP **200 OK** с результатом старта.

## SR-AGG-LESSON-05: Завершение урока {#SR-AGG-LESSON-05}

Когда пользователь выполнил все задачи урока, клиент отправляет результаты прохождения (набранный балл в процентах и затраченное время), которые фиксируются в прогрессе.

### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| **Фиксация метрик** | Передача `ScorePercent` (0-100) и `TimeSpentSeconds` в `VocabularyService`. |
| **Завершение сессии** | Downstream помечает урок как пройденный и рассчитывает дату завершения (`CompletedAt`). |

### 2. Высокоуровневое описание

Пользователь завершает практику. Frontend отправляет POST запрос на `/complete`. BFF валидирует тело запроса и вызывает gRPC метод `CompleteLesson` в `VocabularyService`.

### 3. Примеры взаимодействия (логические сценарии)

* **Инициатор:** Frontend (экран завершения урока).
* **Маршрут:** POST `/api/projects/{projectId}/lessons/{lessonId}/complete`.
* **Body:** `CompleteLessonBody` (ScorePercent, TimeSpentSeconds).
* **Downstream:** gRPC `LessonService.CompleteLesson`.

#### Сценарий А: Успешное завершение (Happy Path)

1. **Запрос:** POST с телом `{ "scorePercent": 85, "timeSpentSeconds": 650 }`.
2. **gRPC:** BFF вызывает `CompleteLessonAsync` с передачей переданных метрик и `user_id`.
3. **Ответ:** HTTP **200 OK** (без тела).
