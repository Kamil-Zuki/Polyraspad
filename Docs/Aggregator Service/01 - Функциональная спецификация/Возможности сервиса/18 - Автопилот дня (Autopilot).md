# Группа 18: Автопилот дня (Autopilot)

## Введение

Этот раздел описывает роль **Aggregator Service** как REST-шлюза для получения **ежедневного плана обучения** (Daily Autopilot Plan) в Polyraspad.

Aggregator проксирует запросы от frontend к downstream-сервису **VocabularyService** (через gRPC-клиент `AnalyticsServiceClient`). Шлюз не производит расчеты плана самостоятельно и не сохраняет историю; его задача — JWT-авторизация, извлечение контекста пользователя (`user_id`) и передача запроса в downstream-сервис для вычисления оптимального набора учебных активностей на текущие сутки.

**Метафора:**

Представьте **умного личного тренера**, который каждое утро выдает вам распечатку с планом тренировки на сегодня. Вам не нужно самому думать, какие группы мышц качать, сколько подходов делать или какие упражнения выполнять. 

Вы просто приходите на стойку администрации (Aggregator), показываете абонемент (JWT), и администратор передает вам план от главного тренера (VocabularyService): 5 минут на разминку (повторение карточек по FSRS), 10 минут на бег (новый урок) и 5 минут на растяжку (чтение текста в Reader).

REST-контракты: [[04 - Бекенд, API и Контракты/Методы API/REST API/18 - Автопилот дня (Autopilot)|REST API — Autopilot]].

# Детальная спецификация требований

## SR-AGG-AP-01: Получение плана автопилота {#SR-AGG-AP-01}

Пользователь должен получать готовый, сбалансированный список рекомендуемых учебных шагов на сегодня при входе в языковой проект.

### 1. Цель и ключевые принципы

| Принцип | Описание |
| :--- | :--- |
| **Авторизованный доступ** | Доступ к плану автопилота разрешен только для аутентифицированных пользователей с валидным JWT. |
| **Проксирование** | Запрос преобразуется в вызов gRPC `GetDailyAutopilotPlan`. |
| **Идентификация** | Идентификатор пользователя извлекается из токена и помещается в metadata gRPC запроса (`user_id`). |

### 2. Высокоуровневое описание

При открытии главного экрана проекта (dashboard) frontend запрашивает ежедневный план. BFF принимает GET запрос, проверяет токен, извлекает `user_id` и запрашивает расчет плана у `AnalyticsService` в VocabularyService. План содержит набор рекомендуемых шагов (например, количество карточек к повторению, следующий доступный урок и т.д.).

### 3. Примеры взаимодействия (логические сценарии)

* **Инициатор:** Frontend (главный экран проекта / dashboard).
* **Маршрут:** GET `/api/v1/projects/{projectId}/autopilot/daily-plan`.
* **Downstream:** gRPC `AnalyticsService.GetDailyAutopilotPlan`.

#### Сценарий А: Получение плана автопилота (Happy Path)

1. **Запрос:** GET `/api/v1/projects/{projectId}/autopilot/daily-plan` с JWT Bearer.
2. **BFF:** Проверяет права, извлекает `user_id`, вызывает `GetDailyAutopilotPlanAsync`.
3. **gRPC:** Downstream возвращает объект `GetDailyAutopilotPlanResponse` с массивом шагов обучения.
4. **Ответ:** HTTP **200 OK** с планом автопилота в формате JSON.

#### Сценарий Б: Ошибка при обработке на стороне downstream (Negative Path)

1. **gRPC:** Downstream выдает ошибку (например, `Internal` или недоступность сервиса).
2. **BFF:** Логирует ошибку, возвращает HTTP **500 Internal Server Error**.
