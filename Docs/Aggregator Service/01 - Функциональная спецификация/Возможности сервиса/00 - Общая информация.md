## Введение

Настоящий документ определяет функциональные возможности (сервисные требования) микросервиса **«Aggregator Service»** — публичного API Gateway (BFF) платформы Polyraspad.

**Aggregator Service** — тонкий шлюз между клиентом (браузер, Next.js) и внутренними микросервисами. Он не владеет доменными данными: принимает HTTP-запросы, валидирует JWT, извлекает контекст пользователя (`user_id`, роли), вызывает downstream-сервисы по gRPC и возвращает JSON DTO.

Документ предназначен для разработчиков, QA, системных аналитиков и архитекторов.

# Группы возможностей

Ниже представлен перечень из **18** групп функциональных возможностей (сервисных требований) для микросервиса Aggregator Service. Требования сгруппированы по логическим блокам для удобства навигации.

| Группа | Название и Описание |
| :----- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Аутентификация и профиль (Auth Proxy)** | **Прокси аутентификации и профиля:** REST-фасад register, login, refresh, profile и rate limit; credentials не хранятся на BFF. |
| **Контент: проекты и колоды (Content)** | **Projects и колоды:** Create/Read/Update project (без Delete), CRUD deck, дерево библиотеки, identity metadata. |
| **Карточки и редактор (Cards)** | **Карточки и Card Editor:** CRUD + delete/bulk/move/leeches/missing-media; поиск и import; note type для редактора. |
| **Сессии обучения (Study)** | **FSRS-сессии обучения:** Запуск session и интерактивный цикл next/review/undo через StudyService. |
| **Аналитика (Analytics)** | **Dashboard-аналитика:** Vocabulary stats, heatmap, daily summary, skill balance. |
| **Reader и термины (Reader)** | **LingQ-style Reader:** Term-first операции со словами и фразами; анализ текста для подсветки страницы. |
| **Подписки на колоды (Deck Subscriptions)** | **Подписки на колоды:** Список, оформление и отмена follow на published/shared decks. |
| **Сообщество и маркетплейс (Community)** | **Community и marketplace:** Contributions, publish/fork, products и проверка deck entitlement. |
| **Медиа и Reader Library (Media)** | **Медиа и библиотека чтения:** Upload, TTS, извлечение текста, CORS-proxy и Reader library. |
| **SaaS-биллинг (Billing)** | **SaaS-биллинг:** Self-service billing для пользователя и приём payment webhooks от provider. |
| **AI-агент (Agent)** | **AI-ассистент в project:** Threads, messages, run, persist run, archive. |
| **AI-прокси (AI Proxy)** | **LLM-прокси для Next.js BFF:** Models, generate и mining-draft по shared secret, не по JWT. |
| **Автоматизация (Automation)** | **Automation:** Copilot/experiments stubs + in-memory jobs API. |
| **Внешние интеграции (Integrations)** | **Внешние HTTP API:** Перевод и словарный lookup по exact word form. |
| **Настройки пользователя (Settings)** | **Глобальные настройки пользователя:** goals, rollover, language, streaks (без server-side page-turn flag). |
| **Платформенные контракты (Operations)** | **Платформенные контракты:** Health, CORS, fail-fast Production config и Swagger (dev). |
| **Уроки и прогресс (Lessons)** | **Уроки и прогресс:** Просмотр списка и деталей уроков, запуск сессий с ИИ-агентом, сохранение прогресса. |
| **Автопилот дня (Autopilot)** | **Автопилот дня:** Daily plan + track-skill (feature flag `EnableAIAgents`). |

## Описание возможностей

Ниже представлен детальный перечень сервисных требований (SR) для каждой группы. Подробное описание каждого требования находится в соответствующих вложенных документах.

### 1. Аутентификация и профиль (Auth Proxy)

*REST-фасад между frontend и authorization-module: публичная auth под rate limit, защищённые маршруты — по локально валидируемому JWT.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-AUTH-01** | **Регистрация нового пользователя:** Публичный REST-фасад создания учётной записи; credentials передаются в authorization-module и не сохраняются на шлюзе. |
| **SR-AGG-AUTH-02** | **Аутентификация и выдача JWT:** Единая точка входа — после проверки пароля клиент получает пару access и refresh token. |
| **SR-AGG-AUTH-03** | **Обновление access token:** Продление сессии по refresh token без повторного ввода пароля; endpoint публичный и защищён rate limit. |
| **SR-AGG-AUTH-04** | **Подтверждение адреса email:** Обработка ссылки из письма — передача одноразового token в auth-сервис для верификации. |
| **SR-AGG-AUTH-05** | **Профиль авторизованного пользователя:** Чтение актуальных атрибутов профиля; identity из JWT, данные запрашиваются у authorization-module. |
| **SR-AGG-AUTH-06** | **Выход из системы:** Завершение сессии и отзыв refresh token в auth-сервисе при наличии Bearer access. |
| **SR-AGG-AUTH-07** | **Изменение данных профиля:** Обновление username, password и avatar URL; идентификатор пользователя только из JWT, не из тела запроса. |
| **SR-AGG-AUTH-08** | **Ограничение частоты публичной auth:** Защита register, login, refresh и confirm-email — не более 10 запросов в минуту с одного IP до вызова downstream. |

### 2. Контент: проекты и колоды (Content)

*REST-фасад к VocabularyService ContentService: projects, decks и дерево библиотеки; на каждый gRPC-вызов прокидывается identity из JWT.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-CONTENT-01** | **Управление языковыми проектами:** Create/Read/Update проектов (Delete project в REST отсутствует); шлюз не хранит project локально. |
| **SR-AGG-CONTENT-02** | **Управление колодами и деревом библиотеки:** Иерархия колод, статистика и фильтры каталога; единый REST-фасад к Deck/Tree API. |
| **SR-AGG-CONTENT-03** | **Инъекция identity в downstream-вызовы:** Передача user_id и roles из JWT в gRPC metadata; авторизация и ACL — в VocabularyService. |

### 3. Карточки и редактор (Cards)

*REST-фасад к CardService: CRUD карточек, поиск и import; схема note type для динамического Card Editor.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-CARD-01** | **CRUD учебной карточки:** Создание, чтение, обновление и **удаление** note/card через CardService. |
| **SR-AGG-CARD-02** | **Поиск, захват и импорт карточек:** Full-text search, проверка exact-дубликатов, capture из extension и пакетный import в колоду. |
| **SR-AGG-CARD-03** | **Схема note type для редактора:** Динамические поля и Anki-like templates для Card Editor без hardcoded schema во frontend. |
| **SR-AGG-CARD-04** | **Обслуживание карточек:** bulk-delete, move, bulk-reset-progress, leeches, missing-media. |

### 4. Сессии обучения (Study)

*REST-фасад к StudyService: запуск FSRS-сессии и интерактивный цикл review в контексте project/deck filters.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-STUDY-01** | **Запуск сессии обучения:** Создание активной FSRS-сессии с фильтрами project/deck; очередь карточек формирует StudyService. |
| **SR-AGG-STUDY-02** | **Интерактивный цикл review:** Выдача следующей карточки, приём FSRS-оценки и отмена последнего review в рамках session. |

### 5. Аналитика (Analytics)

*Read-only dashboard metrics через AnalyticsService; при недоступности downstream daily summary не ломает UI.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-ANALYTICS-01** | **Аналитика словаря для dashboard:** Статистика vocabulary, heatmap активности и daily summary; при сбое Vocabulary daily возвращает безопасный default с нулями. |
| **SR-AGG-ANALYTICS-02** | **Баланс навыков:** `GET /api/analytics/skills` → SkillBalance. |

### 6. Reader и термины (Reader)

*LingQ-style term-first модель: exact form, без лемматизации на BFF; analyze text для подсветки страницы Reader.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-READER-01** | **Управление терминами Reader (term-first):** Сохранение, mark-known, ignore и bulk-known — статусы по exact form через TermService. |
| **SR-AGG-READER-02** | **Подсветка текста в Reader:** Токенизация и статусы для страницы; фраза имеет приоритет над отдельными словами; лимит 100 000 символов. |
| **SR-AGG-READER-03** | **Инспектор термина и служебные операции:** Детали термина, поиск exact-дубликатов и очистка demo-import в project. |

### 7. Подписки на колоды (Deck Subscriptions)

*Подписки пользователя на published/shared decks; identity только из JWT, без target userId в body.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-SUB-01** | **Подписка на опубликованные колоды:** Список, оформление и отмена подписок текущего пользователя на shared/published decks. |

### 8. Сообщество и маркетплейс (Community)

*Community catalog, collaborative editing и marketplace premium content через CommunityService.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-COMM-01** | **Коллаборативные правки (contributions):** Создание, просмотр и разбор предложений изменений deck и настройка contribution policy. |
| **SR-AGG-COMM-02** | **Публикация и fork колод:** Публикация deck в community catalog, fork в project пользователя, browse и author profile. |
| **SR-AGG-COMM-03** | **Маркетплейс учебного контента:** Products, отзывы, статистика продавца и проверка deck entitlement перед premium access. |

### 9. Медиа и Reader Library (Media)

*Upload и TTS через MediaService; локальный parse документов на BFF; CORS-proxy и Reader library.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-MEDIA-01** | **Загрузка медиа и синтез речи:** Upload image/document в MinIO через MediaService и generate-audio (TTS); лимиты 5 MB / 50 MB. |
| **SR-AGG-MEDIA-02** | **Извлечение текста из документа:** Локальный parse PDF/EPUB/TXT на BFF для import в Reader library. |
| **SR-AGG-MEDIA-03** | **Same-origin прокси медиа:** Credentialed serve-image/serve-document — preview без CORS-блокировки для authenticated users. |
| **SR-AGG-MEDIA-04** | **Библиотека чтения (Reader library):** Книги, коллекции, share/unshare collaborators и список shared collections. |

### 10. SaaS-биллинг (Billing)

*Self-service billing для JWT-пользователя и отдельный trust boundary для payment webhooks.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-BILL-01** | **Self-service SaaS-биллинг:** Access, entitlements, subscription, checkout, cancel и invoices для JWT-пользователя через BillingService. |
| **SR-AGG-BILL-02** | **Приём payment webhooks:** Inbound события от payment provider с optional shared key; пользовательский JWT не участвует. |

### 11. AI-агент (Agent)

*AI assistant threads в контексте project через AgentService.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-AGENT-01** | **Жизненный цикл AI-тредов:** Список, создание, сообщения, run и archive assistant threads в контексте project через AgentService. |
| **SR-AGG-AGENT-02** | **Persist run:** `POST /api/agent/threads/{id}/runs/persist` — сохранение результата run без полного Execute. |

### 12. AI-прокси (AI Proxy)

*LLM completion для Next.js BFF по shared secret — отдельная модель доверия от JWT.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-AI-01** | **LLM-прокси для Next.js BFF:** Models, generate и mining-draft по shared secret X-Ai-Proxy-Key; JWT не используется. |

### 13. Автоматизация (Automation)

*Контрактные stub-endpoints для стабильности frontend до полной реализации LLM и experiments.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-AUTO-01** | **Copilot feedback после review (stub):** Контрактный placeholder после FSRS review — neutral empty response без вызова LLM. |
| **SR-AGG-AUTO-02** | **A/B experiments (stub):** Стабильный control variant и no-op event tracking — frontend не блокируется при включённых flags. |
| **SR-AGG-AUTO-03** | **Automation jobs:** POST/GET `/api/automation/jobs` через in-memory orchestrator. |

### 14. Внешние интеграции (Integrations)

*Outbound HTTP к публичным API перевода и словаря; lookup по exact word form (term-first).*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-INT-01** | **Перевод и словарный lookup:** Outbound HTTP к MyMemory и Free Dictionary; lookup по exact word form без лемматизации на BFF. |

### 15. Настройки пользователя (Settings)

*Глобальные preferences пользователя через VocabularyService; scope per user, не per project.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-SETTINGS-01** | **Глобальные настройки пользователя:** RolloverHour, DailyGoalNew/Review, InterfaceLanguage, streaks; **нет** поля AutoMarkAsKnownOnPageTurn — page-turn делает клиент через BulkMarkKnown. |

### 16. Платформенные контракты (Operations)

*Эксплуатационные контракты шлюза: liveness, CORS, fail-fast config и dev-only Swagger.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-OPS-01** | **Проверка liveness процесса:** Anonymous GET `/healthz` — process up без deep downstream checks. |
| **SR-AGG-OPS-02** | **Политика CORS для браузера:** Явный список origins и AllowCredentials; wildcard запрещён в Production. |
| **SR-AGG-OPS-03** | **Fail-fast валидация Production-конфига:** Некорректные JWT, CORS, service URLs или dev AI key — старт приложения невозможен. |
| **SR-AGG-OPS-04** | **Swagger UI в Development:** Interactive OpenAPI и JWT Bearer authorize только в dev environment. |

### 17. Уроки и прогресс (Lessons)

*REST-фасад к LessonService: просмотр структуры уроков и прогресса, запуск с интеграцией чат-треда в AgentService, фиксация результатов.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-LESSON-01** | **Получение списка доступных уроков:** Чтение дерева/списка уроков пользователя с отслеживанием прогресса (ScorePercent, TimeSpent, CompletedAt). |
| **SR-AGG-LESSON-02** | **Получение деталей урока:** Запрос информации о конкретном уроке (SystemPrompt, CefrLevel, OrderIndex, TargetSkills, EstimatedMinutes) и текущем прогрессе. |
| **SR-AGG-LESSON-03** | **Запуск урока:** Инициализация сессии обучения. При отсутствии активного ИИ-треда для урока в AgentService автоматически создается новый тред с системным промптом урока. |
| **SR-AGG-LESSON-04** | **Перезапуск урока:** Принудительное создание нового ИИ-треда для урока для возможности повторного прохождения с чистого листа. |
| **SR-AGG-LESSON-05** | **Завершение урока:** Фиксация результатов прохождения урока (ScorePercent, TimeSpentSeconds) и отметка времени завершения. |

### 18. Автопилот дня (Autopilot)

*Получение ежедневного плана обучения для выбранного проекта на основе алгоритмов VocabularyService.*

| Код | Название и Описание |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SR-AGG-AP-01** | **Получение плана автопилота:** Daily plan для projectId (feature flag `EnableAIAgents`). |
| **SR-AGG-AP-02** | **Track skill activity:** `POST …/autopilot/track-skill` — инкремент навыка через Vocabulary. |

Подробные SR-блоки — во вложенных файлах групп. REST-контракты — в `04 - Бекенд, API и Контракты/`.
