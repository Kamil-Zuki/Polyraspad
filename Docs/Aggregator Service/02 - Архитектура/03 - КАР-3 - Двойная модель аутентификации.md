# Введение

На шлюзе coexisting три модели доверия: **JWT Bearer** (пользователь), **X-Ai-Proxy-Key** (Next.js BFF → Aggregator AI routes), **X-Billing-Webhook-Key** (payment provider webhooks).

## Контекст и проблема

AI routes не должны принимать user JWT из браузера напрямую с provider API key; webhooks — без user session.

## Принятое решение

| Маршрут | Auth |
| :--- | :--- |
| Большинство `/api/*` | JWT `[Authorize]` |
| `/api/ai/*` | `[AllowAnonymous]` + `AiProxyApiKeyFilter` |
| `POST /api/Billing/webhooks/{provider}` | `[AllowAnonymous]` + optional webhook key header |
| `/api/Auth/register`, `login`, … | Public + rate limit |

## Обоснование и последствия

### Плюсы

* Provider API keys не покидают backend perimeter
* Next.js BFF остаётся единственным клиентом AI proxy

### Последствия

* Компрометация `Ai:ProxyApiKey` = доступ к LLM quota
* *Решение:* production guard запрещает dev default key
