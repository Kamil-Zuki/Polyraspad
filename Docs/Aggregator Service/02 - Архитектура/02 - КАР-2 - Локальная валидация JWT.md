# Введение

JWT access tokens выдаёт **authorization-module**. Aggregator проверяет подпись локально с тем же `Jwt:Secret`, `Issuer`, `Audience` — без gRPC-вызова на каждый authenticated request.

## Контекст и проблема

Вызов auth-сервиса на каждый REST-запрос создаёт лишнюю latency и coupling.

## Принятое решение

1. `AddAuthentication(JwtBearer)` с `TokenValidationParameters` (issuer, audience, signing key).
2. `[Authorize]` на защищённых controllers.
3. `MappingHelper.GetUserId` / `GetRoles` из claims (`sub`, `NameIdentifier`, `role`).
4. В тестах — fallback headers `X-User-Id`, `X-User-Roles`.

## Обоснование и последствия

### Плюсы

* Низкая latency на hot path
* Стандартный ASP.NET Core middleware

### Последствия

* Revocation токена до expiry не видна BFF без blacklist или короткого TTL
* *Решение:* короткий access token + refresh через Auth proxy
